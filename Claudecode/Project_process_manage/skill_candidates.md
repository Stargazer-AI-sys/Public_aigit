## 1. 컨텍스트 부하 추정 — 절차 메모
1. 문서 글자 수를 센다(`wc -m`). 토큰은 글자 수 × 0.88로 잡는다. 이 비율은 Claude Read 도구의 실측(49,959자 → 44,021토큰)에서 나왔고, GPT는 오차가 있다.
2. 세션 기록에서 숫자만 뽑는다.
   - Codex: `~/.codex/sessions/**.jsonl`의 `token_count.info.last_token_usage.input_tokens`, `model_context_window`, `compacted` 이벤트
   - Claude: `~/.claude/projects/<폴더>/*.jsonl`의 `usage`(input + cache_read + cache_creation)
   - 대상 폴더 경로가 들어 있는 세션만 고른다.
3. 창 대비 비율로 등급을 매긴다: 10% 미만 가벼움, 10~30% 주의, 30% 초과 방해. 압축이 일어났으면 방해로 본다.
4. 본문은 출력하지 않는다. 비밀값이 섞일 수 있기 때문이다.
- 이번 점검에 쓴 스크립트는 임시 폴더에 있다. 스킬로 만들 때 옮겨서 정리한다.

## 2. 재지시 분류 — 절차 메모
- 자동 주입 메시지(`<`로 시작하는 것, `# AGENTS`)와 자동 승인 검토 세션(`codex-auto-review`)은 뺀다.
- 80자 이하 지시를 모아 유형을 나눈다: 기록 저장 / 진행 / 번호 선택 / 전달 요약 / 실행 보고 / 의미 질문 / 상태 문의.
- 자동 승인 검토는 따로 센다(보안이라 판정에서 빼지만 비용에는 넣는다).

## 3. 지침 비교 — 확인 포인트
- 시작 방식마다 실제로 로딩된 지침을 세션 기록에서 확인한다. 각 지침의 고유 문구가 몇 번 나오는지 `grep -c`로 세면 된다.
- `permissionMode`, 훅 설정, Read 거부 목록이 시작 방식마다 같은지 본다.
