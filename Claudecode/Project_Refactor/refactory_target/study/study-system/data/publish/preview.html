라우팅과 라우터의 기능

라우팅과 스위칭

라우팅은 서로 다른 네트워크 사이에서 패킷을 처리하고 연결하는 것이며, 스위칭은 같은 네트워크에서 데이터를 처리하는 것으로 정리되어 있다. 라우터의 핵심 기능으로 패킷 스위칭과 경로 선택이 제시되어 있다.

원문 근거 
라우터 핵심기능
- packet switching : 패킷을 보낼지 말지 결정
- path selection : 경로 선택
switching : 같은 네트워크에서 데이터를 처리, 보낼 지 말지를 결정
routing : 서로 다른 네트워크 사이에서 처리(연결)

경로 선택 기준

먼저 가장 긴 프리픽스 길이를 우선하고, 이어 AD가 낮은 경로를 우선하며, 비용이 낮은 경로를 우선한다고 정리되어 있다. 동일 목적지로 가는 경로가 둘 다 라우팅 테이블에 올라오면 양쪽으로 트래픽이 분산될 수 있다고 설명한다.

원문 근거 
1. 테이블 룩업(다른 서브넷 회선이 2개 이상 적용되는 IP가 둘다 통과 가능한 아이피 대역인경우 프리픽스 길이가 긴쪽을 우선함) _longest prefix
2. AD값이 적은게 우선시함  192.168.4.0[(1)/0] via ....
3. cost 낮은 비용을 우선시함 192.168.4.0[1/(0)] via ....
2개 채널 구성했을때 인터페이스의 ip가 둘다 라우팅테이블에 올라가면 50% 비율로 양쪽으로 타지만 만약 한개를 백업 루트로 두고 싶다면 AD 값을 부여해서 우선순위를 정해서 백업인터페이스로 설정가능하다.
AI 검토 의견 · 정정

AD는 서로 다른 라우팅 정보 출처의 경로를 비교할 때 사용하고, 메트릭은 일반적으로 같은 라우팅 프로토콜이 학습한 경로를 비교할 때 사용합니다. 따라서 AD와 메트릭을 모든 경로에 연속 적용하는 단일 순서처럼 표현하면 부정확합니다.

IGP와 라우팅 방식

IGP를 내부 게이트웨이 프로토콜로 설명하고, Distance vector의 예로 RIP와 IGRP, Link state의 예로 OSPF와 IS-IS를 기록했다. RIP의 메트릭은 홉 수 기준이며 최대 15라고 적었다.

라우팅 정보 교환과 모니터링

Distance vector는 라우팅 테이블 정보를 주기적으로 교환하는 레거시 기술로, Link state는 상태 변화 시 정보를 교환하고 평상시 Hello packet으로 이웃 라우터를 모니터링한다고 기록했다. 40초 동안 응답이 없으면 테이블에서 삭제한다고 적었다.

원문 근거 
	=> 주기적 정보(라우팅테이블) 교환 레거시 기술
	link state OSPF[대역폭], IS-IS Metric 구성요소는 무엇인가?
	=> 상태 변화시 정보 교환, 평상시 주기적으로 이웃 라우터를 모니터링(Hello packet을 이용 40초동안 응답이 없으면 테이블 삭제)

EIGRP와 EGP

EIGRP를 hybrid로 분류하고, 비용 계산은 IGRP를 기반으로 하며 상태 모니터링과 네트워크 변화 시 업데이트는 Link state 방식을 사용한다고 기록했다. EGP는 외부 게이트웨이 프로토콜로 적었다.

원문 근거 
	hybrid: EIGRP 
	=> 비용계산은 IGRP를 기반으로하고 상태 모니터링 및 네트워크 변화시 업데이트는 link state 방식을 사용




EGP 외부 게이트웨이 프로토콜
AI 검토 의견 · 정정

EIGRP는 IGRP에서 발전한 고급 거리 벡터(advanced distance vector) 프로토콜이며, Link state 방식으로 분류하지 않습니다. Hello 패킷 응답이 없어 경로를 무효화하는 시간은 OSPF에서 네트워크 유형 등에 따라 달라지므로, 40초를 모든 경우에 적용되는 값으로 일반화하면 안 됩니다.

RIPv1

RIPv1은 classful 방식으로 서브넷 범위를 보지 않으며 VLSM을 지원하지 않는다고 기록했다. 예시로 172.16.1.0/24가 172.16.0.0/16 형태로 전달될 수 있고, 브로드캐스트 주소 255.255.255.255를 목적지로 하는 UDP 520 패킷을 주기적으로 보낸다고 적었다.

LAN 통신 원리와 테이블

테이블의 역할

ARP Table은 IP 주소와 MAC 주소의 변환 및 목적지 IP에 대응하는 MAC 주소 확인에 사용된다. MAC Table은 MAC 주소와 포트를 확인하며, Routing Table은 IP 주소와 포트를 확인하는 용도로 설명되어 있다.

원문 근거 
PC, 서버, 스위치, 라우터의 통신 원리에서 가장 많이 사용된느 기능은 Table이다.
1. ARP Table : IP<=>MAC주소 변환용 테이블
 =>PC, Router등에서 사용
 =>목적지 IP에 상응하는 MAC주소 확인용
 =>arp 또는 show arp명려으로 확인 가능
2. MAC Table : MAC<=>Port 확인용 테이블
3. Routing Table : IP<=>Port 확인용 테이블

LAN 통신 순서

송신 시스템은 ARP Table에서 목적지 IP에 대응하는 MAC 주소를 확인하고, 없으면 브로드캐스트 MAC 주소를 목적지로 사용한다. 스위치는 MAC Table에 목적지 MAC 주소가 없으면 모든 포트로 프레임을 전송한다. 수신 시스템은 자신의 IP와 목적지 IP를 비교하며, 응답 과정에서 스위치는 출발지 MAC 주소를 학습하고 송신 시스템은 목적지 MAC 주소를 ARP Table에 저장한다.

원문 근거 
LAN통신 순서
1. 송신 시스템은 ARP Table에서 목적지 IP에 상응하는 MAC주소 확인. 없으면 브로드 캐스트(FFFFFFFFFFFF)주소를 목적지 MAC주소로 입력. 있으면 해당 MAC주소를 목적지 주소로 선택
2. 스위치는 자신의 MAC Table에서 목적지 MAC주소에 상응하는 포트 확인. 없으면 모든 포트에 프레임 전송(브로드 캐스팅)
3. 수신 시스템은 자신의 IP와 목적지 IP를 비교. 맞으면 응답. 틀리면 무시
4. 반송신호를 받은 스위치는 출발지 MAC주소를 MAC Table에 기록 후 유니 캐스팅
5. 송신 시스템은 회신 프레임을 기준으로 자신의 ARP Table에 목적지 MAC주소를 저장. 이후 동일한 목적지로 프레임 전송 시 유니 캐스팅.
AI 검토 의견 · 정정

라우팅 테이블은 일반적으로 목적지 네트워크와 다음 홉 또는 출구 인터페이스를 기준으로 경로를 선택합니다. IP와 포트를 직접 대응시키는 테이블이라는 표현은 부정확합니다.

확장 ACL 접근 제어

ACL 개요와 조건

ACL은 일반적으로 L3 장비 또는 라우터에 구현되며 표준과 확장 유형으로 분류된다. 자료에서는 확장 ACL이 특정 프로토콜을 제어할 수 있다고 설명하고, VLAN 10의 웹 접근, VLAN 30의 FTP 접근, 전체의 메일 서비스 접근을 조건으로 제시한다.

원문 근거 
ACL(Access Control List)-접근통제목록
=>일반적으로  L3또는 라우터에 구현
=>표준, 확장의 2가지 유형으로 분류
=>확장은 특정 프로토콜에 대한 제어 가능

ACL조건
- Vlan 10은 Web접근 가능
- Vlan 30은 FTP접근 가능
- Mail서비스는 모두 가능

ACL 설정과 적용

확장 ACL 100에 TCP/80, UDP/53, TCP/21 및 IP 허용·차단 규칙을 추가하고, R1의 G0/0.20 서브인터페이스에 outbound 방향으로 적용한다.

원문 근거 
R1
conf t
acc 100 permit tcp 192.168.10.0 0.0.0.255 any eq 80
acc 100 permit udp 192.168.10.0 0.0.0.255 any eq 53
acc 100 deny tcp any any eq 80
acc 100 permit tcp 192.168.30.0 0.0.0.255 any eq 21
acc 100 deny tcp any any eq 21
acc 100 permit ip any any
int g0/0.20
ip access-group 100 out

AI 검토 의견 · 정정

제시된 ACL은 VLAN 10의 DNS 허용만 UDP/53으로 처리하고 TCP/53은 허용하지 않습니다. 또한 ACL은 위에서부터 순서대로 평가되므로, VLAN 30의 FTP 허용 규칙은 앞선 `deny tcp any any eq 21`에 의해 차단됩니다.
