# Project_Refactor 지침

상위 `Claudecode/CLAUDE.md`의 공통 규칙에 더해 이 프로젝트에만 적용한다.

## 시작할 때
- 작업 전에 `WORK_LOG.md`를 먼저 읽고 "현재 상태"와 "다음 단계"부터 이어간다.
- 사용자가 "작업기록"이라고 하면 `Project_Refactor/WORK_LOG.md`를 뜻한다. Notion이나 다른 폴더를 검색하지 않고 이 파일을 바로 읽는다. 다른 프로젝트의 같은 이름 문서(예: `gptgit/Project-NetworkEngineer/docs/04_records/작업 기록.md`)와 헷갈리지 않기 위해서다.
- `WORK_LOG.md`는 작업 중 수시로 갱신하지 않는다. 사용자가 작업을 마칠 때 요청하면 한 번에 정리한다(결정, 확인한 사실, 미확인 항목 구분).

## 목표 (2026-10-28 변경: 간소화 재설계)
- 사용자에게 필요한 흐름은 다음이 전부다: 파일 하나 분석 → CCNA 학습 분류에 따라 분류 → 게시할 내용 정리 → Notion에 반영 → CCNA 기준으로 부실하면 코멘트 추가.
- 이 흐름에 필요 없는 보장 장치(다중 지문, 감사 기록, 단계별 가드 등)와 스키마 항목은 줄이는 방향으로 판단한다.
- 자료 구분은 "파일명 + 파일 내용 해시 1개"로 한다. 해시는 내용 변경 감지에만 쓴다.
- 이미 게시된 Notion 페이지는 새로 만들지 않고 파일명 기준으로 같은 페이지를 갱신한다.

## 수정 범위
- 수정은 `refactory_target/`(사본)에서만 한다. 원본 `gptgit/Project-StudyAutomanage/`(`user_app` 포함)은 읽기만 한다.
- 분석 대상에서 `vendor/`는 제외한다.
- 저장된 분석 결과는 다시 분석해도 된다(사용자 결정). 그래서 캐시 지문·스키마 값이 바뀌는 변경도 할 수 있다. 다만 새 분석과 게시는 유료 API와 외부 전송이 따르므로, 실행 전에 사용자에게 알린다.

## 결과물
- 리팩터링 결과는 원본에 반영하지 않는다.
- 최종 결과 소스는 `Project_Refactor/refactory_result/`에 새로 만든다. 모든 작업이 끝나고 사용자가 요청한 뒤에만 만든다. 그 전까지 작업은 `refactory_target/`에서 한다.

## 실행과 검증
- `start.py` 실행은 `study/study-system/data/`를 바꾸고, 분석 버튼은 유료 OpenAI API를 호출한다. 실행 전에 사용자에게 알린다. Notion 게시는 채팅 AI가 게시 패키지(`data/publish/`)를 읽어 수행하므로 게시 전에도 사용자 확인을 받는다.
- 새 흐름 테스트는 `study/study-system/tests/test_flow.py`다(유료 API·Notion 호출 없음). 코드를 바꾸면 이 테스트를 실행한다. 예전 기준선 샌드박스(`%TEMP%\refactor_baseline`)는 삭제된 구조를 검사하므로 더 이상 쓰지 않는다. 실행하지 않은 검증을 성공했다고 보고하지 않는다.
- 미사용 후보는 "확실 / 가능성 높음 / 확인 필요"로 분류한다. 정적 분석 결과만으로 삭제하지 않는다.

## 설명 방식
- 사용자는 코딩 지식이 낮다. 구조와 위험은 쉬운 말로 설명하고 전문 용어에는 짧은 풀이를 붙인다.

## Git
- commit과 push는 사용자가 요청하면 Claude가 한다. 요청 없이 실행하지 않는다.
