# 작업기록

"작업기록"은 지금 작업 중인 프로젝트 폴더의 `WORK_LOG.md`를 뜻한다. 저장소에 같은 이름의 문서가 여러 개 있어(예: `gptgit/Project-NetworkEngineer/docs/04_records/작업 기록.md`) 다른 곳에서 찾으면 엉뚱한 기록을 고치게 된다.

## 대상 찾기
1. 현재 작업 폴더 또는 이번 대화에서 다루는 `Project_*` 폴더의 `WORK_LOG.md`를 바로 연다. Notion이나 다른 폴더는 검색하지 않는다.
2. 어느 프로젝트인지 판단할 수 없을 때만 사용자에게 묻는다.

## 읽고 이어가기
- `## 0. 인계 요약`의 "현재 상태"와 "다음 단계"부터 읽는다. 나머지 절은 이번 작업에 필요한 부분만 읽어 토큰을 아낀다.
- 기록은 당시 시점의 내용이다. 다른 PC의 설치·검증 결과를 현재 PC의 사실로 말하지 않는다.
- 다음 단계에 적힌 일을 실행 허가로 받아들이지 않는다. 유료 API, 외부 게시, commit·push는 프로젝트 지침과 사용자 요청을 따른다.

## 갱신 시점
작업 중에는 갱신하지 않는다. 사용자가 작업을 마치며 요청할 때 한 번에 정리한다. 수시로 고치면 비용만 들고 중간 상태가 기록에 남기 때문이다.

## 정리 방법
기존 파일의 절 구성과 문체를 유지하고 이번 작업에서 바뀐 내용만 반영한다.

1. 맨 위 줄의 최종 갱신 날짜와 PC를 고친다.
   `> 최종 갱신 YYYY-MM-DD (ICT PC 세션) | 새 세션은 §0부터 읽는다. 경로는 저장소 루트(aigit) 기준 상대 경로다.`
2. "현재 상태"를 지금 기준으로 다시 쓴다. 끝난 일은 "다음 단계"에서 빼고 진행 내용이나 이력 절로 옮긴다.
3. "다음 단계"는 새 세션이 바로 시작할 수 있게 우선순위 순서로 적는다. 사용자 결정이 필요한 일, 보류한 일의 재개 조건도 함께 적는다.
4. 다음을 섞지 않고 구분한다.
   - **결정:** 사용자가 정한 것. 날짜와 이유를 함께 적는다.
   - **확인한 사실:** 직접 실행하거나 읽어서 확인한 것. 실행한 검증과 결과를 적는다.
   - **미확인:** 추정이거나 아직 확인하지 못한 것.
5. 날짜는 "오늘", "어제"가 아니라 절대 날짜로 적는다. 경로는 저장소 루트 기준 상대 경로로 적는다.
6. 비밀값과 개인정보는 옮겨 적지 않는다. 필요하면 위치만 적는다.

`WORK_LOG.md`가 없는 프로젝트라면 위 형식으로 새로 만들고 새로 만들었다고 알린다. 기본 구성은 `# <프로젝트> 작업 기록`, `## 0. 인계 요약`(`### 현재 상태`, `### 다음 단계`), `## 1. 사용자 결정`, `## 2. 확인한 사실`, `## 3. 미확인 항목`이다.

정리 후에는 바뀐 절만 짧게 알린다. 기록 정리 요청에는 commit이 포함되지 않는다.
