# 과거 자동화 운영 조건과 판정

이 문서는 당시 설계와 기록을 이해하기 위한 설명이다. 자동화 재개 지시가 아니며 현행 관리 프로젝트의 자동화 운영 기능을 의미하지 않는다. 이번 위키 담당자의 herdr 수동 위임과 과거 자동 전달·회수는 별개다. 기존 가이드 제작과 자료 전송 보류, 추가 비용 및 Git의 별도 승인 조건은 [최신 인계](../../docs/04_records/management_log.md#유지할-제한과-과거-근거)를 따른다.

## 담당·인계와 재개

당시 마스터는 승인 명세와 고정 산출물에 따라 기획·제작·검토·QA를 분담하고, 작업 ID·명세 버전·담당 세션·입출력·완료 조건·시험 결과·증거·미해결 사항을 인계했다. 제작자의 자체 시험과 작성자와 분리된 독립 QA, 서로 다른 제공자의 교차 검증을 각각 기록한다. 실제 연결되지 않은 역할을 실행한 것으로 쓰지 않는다. 범위·비용·공개 등 중요한 변경은 사용자 결정이 필요하다. [근거: 역할 기준](../../raw/docs/00_rules/roles.md#인계와-충돌-해결)

당시 중단 후에는 최신 기록뿐 아니라 관련 결정·설계와 현재 대화의 미저장 결정을 대조하고, 완료·미구현·미검증·보류를 구별하도록 했다. 같은 Task의 수정은 세션 재사용이 가능했지만 독립 검토와 제작은 분리했다. 예상 밖 확대는 마스터에게 알리고 기존 기록에 근거와 남은 입력을 인계한다. 실제 자동 회수 여부는 별도 근거가 필요하다. [근거: Task 설계와 맥락 복원](../../raw/docs/02_design/automation_workflow.md#22-맥락-복원)

## 상태·시험·실패

승인 명세, 고정된 결과물, 검토 및 실제 시험 증거 없이 완료 판정을 하지 않는다. 시험은 요구사항 번호·조건·버전·예상과 실제·수행 세션·증거를 묶는다. 정상 결과뿐 아니라 오류 처리와 발견 결함의 재현·수정 후 시험을 남긴다. 로그인 실패, 도구 부재, 한도 소진, 실행 실패와 검증 불일치는 각각 차단 사유다. [근거: 상태·증거·재시도](../../raw/docs/02_design/automation_workflow.md#3-상태증거재시도)

같은 필수 결함이 두 차례 수정 후에도 반복되거나 재평가 없이 세 차례 검토를 초과하면 마스터가 원인·시도·방향을 재평가한다. 재평가 후 현재 회차를 초기화해도 전체 이력은 보존한다. 재작업은 해당 단계 이후 승인 효력을 취소하고 이전 제출·검토·해시 스냅샷을 보존한다. 이미 끝난 Task를 무조건 재실행하지 않으며, 실행 ID와 operation ID를 통해 동일 요청을 식별한다. [근거: 상태와 로컬 도구](../../raw/docs/02_design/automation_workflow.md#7-로컬-상태-도구)

## 비용·환경·기록

당시 구독 범위에서 모델과 제공자, 실제 세션 및 제한을 기록하고 한도 소진 시 상태를 남겨 대기했다. 자동 유료 API 전환은 없었다. Docker 작업 영역 분리는 네트워크·파일·비밀 접근의 설정 및 시험이 필요하며 Docker만으로 완전 격리를 보장하지 않는다. 설치와 로그인, 로컬 시험, 작은 실제 호출, 전체 프로토타입 완주는 별개의 확인이다. pstack 호환성과 VPC 이전도 재검증 전 완료로 볼 수 없었다. [근거: 환경·도구·비용 및 구현 순서](../../raw/docs/02_design/automation_workflow.md#5-환경도구비용)

실행 기록의 raw는 수집 가능한 원문이며 자동 수집이 보장되지 않는다. 접근할 수 없는 대화·내부 추론은 전체 수집에 포함하지 않고 인증정보를 제외한다. 당시 process_debug On은 추가 요약, Off는 추가 점검 중지를 뜻했으며 Off도 기본 기록을 멈추지 않았다. 사용량 추정치·실제 토큰·구독 잔량은 구분했다. **현행 process_debug 적용 의무는 종료**됐으며 기본 기록 조건은 유지된다. [근거: 기록과 당시 debug](../../raw/docs/02_design/automation_workflow.md#41-process_debug-onoff), [현행 규칙](../../AGENTS.md#작업-재개와-과거-프로세스-점검)

## Hermes의 차단과 재전송

당시에는 매 호출 직전 지정 모델의 구독 과금을 확인하고 실패·누락·다른 모드면 요청을 보내지 않았다. 허용된 세 원문 경로의 해시·행 범위를 확인하고 비밀이나 보류 자료를 입력에 넣지 않았다. 빈 도구 설정·빈 작업 폴더는 OS 수준 격리가 아니고 알려진 인증 패턴 검사도 모든 비밀을 잡지 못한다. [근거: 입력과 호출 경계](../../raw/docs/02_design/hermes_worker.md#호출비용-경계)

같은 Task ID는 성공·실패·중단과 무관하게 재전송하지 않는다. 180초 제한은 해당 CLI 자식에만 적용되고 gateway 종료를 보장하지 않는다. timeout이나 오류 후 실제 세션과 요청 도달 여부를 확인하고 마스터가 재시도 필요성을 판단한 뒤 새 명시 ID를 사용하도록 했다. receipt 삭제를 통한 우회나 불명확 상태의 자동 반복은 금지다. 반환된 초안은 내용 합격이나 완료가 아니다. [근거: 결과·중단·재전송](../../raw/docs/02_design/hermes_worker.md#결과중단재전송)

당시 로컬 시험 성공은 설치·인증·실제 연결·독립 QA·전체 완주를 뜻하지 않는다. 과거 검증에서 절대경로로 진행된 시험과 현행 상대경로 우선 기준은 시점을 나누어 읽는다. 제공자 상태와 현재 도구 동작은 이번에 재검증하지 않았다. [근거: 과거 검증](../../raw/docs/03_verification/automation_validation.md), [현행 규칙](../../AGENTS.md#검증과-보고)
