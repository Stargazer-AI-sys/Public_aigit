# 2026-10-13~11-02 관리 작업 이력

656줄 원문의 날짜별 사건을 주제와 시간에 따라 설명한다. 세부 기록과 당시 문서 버전·근거는 [보관 원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md), 현재 역할·보류·업무는 [공식 최신 인계](../../docs/04_records/management_log.md)를 따른다. 이 페이지는 옛 다음 작업을 자동 실행 요청으로 바꾸지 않는다.

## 10월 13~14일: 관리 역할과 원본 경계

10월 13일 관리 프로젝트는 PM·디렉터·조언자 역할과 사용자 의사결정, 개별 프로젝트의 소스·상세 기록을 원래 위치에 유지하는 경계를 정했다. README·AGENTS는 v0.1에서 v0.3까지 역할과 명시 요청에 따른 파일 반영을 차례로 명확히 했다. 당시 독립 실행 담당이나 별도 에이전트는 구성하지 않았다. 이후 날짜 보고의 제한적 지속 승인은 현재 AGENTS를 따른다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

10월 14일 Library 이전 과정에서 당시 60개 파일·26개 폴더 ZIP을 생성하고 무결성을 확인했다. PC 배치와 기존 저장소 commit·push는 **사용자 완료 보고**였으며 SHA·원격 포함 목록을 직접 확인한 것은 아니었다. 웹과 로컬의 실제 연결, 충돌·반영 주기는 당시 미확정이었다. 당시 PC 경로와 ZIP을 현재 원본으로 취급하지 않는다.

## 10월 15일: 공통 운영과 가이드·점검

GPT 공통 README·AGENTS를 마련하고 AI의 commit·push는 각각 명시적 요청이 필요하다고 구분했다. Git 사용자 가이드를 만들었다가 필수 단계 중심으로 간소화했고, 가이드 작성 스킬과 사용·설치 안내를 작성했다. PC·모바일 화면과 문서 링크는 당시 확인했지만 실제 Git 명령·인증 해제·삭제는 실행하지 않았다. 사용자 정상 동작 보고와 AI 직접 확인도 별개다.

ICT PC와 Stargazer PC의 경로·설치 상태는 각각 확인한 시점의 사실이다. Stargazer에서는 스킬 목록 등록만 확인하고 가이드 생성은 시험하지 않았으며, 사용자는 이전 문서의 원격 반영을 보고했다. 로컬·GitHub 중심과 필요 시 웹 Library 보조 사용을 정했지만 개별 프로젝트 재개는 보류했다. 최초 스킬 기본 검사기의 PyYAML 부재와 대체 점검은 당시 환경의 한계다.

이후 기획·인계 스킬과 문서 점검 도구를 마련해 구현 시험 12개와 당시 실제 가이드 8개의 링크·목차·ID를 확인했다. 새 가이드 한 파일의 1회 구조 검사는 [HTML 리뷰](HTML_점검_자동화_리뷰.md)에 별도로 설명한다. 다른 프로젝트에서 작성→점검→보고가 자동으로 이어지는지, 새 채팅 재개 및 다른 PC 설치는 별도 확인이었다. 예약과 개별 프로젝트 작업은 당시 보류했다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

## 10월 16일: PC 이동·공유 스킬과 공통 구조

PC 이동 후 재개 때 최신 인계와 해당 프로젝트 원본, 실제 환경·설치 차이를 대조하도록 README v0.12·AGENTS v0.8·워크플로 v0.7과 인계 스킬 v0.2를 보완했다. 당시 ICT PC에서는 가이드 개인 설치본이 공유 v0.3과 달랐고 기획·인계 개인 설치가 없었다. 설치본을 자동 수정하지 않았고 사용자 pull 완료는 사용자 보고로 남겼다.

공유 스킬 변경 시 원본 저장→관련 검증→실제 결과 보고를 반복하는 기준을 더하고, 세 스킬의 공통 사용을 gptgit 범위에 연결했다. 이후 공통 재개·스킬 검증·인계를 별도 공통 흐름으로 정리하고 스킬을 상위 공유 위치에 통합했다. 각 프로젝트의 기술 규칙·보류·기록 원본은 유지했으며 자료 폴더에 불필요한 규칙 사본을 만들지 않았다.

당시 Markdown 17개·상대 링크 165개를 검사했고 수정 HTML은 2회 검사했다. 브라우저 부재 후 기존 Edge에서 PC·모바일 화면을 확인했다. ICT 환경에 PyYAML을 설치한 뒤 UTF-8 옵션으로 세 스킬 기본 검사를 통과했지만, 이는 다른 PC 설치나 새 채팅 자동 준수의 검증이 아니다. 이전 PyYAML 부재 기록은 그 이전 시점의 사실이다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

## 10월 19일: 누락 보완과 최적화 위험

10월 16일의 설치·검증 이력을 보완하고, 개인 스킬의 누락·버전 차이를 감지해 설치·갱신하는 구상을 제안했다. 이는 로컬 수정 보호와 실패 처리가 필요한 **미구현 제안**이지 자동 설치·배포가 아니다. 사용자는 플랜·스킬이 잘 동작한다고 보고했으나 개별 PC·입력별 전수 검증 근거는 제공되지 않았다.

네트워크 프로젝트 문서를 읽고 짧은 절만 조회할 때 큰 맥락·변경 파급·인계 불일치·내용 누락을 놓칠 수 있다고 검토했다. 링크 검사 통과와 내용 보존은 다르며, 제안은 당시 해당 프로젝트 규칙에 반영하지 않았다. 네트워크 장비·통신은 시험하지 않았고 원본 프로젝트를 수정하지 않았다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

## 10월 27일: 자동화 기반과 공통 진입점

자동화 원장·증거 도구를 구현하고 별도 GPT QA와 Claude 정적 교차 검토를 거쳤다. 16→18→24 시험과 설치·후속 컨테이너 검증, 사용자 보고의 herdr 연결은 서로 다른 근거다. [자동화 검증 이력](automation_validation_history.md)에 수치와 한계를 모았다. 전체 자동화 완주는 당시에도 미완료였고 현재 관리 프로젝트의 현행 기능도 아니다.

공통 진입점과 기본 틀 1.0은 새 프로젝트의 소스·인증·보류를 관리 프로젝트에서 복사하지 않도록 구분했다. 개설·선택 등 모의 검사 18개와 화면 확인은 있었으나 신규 프로젝트 실사용은 사용자가 필요할 때 확인하기로 했다. herdr 기존 창 유지와 버튼 경로는 사용자 내부 확인 보고이며, 자동 시작·대화 복원 완료를 뜻하지 않았다.

Hermes 설치는 로그인·모델 추론의 증거가 아니었다. OAuth는 사용자의 명시적 동의 후 승인 화면 대기에서 중단돼 로그인 성공은 미확인이었다. 가이드 정식 제작과 기존 자료 전송 보류는 Hermes 연결 동의와 별개로 유지됐다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

## 10월 28일: Task 분리·Hermes 연결과 인계 시험

당시 Task별 담당 세션과 필요한 맥락만 전달하는 구조, process-debug 및 환경 구축을 준비했다. 인증·구독 확인과 제한형 Hermes 단일 응답 회수, 개별 도구 시험이 있었지만 전체 프로토타입은 검증하지 않았다. 옛 process-debug On/Off는 현재 의무가 아니다. [환경 검증 이력](automation_validation_history.md)

부모 대화가 없는 담당에게 인계를 복원하게 한 시험은 당시 완료·보류·On 상태 등을 복원했지만 실제 새 사용자 채팅 재개 검증은 아니었다. 실제 세션 ID의 슬래시를 bind가 거절한 문제는 그 시점에 미수정이었다. 관측 토큰은 일부 구간의 반복 입력을 포함하며 비용이나 실시간 잔여 컨텍스트가 아니다.

이후 내부 GPT가 보고한 GPT·Claude·Hermes 화면 연결은 사용자 전달 근거였고 외부 Codex가 직접 창을 제어한 결과가 아니었다. Hermes 응답 회수와 herdr 시작 감지 실패는 별개다. 실제 업무 전달 전체, 자동 복원 및 제작→QA→문서화 완주를 의미하지 않는다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)

## 11월 2일: 시작기 개선과 작은 역할 분담 시험

Codex 시작기 경로 탐색 개선의 제작 모의 시험 17개와 기존 역할 판정 35개가 통과했다. 읽기 전용 CheckOnly의 로그인 확인, 별도 GPT 읽기 전용 검토, 사용자가 보고한 새 세션 실행을 구분한다. 변경된 시작기로 실제 화면까지 여는 동작과 다른 PC는 당시 미검증이었고, GPT 검토를 Claude 교차 검토로 부르지 않았다.

같은 날 별도 요청으로 Claude가 짝수 합 함수를 작성·자체 실행하고 GPT가 정상·빈 목록·음수의 세 사례를 별도 실행 검증했다. Hermes 대화 창은 `invalid_params`로 실패했으나 동일 설치의 단일 응답 경로에서 문서 초안을 회수했다. GPT는 최초 초안의 담당 오류를 반려하고 수정본을 근거와 대조했다. Claude 제작↔GPT 검증은 제공자 간 검증이지만 Hermes 문서화와 GPT 검토는 같은 GPT 계열의 별도 실행이다. 별도 QA 세션과 전체 자동화 완주를 뜻하지 않는다.

당시 wiki 파일 저장·Obsidian 확인은 실행하지 않았고, 정수 이외 입력·대규모 성능도 미검증이었다. 가이드 제작·보류 자료 전송은 계속 보류했다. 이후 11월 4일 프로토타입 구축과 개선 원본 위치 정정은 [별도 구축 이력](prototype_build_history_2026-11-04.md)을 본다. [원문](../../raw/docs/04_records/management_history_2026-10-13_2026-11-02.md)
