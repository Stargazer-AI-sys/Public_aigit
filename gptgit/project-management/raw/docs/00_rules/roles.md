# 자동화 역할과 인계 기준

> 버전: 0.2 | 최종 수정: 2026-10-28 | 적용: 이 프로젝트에서 승인된 자동화 실행

행동·수정 권한은 [AGENTS](../../AGENTS.md), 단계·증거·재시도 기준은 [자동화 워크플로](../02_design/automation_workflow.md)를 따른다. 이 문서는 역할 책임의 원본이다. 역할 이름을 선언한 것만으로 실제 에이전트 연결이나 교차 검증이 완료되는 것은 아니다.

## 책임과 경계

| 역할 | 입력과 책임 | 출력과 인계 조건 | 금지·제한 |
| --- | --- | --- | --- |
| 마스터 GPT | 사용자 요청, 승인 명세, 현재 상태를 받아 범위·우선순위·모델·담당 결정 | 필요한 결정을 사용자에게 설명하고 증거를 대조한 Phase 보고·최종 보고 제공 | 근거 없는 완료 판정, 범위·비용의 임의 확대 금지 |
| 기획 GPT | 요청의 목적·대상·대표 결과와 제약을 실행계획으로 구체화 | 요구사항 번호와 연결된 Phase·Task·Step, 완료 조건·검증 방법 | 명세를 복사하여 별도 진실 원본을 만들지 않음 |
| Claude 기획 검토 | 승인 명세와 계획의 실현 가능성·누락·과도한 의존성 확인 | 필수 수정과 선택적 개선을 구분한 읽기 전용 의견 | 계획 원본 직접 수정 금지 |
| 제작 Claude | 승인 계획에 따른 코드·문서·자동화 산출물 제작·자체 시험·수정 | 변경 파일, 시험 결과, 한계와 증거를 검토 담당에게 전달 | 자신의 결과 최종 승인, 지시 밖 확장 금지 |
| GPT 제작 검토 | 승인 명세·계획과 결과·증거 대조 | 재현 조건·영향·근거를 포함한 결함 또는 합격 판정 | 제작 원본 직접 수정 금지 |
| 독립 QA | 승인 명세, 고정된 결과물 버전, 시험 환경·입력 | 실제 사용 시험, 예상·실제 결과, 대표 캡처·로그, 미검증 항목 | 제작자의 성공 주장으로 시험 대체 금지 |
| Hermes 운영 | 작업 전달 보조, 실행 기록·변경점·근거 정리 | 원문에 연결된 상태 요약과 wiki 초안 | 범위·합격 기준·완료 상태 임의 변경 금지 |
| GPT 문서 검토 | 변경된 wiki·가이드와 실제 원본·검증 증거 대조 | 설명과 결과의 일치·링크·누락 검토 | 검토하면서 설명 원본을 직접 고치지 않음 |

마스터는 Task별 담당 세션·명세 버전·파일 소유 범위·인계 상태를 연결하고 결과를 종합한다. 기획 담당은 요구사항 단계부터 Task별 산출물·입출력·완료·검토·인계 조건과 새 세션 구성을 실행계획에 설계한다. 실행 담당은 예상 밖 확대를 마스터에게 알리고 기존 공식 기록에 인계를 남긴다. 운영 담당은 실제 수집 가능한 근거와 누락을 구분해 process_debug 요약을 지원하며, 역할 대체 시에도 같은 책임을 유지한다.

## 세션과 모델

- 사용자는 herdr의 마스터 GPT 세션하고만 대화하는 것을 목표로 한다. 다른 세션은 관찰용이며, 담당 에이전트의 질문·차단 사유는 마스터가 모아 전달한다. 로그인·설치 등 사용자만 할 수 있는 작업은 별도로 설명한다.
- 기획·제작 검토·독립 QA는 같은 GPT 계열을 사용할 수 있지만 세션을 분리한다. QA에는 제작 대화 전체를 기본 전달하지 않고 승인 명세·시험 환경·고정된 결과물을 전달한다.
- 세션 식별자는 실제 실행 세션을 가리켜야 한다. 다른 문자열을 입력한 것만으로 독립성이 입증되지는 않는다. 실행 기록과 원문을 대조한다.
- Task별 새 세션을 기본으로 하며 같은 단위의 수정은 재사용할 수 있다. 독립 조사만 병렬로 진행하고 동일 파일 동시 쓰기를 금지한다. 부모 대화 전체 복사 대신 필요한 원본·결정·금지·보류·Task 명세를 전달하며, 전환·확대 인계·맥락 복원의 상세 절차는 자동화 워크플로 2.1·2.2절을 따른다.
- 교차 검증은 GPT↔Claude처럼 서로 다른 제공자에 의한 검증, 독립 검토는 작성자와 분리된 세션의 검토를 뜻한다. Hermes가 GPT를 사용하면 GPT의 Hermes 결과 검토는 별도 세션 검토로 보고한다.
- 일반 스크립트가 가능한 형식 검사에는 LLM을 쓰지 않는다. 모델은 실제 구독에서 제공되는 목록 안에서 작업 난이도에 맞춰 선택하고, 선택 이유·실제 모델·사용량 제한을 기록한다. 고성능 모델은 복잡한 설계·반복 실패·중요 판정 충돌에 우선한다.
- 연결되지 않은 역할을 임의로 실행한 것으로 기록하지 않는다. 대체 담당을 썼다면 실제 제공자·세션과 대체 이유를 기록하고, 원래의 교차 검증 조건 충족 여부를 별도로 남긴다.

## 인계와 충돌 해결

인계에는 실행·작업 ID, 승인 명세의 버전과 위치, 입력·출력 위치, 담당 역할·제공자·세션, 완료 기준, 시험 결과·증거, 미해결 사항을 포함한다. 검토할 파일의 버전을 고정하고 변경되면 관련 검토·QA를 다시 수행한다.

세션은 사람이 식별할 Task 별칭과 실제 ID를 함께 연결한다. 새 담당자는 최신 공식 기록을 관련 결정·설계 원본 및 현재 미저장 대화와 대조하고 결정 완료·미구현·미검증·미정을 구분한다. process_debug On일 때 응답별 표시를 제공하며 Off도 기록 책임은 유지한다. 상세 표시·사용량 한계는 자동화 워크플로 4.1절을 원본으로 삼는다.

판정 충돌은 마스터가 사용자 목표 → 승인 명세 → 원본·재현 증거 순서로 대조해 해결한다. 필수 결함과 범위 밖 개선은 분리한다. 비용·핵심 범위·외부 공개·되돌리기 어려운 변경은 사용자 결정으로 돌린다. 검토 담당은 문제를 발견하면 제작 담당에게 반환하며 직접 수정하지 않는다.
