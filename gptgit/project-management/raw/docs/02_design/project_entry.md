# 프로젝트 개설과 공통 진입점

> 버전: 1.0 | 2026-10-27 | 로컬 개설·선택 구현, AI 시작·복원 연결 전

## 목적과 책임

project-management는 여러 프로젝트에 적용할 환경·공통 절차·기본 틀을 개선하는 관리 프로젝트다. 사용자의 개별 작업은 별도 프로젝트 폴더에서 수행한다. 관리 프로젝트의 개선 작업과 새 프로젝트의 제작 작업을 혼동하지 않는다.

‘프로젝트 관리 열기’는 신규 개설·기존 프로젝트 열기·관리 환경 점검을 선택하는 Windows 화면이다. 단순히 실행했다는 이유로 새 프로젝트를 만들거나 이전 AI 대화를 선택하지 않는다. 마스터 GPT를 사용자 대화 창구로 유지하며, 개설 화면의 목적 입력은 초기 입력일 뿐 상세 제작 승인이나 기획 완료를 뜻하지 않는다.

## 구현된 흐름

1. 새 프로젝트 만들기: 이름·목적·저장할 상위 폴더를 표시하고 사용자가 생성 버튼을 누르면 새 폴더를 만든다. 같은 이름이 있으면 거절하고 기존 폴더를 덮어쓰지 않는다.
2. 기존 프로젝트 열기: 사용자가 선택한 폴더를 작업 위치로 지정하여 프로젝트별 herdr 세션을 연다. 기존 문서·기록·규칙을 변경하거나 기본 틀을 주입하지 않는다.
3. 관리 환경 열기: project-management 세션을 연다. 시험·설치·모델 호출을 자동 실행하지 않는다.
4. 관리 AI 연결·재개 요청: 관리 프로젝트의 요청 파일을 저장하고 herdr 세션을 연다. [내부 수신기·연결 실행기](agent_session_lifecycle.md)가 켜져 있으면 기본적으로 기존 창 유지 요청을 자동 처리한다. 수신기 자체는 실제 herdr 내부에서 한 번 시작해야 하며 Desktop이 외부에서 기동하지 않는다. 화면에는 로컬 요청 처리 상태를 표시한다.

생성 직후에는 위치를 보여주며 AI 작업을 자동 호출하지 않는다. 요구사항·대표 결과 합의는 이후 마스터와 진행한다. 프로젝트별 세션 이름은 정규화한 폴더 경로의 해시로 구분한다. 관리 프로젝트는 기존 project-management 이름을 유지한다. 폴더 이동 시 해시가 바뀌므로 기존 세션 자동 이전은 아직 지원하지 않는다.

## 공통 기본 틀

[기본 틀 1.0](../../templates/project-v1/README.md)은 현재 프로젝트를 통째로 복사한 것이 아니라 재사용할 최소 문서만 별도로 정의한 원본이다.

| 생성 파일 | 책임 |
| --- | --- |
| README.md | 목적·문서 진입점 |
| AGENTS.md | 기본 작업·권한·역할·검증 기준 |
| docs/project.md | 초기 목적과 합의할 요구사항·실행계획 |
| docs/04_records/work_log.md | 개설 사실·현재 미수행 상태·다음 행동 |
| .project-management.json | 기본 틀 버전·개설 시각·프로젝트명, 현재 비어 있는 대화 연결 정보 |

개발·네트워크·문서 제작에 필요한 전문 구조는 프로젝트 요구사항을 보고 추가한다. wiki·guide_docs·실행별 workflows도 필요할 때 만든다. 관리 프로젝트의 시험 결과·가이드 보류·설치 경로·인증·대화 ID는 복사하지 않는다. 새 프로젝트는 개설 버전을 유지하며 공통 기본 틀 수정이 기존 프로젝트를 자동 갱신하지 않는다.

기본 저장 위치는 gptgit 하위다. 사용자가 다른 위치를 선택하면 그 위치의 상위 규칙을 확인해야 하며, gptgit 공통 스킬·규칙이 자동 연결됐다고 주장하지 않는다. 기존 프로젝트는 자기 원본을 우선한다.

## 아직 연결하지 않은 기능

- 관리 프로젝트 내부 실행기의 실제 GPT·Claude 창 생성·구독 인증 후 시작 검증. 구현 범위와 제한은 대화 수명주기 문서를 따른다. 신규 프로젝트 적용은 별도다.
- 마스터 대화에서 합의한 개설 요청과 화면의 프로젝트 생성 절차 연결.
- 닫힌 탭 복구와 진입 화면의 AI 자동 연결. 프로젝트·역할별 로컬 대화 저장·명시적 재개 및 시작기 재사용 판정은 [대화 수명주기](agent_session_lifecycle.md)에 구현·모의 검증했으며 실제 복원은 미검증이다. 현재 빈 conversation_sessions는 복원 구현을 의미하지 않는다.
- herdr 공식 연동과 Claude 훅 비활성 설정의 호환성 확인. 현재 시작기는 관리 프로젝트용이며 새 프로젝트에 무조건 실행하지 않는다.
- 시작기의 기존 창 상태 검사·재사용·중복 실행 방지에 대한 실제 내부 실행 확인. 외부 진입 화면은 기존 창에 명령을 입력하지 않는다.

이 연결은 herdr 내부 실행 조건과 실제 세션·프로젝트 대조를 충족한 뒤 구현·검증한다. 새 프로젝트는 새 대화로 시작하고 기존 프로젝트만 확인된 대화를 재개한다. 무조건 ‘가장 최근 대화’를 선택하지 않는다. 대화 복원으로 진행 중 프로세스나 미저장 파일까지 복구된다고 보장하지 않는다.

## 검증과 제한

[개설·선택 도구](../../tools/project_hub.psm1), [화면](../../tools/project_hub_ui.ps1), [시험](../../tools/test_project_hub.ps1)을 분리했다. 시험은 .local/hub-tests 아래의 고유한 시험 폴더만 생성하며 실제 사용자 프로젝트를 개설하거나 수정하지 않는다. 시험 자료는 실패 원인 확인을 위해 보존한다.

프로젝트 경로를 세션 이름으로 구분하는 것은 보안 격리나 접근 통제가 아니다. 로그인·추가 청구·AI 호출·전체 자동화 성공은 이 로컬 시험으로 판정하지 않는다. 가이드 정식 제작과 기존 자료의 Claude 전송 보류, 재시작·유료 호출·Git 제한은 유지한다.
