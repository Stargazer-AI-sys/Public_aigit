## 2026-10-13 — 초기 운영 기준 수립

### 요청과 목적

AI로 진행하는 개별 프로젝트를 관리·개선하는 상위 프로젝트의 역할을 정의하고 기본 문서와 확장 가능한 폴더 구조를 마련했다. 이후 조언자 역할과 명시적 요청에 따른 파일 반영 규칙을 추가했다. 이번 작업기록은 사용자의 저장 요청에 따라 작성했다.

### 확정한 사항

| 항목 | 결정 내용 |
| --- | --- |
| 프로젝트 역할 | PM·디렉터·조언자를 함께 수행한다. 역할은 추후 세분화할 수 있다. |

| 관리 경계 | 개별 프로젝트의 소스·상세 상태·작업기록은 원래 프로젝트에 유지한다. 이곳에서는 공통 개선과 조정을 담당한다. |

3. README·AGENTS v0.1을 작성해 프로젝트 정의, PM·디렉터 책임, 작업 경계, 역할 확장과 방침 변경 절차를 마련했다.

## 2026-10-14 — Library 전체 이전 및 Git 관리, 로컬 작업 인계

### 최신 인계 요약

현재 웹에서 작업기록을 갱신한 상태다. 사용자는 Library 복사본을 PC에 배치하고 기존 `Aigit` 저장소에 커밋·push까지 완료했다고 보고했다. 로컬 프로젝트 연결 및 실제 파일 조회 성공은 아직 확인하지 않았다. 이번 기록을 내려받아 로컬의 동일 파일을 갱신한 뒤, 로컬 채팅에서 README·AGENTS·이 절을 읽고 이어가는 것이 다음 작업이다.

| 항목 | 상태와 근거 |

### 현재 적용 기준과 미확정 사항

- AI 역할은 PM·디렉터·조언자다. 사용자 직접 작업과 AI 수행 작업을 구분하고 더 나은 대안을 설명한다.
- 파일 반영은 명시적 요청 때만 수행한다. 로컬 연결·문서 읽기 자체는 문서 수정이나 커밋·push 허용을 뜻하지 않는다.
- GitHub를 통한 PC 간 공유와 웹 Library 반영은 별개다. commit·push만으로 Library가 갱신되지는 않는다.
- 로컬 작업과 원격 Git 저장소를 중심으로 운영하고 Library는 필요한 시점에 갱신하는 방식을 제안했다. 최종 원본 위치와 웹·로컬 충돌 해결·반영 주기는 아직 확정하지 않았다.
- 로컬 프로젝트를 별도로 열어 기존 문서로 이어가는 방식을 안내했다. 웹 채팅 이력이 자동으로 로컬 프로젝트에 합쳐진 것으로 간주하지 않는다. 실제 앱의 메뉴와 지원 상태는 사용자의 설치 환경에서 확인한다.
- 같은 저장소에서 다른 프로젝트의 변경이 함께 발생할 수 있다. Git 작업 요청 시 저장소 상태와 대상 파일을 확인하고 요청 범위의 변경만 기록한다.
- 역할 지침인 AGENTS와 실제 파일 접근 권한은 구분한다. 이 웹 채팅에는 사용자 PC 경로에 대한 직접 접근이 연결되지 않았다.

## 2026-10-15 — GPT 공통 운영 방법과 Git 실행 제한 명시

- 사용자 요청으로 gptgit 최상위 README.md와 AGENTS.md를 생성했다. 공통 규칙의 적용 범위는 GPT 작업 공간이며, Git 저장소 단위는 상위 Aigit 전체로 구분했다.

- AI의 commit과 push는 각각 명시적 실행 요청이 있을 때만 허용한다. 파일 반영 요청이나 작업 완료를 Git 허가로 해석하지 않으며 자동 commit·push를 금지했다.
- 이 프로젝트의 README·AGENTS를 0.4로 갱신하고 공통 문서 참조를 연결했다. 다른 하위 프로젝트 문서는 수정하지 않았다.
- 기준: [GPT 공통 README](../../../README.md), [GPT 공통 AGENTS](../../../AGENTS.md).
- Git 명령은 실행하지 않았다. 웹 반영 주기와 웹·로컬 충돌 처리의 세부 절차는 미확정이다.

- **자동 설치·갱신은 미구현 제안**이다. 현재 확정된 생성·수정 시 공유 원본 저장·검증·보고 절차와 구분한다. 설치 범위·로컬 수정 보호·검증·실패 처리·실행 권한을 정해 구현 요청을 받은 뒤 진행하며, 이번 기록 보완으로 설치 금지 조건이나 예약·Git 권한을 변경하지 않는다.

### 다음 작업 — 재시작 이후

1. 사용자가 원하는 시점에 Windows를 재시작한다. AI가 임의로 재시작하지 않는다.
2. WSL2 상태·가상화 지원을 확인하고 Docker Desktop을 시작한다. 첫 실행 약관·필요 설정은 사용자가 확인한다. Docker 엔진이 준비되면 프로젝트의 `docker compose run --rm verify`를 실행하여 실제 컨테이너 시험·읽기 전용 마운트·네트워크 제한을 확인한다. compose.yaml은 작성했지만 실행하지 않았다.
3. `tools/start_master.ps1`로 herdr 안의 마스터 GPT를 시작해 Claude 작업 전달·상태·결과 회수를 검증한다. 시작기의 구독 가드는 해당 실행 경로만 보호하며 임의의 다른 CLI·설정 변경을 통제하지 않는다.
4. Hermes는 아직 설치·연결하지 않았다. 공식 설치 방식·ChatGPT 구독 연결과 사용량 경로를 확인하고 추가 API 비용 없이 가능한 범위만 설치·시험한다. 현재 운영 기록은 로컬 스크립트가 담당한다. pstack은 필요한 기능만 호환성을 확인한 뒤 도입한다.
5. 가이드 대표 화면을 사용자와 확인한다. Claude 기획 사전 검토 G1은 계획에 초안 취급을 명시해 수정했으나 재검토 전이다. 기획 재검토→정식 제작→별도 QA→wiki 검토를 수행한다. 완료 상태로 바꾸기 위해 증거를 꾸며 넣지 않는다.
6. 자동 전달·수집·모델 선택·판정 루프, 실제 세션 중단/재개, 정상·실패 화면 증거를 연결한다. 목표 완료 기준을 충족하기 전까지 전체 자동화는 미완료로 둔다.

### 재개 시 주의

- 설치 파일·인증은 이 PC 상태다. 다른 PC에는 재현 설치기와 공식 로그인 절차가 필요하다. 비밀번호·토큰은 문서에 보관하지 않았다.
- .local은 Git 제외이며 설치 파일·임시 시험·CLI 원문을 보관한다. 공식 검증 근거는 docs/03_verification/automation-evidence에 옮겼다. 초기 개인 스킬과 공유 원본 차이는 그대로 두고 공유 원본을 적용했다.
- 실제 Git commit·push는 하지 않았다. 현재 변경을 요청 범위대로 검토한 후 사용자가 명시적으로 요청한 Git 작업만 수행한다.

- **Docker:** 사용자가 재시작과 설치 복구 후 Client/Server 출력을 제공했다. - **herdr 전달·회수 — 사용자 보고:** project-management의 w1:p4에서 Claude 세션 `c4f9572a-0272-41bc-8b11-9e4d1e9efae3`에 지정 문구를 한 번 전달하고 `HERDR_CLAUDE_OK_20261027`·success를 회수했다. 프로젝트 자동 읽기와 도구를 끈 짧은 시험이다. 실행 순서 오류로 종료 코드는 확보하지 못했다. 이후 사용자가 우측 터미널에서 Claude Code가 동작하는 것을 확인했다. 이 채팅이 herdr 내부 세션을 직접 제어해 확인한 것으로 기록하지 않는다.

## 2026-10-27 — 공통 진입점·herdr 연결 검증 완료 범위와 Hermes 로그인 중단

### 공통 진입점과 프로젝트 개설

- 사용자가 관리 프로젝트의 역할을 ‘여러 프로젝트용 환경·절차·기본 틀 개선’으로 명확히 했다. 신규 작업은 별도 프로젝트 폴더에 개설하고 공통 기본 틀을 적용하며 현재 관리 프로젝트의 시험·보류·인증·대화를 복사하지 않는다. 기존 프로젝트에는 개선안을 자동 덮어쓰지 않는다.

- 직접 검사: 프로젝트 개설·선택·중복/위험 이름 거절·원본 보존 18개 통과, 당시 문서 링크 47개 문제 없음. 대표 시작 화면을 렌더링해 확인했다. **신규 프로젝트 실사용 검증은 사용자가 필요할 때 수행하기로 했으므로 현재 필수 작업에서 제외한다.**

### herdr 연결과 창 유지 — 사용자 확인 근거

- 사용자가 herdr 내부에서 확인한 project-management 세션의 클라이언트·서버는 0.9.5, 작업 경로는 현재 관리 프로젝트다. 좌측 GPT w3:p1, 우측 Claude w3:p2(Opus 5.5·Claude Pro)였으며 기존 창을 유지했다.
- GPT 대화 ID는 `01a17bf2-6d0f-7421-86e7-325e90ab0b7a`(환경변수), Claude는 `295d9612-c843-4648-a60c-13fdac73346d`(당시 /status)로 사용자 보고를 받았다. 새 CLAUDE.md·coordination.md·상위/프로젝트 AGENTS·automation-handoff 등록을 확인했고, 확인 문구 한 번의 실제 응답 `HERDR_LINK_OK_20261027_W3P2_01`을 회수했다고 보고받았다. 스킬의 실제 작업 수행은 미검증이다. 원문 도구 출력은 내부 검증 채팅에 있고 별도 파일로 제공되지 않았다.
- 대화 정보는 `.local/agent-sessions/`에 source=user_report로 저장했다. Desktop 직접 검증으로 바꾸지 않았다. 창 번호는 관측값이며 현재 제어 대상을 그 값만으로 결정하지 않는다.
- [대화 수명주기 기준](../02_design/agent_session_lifecycle.md) v0.4에 상세 구현·한계가 있다. 역할별 프로젝트·현재 상태 대조, 중복 시작 잠금, 명시적 저장 대화 재개, 창 유지와 대화 ID 검증 분리를 구현했다. 모의 역할 판정 35개 통과.
- 사용자가 PowerShell 7.6.5에서 변경된 `check_agent_sessions.ps1 -Live` 실행 성공(exit 0)을 보고했다. 최초 권한 오류 후 추가 권한으로 동일 검사를 실행했다. schema_version=2, master=reuse/reusable/working, producer=reuse/reusable/idle, 두 역할의 conversation_check=unverified/source=none/observed_id=null, saved_source=user_report, automatic_prompt_allowed=false, restore_verified=false였다. 그 출력에 agent_session 자체는 없으므로 해당 재검사에서 null을 직접 확인한 것으로 확대하지 않는다.
- `connect_workspace_agents.ps1 -Apply -ReuseOnly`도 사용자 내부 실행 성공(exit 0)을 보고받았다. processed, 양쪽 preserved, ID unverified, restore_verified=false, prompts_sent=0이었다. 로컬 요청 상태만 갱신했고 새 AI·메시지·창 생성/종료·재시작은 없었다.

### 화면 요청 자동 수신 — 구현과 사용자 확인

- 시작 화면에 ‘관리 AI 연결·재개 요청’을 추가했다. Desktop은 로컬 요청을 저장하고 화면을 열며 실제 세션 제어는 내부 실행기가 담당한다. 수신기는 새 요청이 있을 때만 내부 연결 실행기를 호출하고 기본 reuse-only 모드에서 기존 창을 보존한다. 누락 역할 시작은 별도 AllowStartMissing 옵션이며 이번 실사용에서 켜지 않았다.
- 중복 클릭·동시 처리·전달 전 이력·처리 중단 후 재전송 방지, 예상 요청 ID 대조, 화면의 로컬 처리 상태·최근 수신기 응답 표시를 구현했다. 요청/외부 경계 9개, 수신기 모의 처리 10개 검사 통과. 실제 herdr 제어를 모의 검사했다고 표현하지 않는다.
- 사용자 내부 실행 보고: 서비스 창 w3:p3, 수신기 PID 30312, reuse-only/waiting, 이전 요청 not_pending으로 재실행하지 않음. 기존 GPT w3:p1·Claude w3:p2를 유지했다. PID·창 번호는 당시 값이며 재개 시 현재 상태를 추측하지 않는다.
- 이어 사용자가 시작 화면 버튼의 결과를 확인했다고 보고했다. **시작 화면 → 내부 수신 → 기존 창 유지 경로는 사용자 확인 완료**다. 동일 검사를 다시 요구하지 않는다. 수신기는 당시 계속 대기 중이라고 보고됐으며, 이번 중단 요청에서는 herdr 서비스나 기존 AI를 종료하지 않았다. 현재 생존 상태는 재조회하지 않았다.
- 사용자는 **새 AI 시작·대화 복원은 herdr 안에서 필요할 때 직접 처리하거나 추가 요청하겠다고 결정했다.** 해당 추가 구현·실제 복원 시험을 현재 필수 작업에서 제외한다. 검증 완료로 바꾸는 것은 아니다. 자동화 전체 제작→독립 QA→문서화 완주는 여전히 미완료다.

### Hermes 연결 준비와 중단 지점

- 사용자가 Hermes 연결부터 진행하도록 요청했다. 기존 설치를 확인하니 기본 데이터 위치로 실행할 때 ruamel 의존성 오류가 발생했다. `HERMES_HOME`을 프로젝트 `.local/hermes-setup/data`로 지정하자 기존 런타임에서 정상 동작했다. 재설치·업데이트하지 않았다.
- [Hermes 연결 도구](../../tools/hermes_connection.ps1)를 추가했다. Check는 버전·Nous 인증 상태만 확인하고 Login은 공식 Nous OAuth 흐름만 시작한다. 프로젝트 데이터 경로를 명시하고 실행 후 기존 환경변수를 복원한다. 모델 호출·유료 도구 설정·유료 플랜 선택 기능은 넣지 않았다.
- 직접 확인한 출력: Hermes v0.22.5 stable, local bf0203a794a0, Python 3.14.9, OpenAI SDK 2.24.0. 로그인 시작 전 상태는 `nous: logged out`이었다. Check exit 0은 로그인 완료를 뜻하지 않는다.
- 공식 [OpenAI 플랜 공유 안내](https://learn.chatgpt.com/docs/sign-in-with-chatgpt)에서 Hermes Agent가 플랜 사용 지원 앱으로 안내됨을 확인했다. [Nous 플랜 공유 안내](https://portal.nousresearch.com/help/chatgpt-plan-sharing)는 지원 추론에 ChatGPT 플랜을 사용할 수 있고 유료 Nous 구독이 필요하지 않다고 설명한다. 도구·다른 모델·호스팅은 별도 과금 대상이며 기존 ChatGPT 한도를 함께 사용한다. 이는 계정별 연결·과금 설정을 실제 확인한 결과와 구분한다.
- 최초 로그인은 네트워크 이름 확인 오류로 실패했다. 추가 권한 재시도는 자동 승인 검토가 ‘Nous 계정 연결·ChatGPT 플랜 사용 공유의 구체적 동의 부족’을 이유로 차단했다. 이후 사용자가 **‘동의: 로그인·플랜 공유 진행’**을 명시적으로 선택해 동의가 확보됐다. 유료 Nous 구독·크레딧 구매·유료 도구는 사용하지 않으며 로그인·동의 화면은 사용자가 직접 확인하는 조건이다. 이 동의는 다음 재개에도 유지한다.
- 동의 후 공식 OAuth 로그인 시작은 허용되어 브라우저 승인 대기까지 진입했다. 사용자는 로그인 페이지에서 작업 중단·기록 저장을 요청했다. 승인 완료·플랜 공유 활성화·모델 연결·실제 추론은 확인하지 못했다.
- **중단 처리:** 이 채팅이 실행한 OAuth 대기 프로세스에 Ctrl+C를 보내 KeyboardInterrupt·종료 코드 1로 종료된 것을 직접 확인했다. 로그인 성공 코드가 아니다. 브라우저 연결 권한을 취소하거나 이미 저장된 인증을 삭제한 것으로 해석하지 않는다. 중단 후 계정 상태는 추가 조회하지 않았다. 일회용 인증 코드·인증 URL·토큰은 이 기록에 저장하지 않는다. 이전 코드 재사용을 안내하지 않는다.

### 다음 재개 지점과 조건

1. 사용자가 Hermes 작업을 재개하면 프로젝트 루트에서 Hermes 연결 도구의 Check로 현재 인증 상태부터 확인한다. 이미 연결돼 있으면 로그인을 반복하지 않는다. 미인증이면 기존 동의 범위에서 Login을 시작하고 새 승인 화면을 사용자에게 제공한다.
2. 로그인과 ChatGPT 플랜 공유는 별개다. 사용자 화면 또는 지원되는 공식 상태 조회로 실제 플랜 공유 활성화·대상 모델·한도·추가 크레딧 사용 설정을 확인한다. 결제·새 구독·크레딧 구매·유료 도구를 활성화하지 않는다. 계정별 조건이 불명확하면 모델 시험은 보류한다.
3. 추가 과금 없는 경로를 실제 설정에서 확인한 뒤, 프로젝트 문서를 보내지 않는 최소 입력과 도구 비활성 범위로 연결 시험을 진행한다. 아직 실행하지 않은 모델 호출을 완료로 기록하지 않는다. 전역/다른 제공자 fallback과 유료 도구는 별도 확인 대상이다.
4. Hermes 인증·모델 연결 성공과 프로젝트 운영 자동화 통합은 구분한다. 역할·입출력·허용 도구·기록 연계를 확인한 범위에서만 다음 통합을 진행한다. 현재는 로그인 단계에서 멈췄다.

### 유지할 제한

- 사용자 요청으로 지금 작업을 멈췄다. 로그인 재시도·계정 연결·모델 시험을 자동으로 이어가지 않는다. 다음 사용자 재개 요청을 기다린다.
- 신규 프로젝트 실사용 검증과 새 AI 시작·대화 복원은 필요 시 별도 요청 항목이다. 완료한 연결·기존 창 유지 검사를 일괄 반복하지 않는다.
- 가이드 정식 제작과 기존 HTML·실행계획·simple-user-guide 원문의 Claude 전송은 계속 보류다. Hermes 연결 동의가 이 보류를 해제하지 않는다.
- 추가 API 비용·재시작·commit·push 금지 유지. 이번 기록 저장은 작업기록 갱신이며 별도 설치·모델 호출·Git 작업은 수행하지 않았다.

## 2026-10-28 — Task 세션·process_debug 반영과 Hermes 실행 환경 준비

사용자가 제안 방식 적용·프로세스 반영·작업환경 구축을 요청했다. **Task 분리와 점검 도구 준비, Hermes 제한형 작업 전달·회수 시험 완료 / 전체 프로토타입 미검증**이다. 상세 실행 근거와 담당 간 요청·수정·검토 요약은 [환경 구축 기록](../workflows/environment-setup/timeline.md)에 둔다.

### 프로세스 반영

- 요구사항·기획부터 Task별 새 담당 세션과 입출력·완료·인계 조건을 정한다. 부모 대화 전체를 복사하지 않고 관련 결정과 문서 범위만 전달한다. 예상 작업 증가 시 완료 근거·남은 작업을 기록해 인계하고 마스터가 보고한다. 이번에도 DEBUG-01·PROCESS-01·ENV-01을 분리하고 독립 검토를 수행했다.
- 최신 인계만으로 판단하지 않고 관련 요구사항·설계·결정 원본 및 현재 미저장 대화를 대조한다. 공통 작업 흐름·project-handoff·project-planning 공유 원본과 프로젝트 역할·워크플로·AGENTS에 반영했다. 개인 설치본을 자동 덮어쓰지 않았다.
- [process-debug 스킬](../../skills/process-debug/SKILL.md)과 [점검 도구](../../tools/process_debug.py)를 만들었다. 명령은 process_debug On/Off이며 실행별로 유지된다. On일 때 응답마다 세션·Task·문서 절/줄·관측 사용량과 잠정 규모를 종합 보고한다. Off에서도 기존 작업 증거는 유지하되 추가 측정은 소급하지 않는다. 이번 작업 전체의 점검 모드를 소급 On으로 만들지 않았다.
- 현재/남은 컨텍스트와 누적 토큰·구독 한도는 다른 값이다. 공개된 사용량 이벤트 또는 해당 세션 로그의 숫자만 이용하며 관측값·추정·미측정을 구분한다. 일반 도구의 모든 읽기와 에이전트 대화를 자동 감시하는 기능은 아니다. 보고서 모양과 실제 한 작업의 비용 해석은 이후 프로토타입에서 검증한다.

### 실행 환경과 실제 확인

- Nous 로그인 및 ChatGPT 연결을 완료했다. 사용자가 Hermes Portal 공유 On·100%를 확인했고 계정 사용량 화면도 확인했다. 결제·크레딧 확인은 사용자가 맡는다. 무료/유료 플랜을 다시 선택하도록 요구하지 않는다.
- openai 모듈 오류는 단순 미설치가 아니라 Windows 긴 경로 설정과 관련됨을 확인했다. 사용자 승인으로 LongPathsEnabled를 0에서 1로 변경한 후 새 Python 프로세스에서 SDK import가 성공했다. 라이브러리 재설치나 PC 재시작을 하지 않았다.
- 최소 직접 호출 HERMES_CONNECTION_OK와 Hermes 자체 실행 HERMES_RUNTIME_OK를 확인했다. 이어 [제한형 worker](../02_design/hermes_worker.md)로 새 세션 작업 전달·결과 회수를 실제 확인했다. 기본 모델 설정은 유지하고 시험 명령에서 openai/gpt-6-luna를 명시했다. 모델 요청 직전 subscription을 확인하며 추가 API 비용 경로로 자동 전환하지 않는다.
- worker의 합성 시험 응답은 HERMES_WORKER_OK, 입력 1,293·출력 10·총 1,303토큰이었다. 프로젝트 문서를 보내지 않았다. 실제 출력·세션 ID·해시와 구독 확인은 환경 구축 raw 기록에 있다. 이 수치를 전체 작업 사용량이나 정확한 금액으로 환산하지 않는다.
- 점검 도구 13개 시험과 독립 결함 재검증, worker 13개 시험, 스킬 3개 메타데이터 검사를 통과했다. 점검 도구의 출처 변경 차감·Off 소급 집계 오류는 수정 후 별도로 재현 검사를 통과했다. 검사 전용 PyYAML은 프로젝트 .local에만 설치했다. OS 임시폴더 권한 문제는 수정하지 않았고 시험 폴더를 명시적으로 프로젝트 내부에 정했다.

### 다음 작업과 유지 조건

1. 작업환경 준비 결과를 바탕으로 사용자가 정한 프로토타입을 실행하면서 process_debug On을 적용한다. 먼저 Task·명세·담당·입력 범위를 고정한다.
2. 제작→독립 QA→Hermes 기록 초안→마스터 판정의 전체 전달·실패·인계·재개와 점검 보고의 유용성을 실제 검증한다. 개별 도구 시험 통과로 전체 자동화 완주를 대신하지 않는다.
3. 기존 가이드 정식 제작과 HTML·실행계획·simple-user-guide의 Claude 전송 보류는 유지한다. 신규 프로젝트 실사용 및 새 AI 시작·대화 복원 시험은 사용자가 필요할 때 수행한다.
4. 정확한 현재 컨텍스트는 공개되는 상태 화면/이벤트가 있을 때만 보고한다. 접근 불가한 담당 세션은 미측정으로 남긴다. 개인 스킬 목록 등록·전역 자동 수집 완료로 표시하지 않는다.

이번 작업에서 commit·push·다른 프로젝트 수정은 수행하지 않았다. 저장소에 함께 나타난 다른 프로젝트 변경과 삭제 항목은 이 작업에 포함하거나 되돌리지 않았다.
