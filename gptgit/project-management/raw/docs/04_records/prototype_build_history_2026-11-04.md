## 2026-11-04 — 프로토타입 0.1 문서·구조 구성

### 요청과 결정

사용자는 개선된 프로세스를 새 `gptgit/project-prototype`에 구성하고 앞으로 이곳을 수정 원본으로 사용하도록 요청했다. 기존 관리 프로젝트를 복사하지 않고 규칙·프로세스·도구를 분류한다. 기획 작성↔Claude 검토와 개발↔독립 QA 루프를 함께 구축 대상으로 한다. 일상적인 Task 진행·판정·기록은 사용자 승인 명세 안에서 마스터가 맡는다.

### 이 절 작성 시 확인된 작업

- 문서 담당 `process_design`이 README, AGENTS, 구축 작업명세서, 프로세스, 컨텍스트·서브에이전트 기준과 wiki 진입점을 작성했다.
- 최종 배치 전 임시 staging에서 작성했으며 기존 `project-management` 문서·인증·가이드 자료·실행 이력은 수정하거나 복사하지 않았다.
- 담당은 전체 부모 대화가 제공된 Codex 서브에이전트였다. 향후 운영 목표인 최소 Task 입력 방식의 실증으로 계산하지 않는다.
- 이 문서 작성만으로 Claude 검토·독립 QA·Hermes 문서화 또는 전체 프로토타입 실행 성공을 주장하지 않는다.

### 통합 검증과 남은 작업

최종 배치·파일 목록·도구 검증·독립 검토 결과는 마스터가 실제 수행 후 이 절에 추가한다. 현재 문서 작성 단계의 미검증은 실제 herdr 제어, Claude 시작 설정 적용, 전달·회수·재시도 경계, 구독 확인, 기획 및 개발 QA 전체 루프다.

다음 담당은 README→작업명세서→프로세스의 해당 단계→관련 도구 근거 순서로 필요한 범위만 읽는다. 이전 프로젝트의 최소 함수 시험을 이 프로젝트의 실연결 증거로 승계하지 않는다. commit·push는 이번 개설 요청에 포함되지 않는다.

### 마스터 통합 결과 — 배치 전

- 신규 tools/start_role.ps1은 역할별 CLI와 구독 검사를 연결하고 Codex auto_review·QA read-only, Claude auto·기획 검토 읽기 도구 제한을 구성했다. CheckOnly는 명령 구성만 검사한다.
- tools/dispatch_task.py는 마스터의 새 herdr pane 생성·시작기 전달과 Task별 선점 영수증을 구현했다. 결과 자동 수집·Hermes adapter는 미구현이며 상태 도구는 모델을 호출하지 않는다.
- 독립 Codex 검토가 실행 기록 경로 분열, 역할/provider 미대조, QA 시험용 쓰기 경계 문제를 발견했다. 담당자가 docs/workflows 통일·제공자 검사·test_write_scope 분리로 수정했다.
- workflow 원장 이관본 24개 단위시험 통과. packet 최종 14개 중 13 통과·Windows symlink 생성 권한 부재 1 제외. 실제 junction 검증은 미수행이다. 최초 제한 셸에서 Python을 찾지 못했으나 권한 승인 후 설치된 Python 3.14로 시험했다.
- 현재 마스터는 herdr w8:p1, cwd=project-management임을 읽기 전용 조회로 확인했다. 일반 권한 조회는 서버에 거부됐고 승인된 권한으로 조회했다. 새 프로젝트에서의 실제 역할 실행은 아직 하지 않았다. 기존 서버·창 변경 없음.
- 이번 작업의 담당 세션은 Codex 내장 서브에이전트 /root/process_design, /root/tool_audit, /root/packet_tools이며 새 herdr Claude/Hermes 실행이 아니다. 전체 사용량은 미측정이다.
