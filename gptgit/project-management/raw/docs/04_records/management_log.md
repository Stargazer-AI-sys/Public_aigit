# 프로젝트 관리 — 최신 작업 인계

> 갱신: 2026-11-04 | 개선 작업은 이 프로젝트에서 계속한다.

## 확정된 역할

- **project-management:** 프로세스 개선의 논의·설계·구현 조정·검증·작업기록 원본.
- **project-prototype:** 개선된 프로세스를 독립적으로 적용하는 시험 프로젝트. 관리 작업의 이력·보류·세션·설치 경로·인계 자료를 넣지 않는다.
- 2026-11-04 최신 사용자 결정: 아래 남은 작업은 project-prototype에서 실행한다. 실행 중 확인된 문제는 이 관리 프로젝트로 가져와 개선한다. 자체 실행 근거는 프로토타입에, 문제 분석·개선 결정은 여기에 기록하며 상세 기록을 서로 복제하지 않는다.
- 사용자는 작업명세와 실행 범위를 승인하고, 그 범위의 Task 분담·검토·진행·기록은 마스터가 판단한다. 기획 작성↔Claude 검토와 개발↔독립 QA를 모두 적용한다.
- 담당은 최소 Task 입력·관련 소스·필수 규칙만 받고 마스터가 실행·전달·회수한다. 사용자에게 담당 창 복사·조작을 맡기지 않는다.

## 완료와 정정

- 프로토타입 기반 문서·양식·상태 원장·packet 검사·역할 시작기·herdr 전달 도구를 구성했다. 최초 시험은 원장 24＋packet 13＋dispatcher 8개 통과, symlink 권한 부재 1개 제외였다.
- 프로세스 개선 위치를 프로토타입으로 옮긴다고 기록한 것은 잘못이었다. 사용자 정정에 따라 이곳을 개선 원본으로 유지한다.
- 프로토타입의 구축 이력·관리 인계·도구 이관 감사·관리 폴더 런타임 참조를 제거했다. 필요한 지침은 독립적인 적용 조건·실행 설계·도구 목록·환경 지침으로 재작성했다.
- 프로토타입 work_log에는 자체 작업 입출력 규칙과 실행 미등록 상태만 남겼다. 관리 프로젝트 작업을 프로토타입의 자체 작업으로 기록하지 않는다.
- 현재 실행 환경과 CLI 권한은 실제 연결 시 확인해야 한다. 설정 문서 작성이나 CheckOnly를 실제 인증·모델 실행 성공으로 계산하지 않는다.

## 남은 작업 — 프로토타입에서 실행

1. 독립 실행 환경 구성: 프로젝트 전용 또는 시스템 공용 CLI 사용. runtime.local은 제거했고 example만 있으므로 실제 설치·구독 경로부터 확인한다.
2. 마스터의 담당 제어 검증: 시작기→Claude 실행→Task 전달→응답 회수. 사용자 창 조작 없이 수행한다.
3. 기획 작성↔검토 루프 검증: Codex 기획·통합→Claude 검토→수정·재검토→마스터 승인.
4. 서브에이전트 운영 보완: 병렬 Task·파일 소유권·실제 세션 추적 및 중복 시작·충돌 방지.
5. 결과 자동 회수·세션 재사용 구현: 현재 미구현인 회수·재사용 판단을 연결하고 불명확 상태를 확인한다.
6. 개발↔독립 QA 루프 검증: 별도 세션에서 실제 시험·결함 반환·수정·재시험.
7. Hermes 문서화 연결 구현: 구독 확인·최소 입력·초안 회수·중복 방지·마스터 근거 대조.
8. 전체 프로세스 완주 시험: 작은 신규 자체 명세 하나로 요구사항부터 문서화까지 단계별 근거 확보.

현재 요청은 기록 갱신이다. 위 실행은 이번 응답에서 착수하지 않는다. 문제를 이곳으로 가져올 때 해당 Task·버전·예상/실제·오류·최소 재현·근거 위치만 전달하고 전체 대화·작업기록을 복사하지 않는다.

## 이번 사용량 관찰과 개선점

- Task별 정확한 토큰·구독 차감량은 미측정이므로 최대 사용 구간이나 비율을 확정하지 않는다.
- 부담 요인으로 추정되는 부분: 긴 부모 대화를 상속한 3개 서브에이전트, 대량 문서·CLI 도움말·공식 문서 출력, 프로젝트 역할을 잘못 해석해 발생한 문서·기록 재작성. 승인 검토의 별도 사용량은 미측정이다.
- 다음 분담은 필요한 Task 입력만 전달하는 새 맥락을 사용하고, 조회는 필요한 절·옵션만 출력한다. 단순 조회·기록 수정은 담당을 불필요하게 늘리지 않는다. Python 모의 시험 실행 횟수를 LLM 토큰 소비와 동일시하지 않는다.
