# 사용자 가이드 실행계획

기준: [요구명세](../00-request/request.json) v1.0. 기획 담당: 이 채팅의 GPT 마스터.

## 대표 결과

흰 배경의 한 페이지 가이드에 준비 → 요청 → 진행 확인 → 재개 네 단계를 표시한다.
요청 예시: “문서 정리 가이드를 만들어줘. 대상은 나 혼자이고, 처음 한 번 준비와 매번 할 일을 구분해줘.
대표 한 페이지를 먼저 보여주고, 확인 뒤 제작·검토·시험 결과를 보고해줘.”
사용자는 JSON을 작성하지 않는다. 기술 입력은 마스터가 tools/workflow.py로 관리한다.

## Phase 1: 읽고 따라 할 가이드

| Task | Step | 완료 조건 |
| --- | --- | --- |
| 요청 안내 | 대상·목적·범위 예시와 대표 결과 검토 문구 작성 | R1 |
| 진행·근거 안내 | 상태·필수 결함·증거·남은 제한 구분 | R2 |
| 재개 안내 | 실행 ID 지정, 마지막 완료 단계와 미완료 Task 대조, 무작정 반복 금지 | R3 |
| 환경 안내 | herdr·Codex·Claude 준비와 미연결 기능을 구분 | R4 |

제작 담당은 Claude, 검토 담당은 GPT, 독립 QA는 별도 GPT 세션이다. 역할과 실제 수행 여부를 구분한다.
simple-user-guide 공유 원본과 기본 HTML 틀을 사용한다. 최종 파일은 guide_docs/AI_작업_요청과_재개_가이드.html.
현재 같은 경로의 파일은 Claude가 먼저 작성한 대표 화면 검토용 초안이다. 원장 밖에서 작성되었으며 정식 QA 대상·완료 산출물이 아니다.
사용자가 대표 화면을 확인한 뒤 이 파일을 02-development의 입력으로 개정한다. 변경 전 초안의 해시와 스냅샷을 보존하고 정식 제출 시 결과물 해시를 고정한다.
목차·상대 링크·명령의 경로를 검사하고 가능한 도구로 화면을 확인한다.
실제 herdr 사용자 창구 완주와 Docker/Hermes 연결이 되지 않으면 R4를 통과해도 전체 환경 통합 완료로 보고하지 않는다.

## 예외와 검증

로그인 실패·도구 미설치·사용량 제한은 차단 사유다. API 키로 우회하지 않는다.
사용자 명령은 실제 설치한 PowerShell 7, Python 및 시작 스크립트 기준으로 작성한다.
가이드의 구조 검사와 실제 사용자 동선 수행 검증을 분리한다. 사용자는 2026-10-27 현재 구성과 글자 크기로 정식 제작 진행을 승인했다. 승인 기준 버전·스냅샷·제시 화면은 [대표 화면 승인](../00-request/screen-approval.md)에 연결한다. 초안 해시와 스냅샷은 이미 기획 1차 제출에 보존되어 있으며 마스터가 화면 제시 전 동일성을 확인했다. 정식 제작은 이 승인된 초안을 입력으로 한다.

정식 제작에서도 현재 환경 제한을 보존한다. WSL의 docker-desktop은 버전 2로 생성됐지만 마지막 확인 시 정지 상태였고 컨테이너 시험은 엔진 연결 실패로 미실행이다. herdr 시작기의 첫 화면까지만 확인했으며 내부 마스터와 Claude 전달·회수는 미검증이다. Hermes는 비용 조건 미확인으로 미설치·미연결이다. 가이드가 시작을 안내하는 두 번째 명령은 검증 예정 절차임을 분명히 표시한다. 사용자 승인·문서 제작·전체 환경 통합 완료를 구분한다.
