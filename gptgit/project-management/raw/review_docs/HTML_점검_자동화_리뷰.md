# HTML 점검 자동화 리뷰

2026-10-15 · 개인 열람용 작업 리뷰 · AI 작업 기준

HTML 가이드 작성·수정 후 AI가 해당 파일을 로컬에서 1회 구조 점검하는 절차를 정의하고 실제 적용했다. 상세 절차는 공통 스킬에서 관리하고 각 프로젝트 AGENTS에는 사용 조건만 연결했다.

가장 큰 이점은 AI가 작성 결과를 자체 판단만으로 완료 처리하지 않고, 반복 가능한 검사 결과를 근거로 마무리하게 된 것이다.

- **작업 완결성:** 작성 → 구조 점검 → 결과 보고까지 AI가 이어서 수행했다.
- **검증 일관성:** 링크·목차·중복 ID를 같은 규칙으로 확인하므로 매번 검사 방법을 새로 구성할 필요가 줄었다.
- **완료 근거:** 검사 대상·횟수·결과·제외 범위를 구체적으로 보고할 수 있게 됐다.
- **사용자 개입 감소:** 새 가이드 제작에서는 사용자에게 별도 검사 실행을 요청하지 않고 AI가 마무리했다.
- **유지관리:** 공통 절차를 한 곳에서 관리해 프로젝트별 중복 수정 부담을 줄였다.

실제 새 가이드 한 파일에 검사기를 1회 실행해 상대 링크 4곳·목차 연결 3곳·ID 3개를 확인했다. 결과는 `CHECKED_ITEMS_OK`, 종료 코드 `0`이었으며 검사 전후 파일 내용도 같았다.

초기에는 PowerShell 버전·실행 정책·상대경로 문제로 사용자 개입이 필요했다. AI 환경에서 통과한 명령이 사용자 터미널에서도 그대로 동작한다고 가정하면 안 된다는 점을 확인하고, 실행기와 대상의 절대경로를 확인하는 절차로 보완했다.

이번 가이드에서는 오류가 발견되지 않아 실제 작성 오류와 재작업을 줄인 효과까지 입증한 것은 아니다. 오류 감지는 앞선 12개 테스트로 확인했으며, 시간·토큰 절감량은 측정하지 않았다. 구조 점검은 내용 정확성·화면 품질 검토를 대신하지 않는다.

현재 평가는 **작은 비용으로 AI의 완료 품질과 작업 일관성을 높인 보조 자동화**다. 이후에는 추가 지시 없이 점검까지 마치는지, 오류 수정 후 필요한 파일만 재검사하는지, 검사 범위를 과장하지 않는지를 실제 작업에서 살펴보면 된다.
