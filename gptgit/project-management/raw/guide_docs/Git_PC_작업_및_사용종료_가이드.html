Git 간단 사용 가이드

새 PC 준비 → 작업 전 pull → 작업 후 commit·push → PC 사용 종료

Windows PowerShell · GitHub HTTPS · main 브랜치 기준입니다. 명령은 한 줄씩 실행하세요. 오류나 충돌이 나오면 멈추고 메시지를 확인합니다. AI는 별도 요청 없이 commit·push하지 않습니다.

1. 새 PC 준비2. 작업 시작3. 저장·전송4. 사용 종료

1. 새 PC 준비 — 처음 한 번

  1. Git for Windows를 설치하고 PowerShell을 새로 엽니다.
  2. GitHub의 Aigit 저장소에서 Code → HTTPS 주소를 복사합니다.
  3. 아래의 복사한HTTPS주소를 실제 주소로 바꿔 실행합니다. 로그인 창이 나오면 본인 GitHub 계정으로 인증합니다.
cd $env:USERPROFILE
git clone 복사한HTTPS주소 Aigit
cd Aigit

이 예제는 사용자 폴더 아래에 Aigit을 만듭니다. 이미 clone한 PC는 이 단계를 건너뜁니다.

작성자 이름과 이메일도 실제 값으로 바꿔 설정합니다.

git config --local user.name "작성자 이름"
git config --local user.email "GitHub에 등록한 이메일"

--local: 이 저장소에만 적용합니다. 이름·이메일은 commit 작성자 정보이며 로그인 정보가 아닙니다.

2. 작업 시작 — 매번

PowerShell에서 Aigit 폴더로 이동합니다. 다른 위치에 clone했다면 첫 줄을 실제 경로로 바꿉니다.

cd "$env:USERPROFILE\Aigit"
git status --short --branch
git pull --ff-only origin main

status에서 main 브랜치인지, 남은 변경 파일이 없는지 확인한 후 pull합니다. 변경이 있거나 다른 브랜치라면 먼저 확인합니다.

  • --short --branch: 변경 파일과 현재 브랜치를 간단히 표시합니다.
  • --ff-only: 이력이 갈라지면 자동 병합하지 않고 중단합니다.
  • origin main: 원격 저장소 origin의 main 브랜치입니다. 실제 브랜치가 다르면 이름을 바꿉니다.

이제 gptgit 아래 원하는 프로젝트에서 작업합니다. 아래 Git 명령은 계속 Aigit 폴더에서 실행합니다.

3. 작업 후 저장·전송

① 변경 파일 확인 → ② 필요한 파일 선택 → ③ 내용 확인 → ④ commit → ⑤ push

git status --short
git add -- "gptgit/project-management/README.md"
git diff --cached
git commit -m "문서 수정"
git push origin main
git status --short --branch

add의 경로와 commit 메시지는 실제 작업에 맞게 바꿉니다. 파일이 여러 개면 필요한 파일마다 add합니다. diff 내용을 확인한 뒤 commit하고, commit 성공 후 push합니다.

  • add -- "파일경로": 다음 commit에 넣을 파일을 선택합니다. -- 뒤는 파일 경로입니다.
  • diff --cached: 선택된 변경 전체를 보여줍니다. 확인 후 q로 나옵니다.
  • commit -m "설명": 로컬에 변경 이력을 기록합니다. -m은 설명 메시지입니다.
  • push origin main: 로컬 commit을 원격 main에 전송합니다.

완료 확인: push가 성공하고 마지막 status에 변경 파일과 ahead 표시가 없는지 확인합니다. GitHub에서도 새 commit이 보이면 다른 PC에서 pull하여 이어갈 수 있습니다.

Aigit에는 다른 프로젝트도 있습니다. 필요한 파일만 add하고, 비밀번호·API 키가 포함되지 않았는지 확인하세요. push는 이전에 전송하지 않은 commit도 함께 보냅니다. 거부·충돌 메시지가 나오면 강제 push하지 말고 해당 메시지로 도움을 요청하세요.

4. 이 PC에서 더 이상 작업하지 않을 때

잠시 작업을 마치는 개인 PC는 push 완료 확인까지만 하면 됩니다. PC를 반납하거나 다른 사람에게 넘길 때는 다음 순서로 정리합니다.

  1. 필요한 작업 보존: push 성공과 GitHub 반영을 확인합니다. 아직 commit하지 않은 파일·별도로 보관한 파일도 필요한 것이 없는지 확인합니다.
  2. Git 저장 인증 삭제: Windows 시작 메뉴에서 자격 증명 관리자 → Windows 자격 증명을 엽니다. GitHub/Git 관련 항목의 계정을 확인하고 본인 항목만 제거합니다.
  3. 별도 로그인 종료: 브라우저의 GitHub에서 로그아웃합니다. GitHub Desktop 등 로그인한 앱이 있다면 해당 앱에서도 로그아웃합니다.
  4. 로컬 초기화가 필요하면: 작업 앱을 닫고 파일 탐색기에서 실제 Aigit 폴더를 확인하여 삭제합니다. 나중에 다시 쓸 때는 새로 clone하면 됩니다.

Aigit 전체 삭제는 Claudecode 등 다른 프로젝트와 로컬 이력도 지웁니다. 미전송 작업·보관 자료를 먼저 확인하세요. 원격 GitHub 저장소는 삭제되지 않습니다. git reset은 로그아웃 명령이 아니며 이 절차에서는 필요하지 않습니다.

이 문서는 HTTPS 사용 기준입니다. SSH 키나 GitHub CLI로 별도 인증한 PC는 해당 인증도 따로 해제해야 합니다.
