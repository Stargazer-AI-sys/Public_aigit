HTML 가이드 구조 점검

가이드 완성 → 해당 파일만 로컬 1회 점검 → 결과 확인

AI는 가이드를 작성·수정한 뒤 관리 워크플로 5.2절과 simple-user-guide의 「로컬 1회 구조 점검」에 따라 해당 HTML만 검사합니다. 정상 통과했다면 사용자가 다시 실행할 필요는 없습니다.

1. 언제 무엇을 검사하나2. 직접 실행하는 방법3. 결과 확인

1. 언제 무엇을 검사하나

가이드 작성·수정을 마친 뒤 최종 HTML을 한 번 검사합니다. 발견한 오류를 수정했다면 영향받는 파일만 다시 검사합니다.

  • 상대 링크로 연결한 파일·폴더가 존재하는지 확인합니다.
  • 같은 HTML의 목차가 실제 ID에 연결되는지, ID가 중복됐는지 확인합니다.
  • 검사기는 원본을 읽기만 합니다. 예약 실행·자동 수정·Git 작업·가이드 속 명령 실행은 하지 않습니다.

확인: AI의 완료 보고에 검사한 파일, 실제 결과, 검사하지 않은 범위가 구분되어 있어야 합니다. 내용 정확성과 화면 가독성 검토는 별도입니다.

2. 직접 실행하는 방법 — 필요할 때만

PowerShell 7이 필요합니다. Windows 기본 PowerShell 5.1 창에서도 아래처럼 PowerShell 7 실행기를 직접 지정할 수 있습니다. 현재 폴더에 의존하지 않도록 절대경로를 사용합니다.

아래는 현재 Stargazer PC에서 이 가이드 자체를 점검하는 예시입니다. 다른 PC에서는 관리 프로젝트와 사용 가능한 PowerShell 7의 실제 위치를 먼저 확인해 바꿉니다. Codex 번들 경로는 앱 환경에 따라 달라질 수 있습니다.

$managementRoot = "C:\Users\Stargazer\OneDrive\Desktop\aigit\gptgit\project-management"
$powerShell7 = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe"
$checkerPath = Join-Path $managementRoot "tools\check_project_docs.ps1"
$targetProjectRoot = $managementRoot
$guidePath = Join-Path $targetProjectRoot "guide_docs\HTML_가이드_구조점검_사용_가이드.html"
& $powerShell7 -NoProfile -File $checkerPath -ProjectRoot $targetProjectRoot -Files $guidePath
$LASTEXITCODE

다른 가이드는 아래 대상 프로젝트와 HTML 경로만 바꿔 지정합니다.

변수·옵션역할
$managementRoot점검 도구가 있는 관리 프로젝트의 절대경로
$targetProjectRoot / $guidePath점검할 프로젝트와 HTML의 절대경로. 다른 프로젝트를 검사할 때 이 두 값을 바꿉니다.
-NoProfile / -File개인 시작 설정을 불러오지 않고 지정한 스크립트를 실행합니다.
-ProjectRoot / -Files검사 대상 프로젝트와 파일을 지정합니다.

확인: JSON 결과 뒤의 숫자가 0인지 확인합니다. 파일 경로·버전·실행 정책 문제로 시작하지 못했다면 검사가 완료된 것이 아닙니다.

3. 결과 확인

결과확인·조치
CHECKED_ITEMS_OK / 종료 코드 0검사한 범위에서 문제 없음. skipped_checks의 제외 항목도 확인합니다.
ISSUES_FOUND / 종료 코드 1findings의 파일·줄·대상을 확인합니다. 링크나 ID를 요청 범위에서 수정한 뒤 해당 파일만 다시 검사합니다.
CHECK_ERROR / 종료 코드 2실행 조건 오류입니다. 메시지와 프로젝트 경로를 확인합니다.

대표 오류는 broken_relative_link(연결 파일 없음), missing_html_id(같은 문서의 연결 대상 ID 없음), duplicate_html_id(중복 ID)입니다.

외부 사이트 연결, 다른 문서 내부의 ID, 동적으로 생성된 링크, 내용 정확성·화면 품질은 검사하지 않습니다. CHECKED_ITEMS_OK를 이 항목들의 검증 완료로 해석하지 않습니다.

실행 자체가 차단되면 PowerShell 7 실행기와 절대경로를 먼저 확인합니다. 실행 정책을 자동 변경하거나 우회하지 않습니다. 이 도구가 없는 환경에서는 미점검 사유를 남깁니다.

확인: 오류가 해결된 결과와 검사 제외 범위를 함께 보고하면 구조 점검을 마칩니다.
