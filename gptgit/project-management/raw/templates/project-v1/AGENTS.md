# 프로젝트 작업 규칙

- 이 프로젝트의 README와 docs/project.md, 최신 작업기록을 먼저 확인한다. 적용되는 상위 규칙도 확인하되 다른 프로젝트의 상태·보류·권한을 자동 상속하지 않는다.
- 사용자의 목적과 요청 범위가 기준이다. 사용자가 지정하지 않은 핵심 범위·비용·공개·파괴적 변경은 임의 확정하지 않는다.
- 요구사항·대표 결과 확인 → 기획·검토 → 제작·자체 시험 → 독립 QA → 문서화·완료 판정 순서로 진행한다. 소규모 작업은 문서를 합치고 불필요한 단계·빈 폴더를 만들지 않는다.
- 마스터는 사용자 창구와 작업 배분을 담당한다. 제작·검토 담당의 대상 파일·입력·완료 조건을 구분한다. 별도 에이전트는 사용자 또는 적용 지침이 허용할 때만 생성한다.
- 검토자는 원본을 읽기 전용으로 확인한다. 제작자의 자체 시험과 독립 검토를 구분하며 자신의 결과를 최종 승인하지 않는다. 같은 파일을 동시에 수정하지 않는다.
- 소스·기록·결과는 이 프로젝트에 유지한다. 관리 프로젝트의 시험 기록·로그인 정보·대화 ID·미완료 목록을 복사하지 않는다.
- 파일 변경은 사용자 요청 범위에서 수행한다. 논의만으로 문서를 자동 저장하지 않는다. 기록 요청에는 완료 근거·미검증·보류·다음 행동을 남긴다.
- 완료한 시험은 변경·실패·환경 차이가 필요한 경우에만 반복한다. 직접 확인·사용자 보고·추정·미검증을 구분한다.
- ChatGPT Plus·Claude Pro 구독 범위를 유지하며 유료 API로 자동 전환하지 않는다. 한도·인증 실패 시 대기한다.
- commit·push·재시작은 각각 명시적인 실행 요청 없이 하지 않는다. 비밀번호·API 키·인증정보를 문서에 저장하지 않는다.
