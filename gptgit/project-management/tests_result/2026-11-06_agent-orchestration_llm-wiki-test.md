# LLM wiki 다중 pane 작성 테스트

- 날짜: 2026-11-06, 한국 시간.
- 프로세스: agent-orchestration — 담당 기획·작성·검토를 전달하고 결과를 회수·통합하는 과정.
- 상태: 완료 — 6담당 전달·회수, 샘플 작성, 형식 검사, 독립 내용 검토와 마스터 통합 판정 완료.
- 범위: project-management 안의 작은 샘플 작성. 실제 자동화 전체 프로세스나 다른 프로젝트의 개발 시험은 아니다.

## 사용자 조건과 시험 방법

| 조건 | 방법·관측 결과 |

| LLM wiki 작성·갱신 | 기획·출처·본문·운영·검토 기준을 병렬로 생성한 뒤 마스터가 샘플 0.1을 작성. 형식 담당과 독립 내용 담당에게 샘플을 재전달. |
| 결과 파일 저장 | tests_result에 날짜_영문프로세스_영문제목.md로 샘플·결과·증거·검토 결과를 분리. |

## 실제 담당과 결과

| 담당 | pane | 작업·회수 결과 |
| --- | --- | --- |
| 마스터 | w6:p1 | 배치, 담당 시작, 작업 전달, 원문 대조, 샘플 작성, 검사 및 최종 통합 |

| wiki-draft | w6:p4 | 원문 보관과 설명의 차이, 내용 합성에 관한 2단락 초안 |

| wiki-review | w6:p7 | 독립 검토 기준 4개, 샘플과 세 출처의 내용 대조 |

6개 담당의 터미널 상태 표시에서 GPT-6-Astra medium과 Codex v0.166.0을 확인했다. 모델을 별도로 지정하지 않고 현재 기본 설정으로 시작했다. 같은 모델의 별도 세션 검토이며 다른 제공자 교차 검증은 아니다. 내장 서브에이전트는 사용하지 않았다.

담당은 원칙적으로 읽기 전용이며 최종 파일 쓰기는 마스터가 맡았다. 예외로 wiki-review에게 자기 검토 결과 파일 하나만 쓰도록 허용했다. 작은 pane의 응답 앞부분이 recent-unwrapped 180줄로도 회수되지 않아 적용한 herdr fallback이다. 샘플 원본의 수정 권한을 검토자에게 주지 않았다.

## 검증과 발견한 문제

- 형식 담당: 기존 .local/wiki-editor-venv/Scripts/python.exe 부재로 첫 명령 실패(exit 1), 검사기 미진입. 마스터도 같은 실행기 부재를 직접 확인했다. 샘플 결함으로 계산하지 않는다.
- 시스템 Python 3.14.8 및 PyYAML 6.0.3 존재를 마스터가 확인했다. 스킬이 허용한 기존 시스템 Python을 사용했으며 설치·환경 변경·절대경로 우회는 하지 않았다.
- 형식 담당의 실제 지정 검사: 파일 1개, 오류 0, exit 0. 마스터도 동일 명령으로 파일 1개·오류 0·exit 0을 확인했다. 정상 실행은 총 2회이며, 앞선 실행기 부재 시도와 구분한다.
- 검사 명령: 프로젝트 루트에서 아래 실행.

```powershell
python -X utf8 skills/wiki-editor/scripts/check_wiki.py tests_result/2026-11-06_wiki-authoring_llm-wiki-sample.md
```

- 일부 담당의 최초 읽기 도구는 프로세스 시작 실패 또는 문자 인코딩 문제가 있었고, 이후 읽기 수단·UTF-8 출력으로 지정 원문을 회수했다. 승인 거부를 우회한 것으로 기록하지 않으며 정확한 내부 실패 원인은 미확인이다.
- 작업 중 긴 터미널 조회는 agent_not_idle로 거절됐다. 프롬프트를 중복 전송하지 않고 visible 조회 또는 완료 후 조회를 사용했다.
- pane 너비가 처음에는 오른쪽 29~30칸으로 작아 마스터가 분할 비율을 조정했다. 최종 폭은 59/57/57칸, 높이는 15~24행이며 긴 응답은 별도 회수가 필요했다.

## 완료 판정과 한계

마스터 판정: 이번 소규모 테스트는 통과다. 6개 담당의 실제 응답과 별도 세션, 샘플 파일, 오류 0건의 실제 형식 검사, 독립 내용 검토 파일을 대조했다. 사용자가 볼 수 있도록 같은 탭에 7개 pane이 열린 비확대 배치를 유지했다. 독립 검토의 네 관점에서 미해결 필수 결함은 보고되지 않았다. 형식 검사와 내용 대조, 마스터 통합 판정은 서로 다른 근거로 관리한다.

기록 갱신: 0.1에서 담당 초안 통합·형식 검사 결과와 검토 회수 대기를 기록했고, 0.2에서 실제 독립 검토 파일을 회수하여 링크·완료 판정으로 갱신했다. 위키 샘플 내용은 0.1 그대로이며 검토 결과를 이유로 자동 게시하지 않았다.

외부 URL 접근·앵커·참조형/복잡한 링크·Mermaid 렌더링·도식 정확성·고아 문서·상충·사실·최신성은 형식 검사기가 판정하지 않는다. 내용 대조는 지정된 로컬 원문 세 개의 범위다. 샘플은 draft이며 실제 서비스 게시·전체 자동화 완주·성능/부하·비용 측정·사용자의 실제 시청 여부는 확인하지 않았다.

사용자 모니터링을 위해 생성한 6개 담당 pane은 닫지 않는다. 기존 wiki·raw·규칙·다른 프로젝트를 수정하지 않으며 commit·push는 수행하지 않는다.
