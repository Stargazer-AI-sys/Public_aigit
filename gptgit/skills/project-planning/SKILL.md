# 초기 프로젝트 기획

> 스킬 버전: 0.3 | 최종 수정: 2026-10-28

사용자가 목적·가치·중요한 조건을 정하고 AI가 상세 기획을 맡는 방식으로 진행한다.

- 이 스킬을 보관한 관리 프로젝트와 실제 기획 대상 프로젝트를 구분한다. 대상 프로젝트의 규칙·기존 요구사항·산출물 위치를 따르며 관리 프로젝트의 폴더 구조나 역할을 강제로 적용하지 않는다. 기존 요구사항 문서를 입력으로 활용하고 별도 요청 없이 공통 양식으로 교체하지 않는다.

- 아이디어나 작성된 요구사항을 입력으로 받는다. 기존 프로젝트는 README·AGENTS와 관련 최신 요구사항·인계를 먼저 확인하고 필요한 자료만 읽는다. 정해진 사항을 다시 질문하지 않는다.
- 사용자의 말에서 목적·사용자·가치·핵심 기능·부가 기능·제외 범위·제약·성공 기준을 구분한다. 모든 빈칸을 채우라고 요구하지 않는다.
- 대표 사용 장면과 읽기 쉬운 결과 예시를 먼저 구성하고, 상세 기능·화면·데이터 구조·기술·검증 방법을 추천한다. 명명·자료형·분류 같은 세부 선택은 기존 방식과 단순한 안을 기준으로 판단한다.
- 확정 요구사항과 AI 제안·가정을 구분한다. 중요하지만 아직 모르는 값은 미정으로 두고, 쉽게 바꿀 수 있는 선택은 가정을 표시해 진행한다.
- 목적·핵심 범위·필수 조건 변경, 비용, 손실·외부 공개, 되돌리기 어려운 결정만 필요한 시점에 묶어서 질문한다. 추천안과 사용자 관점의 영향을 제시한다. 기술적 사실 확인을 사용자에게 떠넘기지 않는다.
- 기존 구조와 실제 대표 자료로 표현 가능한지 먼저 확인한다. 보조 기능·예상 확장 때문에 첫 버전을 불필요하게 키우거나 기존 스키마를 전면 교체하지 않는다.
- 결과에는 목적·첫 버전 범위, 대표 흐름·결과, 핵심/부가/제외 기능, 추천 구현 방향·진행 순서, 완료 확인 방법, 중요한 가정·필수 질문을 필요한 만큼 담는다.
- 기본 산출물은 채팅 제안이다. 파일 저장은 명시적 요청 범위에서만 하며 이 스킬 호출을 구현·유료 호출·외부 반영·Git 실행 허가로 해석하지 않는다. 별도 에이전트는 사용자의 요청 또는 적용 지침이 허용할 때만 사용한다.

## 승인된 작업의 세션 계획

- 에이전트 분담이 승인된 자동화 기획은 요구사항을 검토 가능한 Task로 나눌 때 담당 역할·새 세션 경계·필요 원본 범위·입출력·완료/검토/인계 조건도 정한다. 과도하게 작은 단계마다 세션을 만들지 않고 같은 Task의 수정은 재사용할 수 있다.
- 부모 대화 전체 대신 확정 결정·제약·원본 절과 버전·쓰기 범위·보류·Task ID를 전달한다. 독립 조사만 병렬화하며 선행 결과에 의존하는 단계는 순차 실행한다. 같은 파일 수정은 담당과 순서를 분리한다.
- 예상외 작업량 확대 시 기존 승인 범위의 기록·인계 후 새 세션으로 넘길 기준을 계획에 포함한다. 주요 범위·비용 변경만 별도 결정으로 남긴다. 이미 확정된 역할·설계를 미구현이라는 이유로 다시 기획하지 않는다.
