# 간단한 사용자 가이드 작성

> 스킬 버전: 0.4 | 최종 수정: 2026-10-16

## 기준

사용자가 승인한 `Git_PC_작업_및_사용종료_가이드.html` v0.2(2026-10-15)의 간결한 구성과 최소 디자인을 재사용한다. Git 전용 스킬은 아니다. 원본의 Git 명령·Aigit 경로·main 브랜치·로그아웃 단계를 다른 주제에 복사하지 않는다.

## 작성 방식

1. 대상 프로젝트 README·AGENTS와 요청에 직접 관련된 자료로 작업 범위, 환경, 저장 위치를 확인한다. 이미 확인한 자료는 재사용한다.
2. 사용자가 실제로 따라 할 정상 절차를 중심으로 쓴다. 처음 한 번 필요한 준비와 매번 하는 작업을 구분하되, 제목·단계 수는 작업에 맞춘다. Git 가이드의 네 단계를 강제하지 않는다.
3. 사용자가 형식을 지정하면 그 형식을 따른다. 별도 지정이 없으면 [assets/guide-template.html](assets/guide-template.html)을 사용한 독립 HTML로 작성한다. 기존 문서 수정은 기존 파일을 갱신하며 사본·상세판을 자동 생성하지 않는다.
4. 명령은 실행 순서대로 최소한만 넣고 실제 쓰는 옵션만 한 줄씩 설명한다. 실행할 터미널·장비·작업 폴더가 달라지면 그 위치에 짧게 표시한다. 명령만 한꺼번에 붙여 넣도록 유도하지 않는다.
5. 각 주요 단계 끝에 사용자가 확인할 출력·화면·결과를 짧게 적는다. 실제 값과 바꿔 넣을 예시 값을 구분한다. 주소·계정·경로는 추측하여 확정하지 않는다.
6. 명령·제품 동작에 최신 확인이 필요하면 공식 문서를 확인하고 관련 출처만 짧게 연결한다. 실제 실행하지 않은 절차를 검증 완료로 표시하지 않는다.

## 분량과 표현

- 한국어로 짧고 쉬운 문장을 쓴다. 제목, 짧은 설명, 필수 명령, 사용 옵션, 확인 방법이 중심이다.
- 정상 사용에 필요하지 않은 개념 설명·여러 대안·고급 옵션·상세 충돌 복구는 기본 가이드에서 제외한다. 사용자가 상세 내용을 요청한 경우에는 필요한 범위까지 설명한다.
- 오류·충돌로 절차를 계속할 수 없으면 멈추고 메시지를 확인하도록 짧게 안내한다. 주제별 실제 위험이 있으면 대상 범위·보존할 자료를 해당 단계 바로 앞에 적는다. 경고·면책 문구를 매 절마다 반복하지 않는다.
- 사용 종료·인증 해제·초기화는 요청 범위에 있을 때만 포함한다. 더 간단하고 명확하면 GUI 절차로 안내해도 된다. 인증 제거, 설정 제거, 자료 삭제의 차이는 필요한 만큼 구분한다.

## HTML 틀과 확인

- 흰 배경, 제한된 본문 폭, 회색 명령 상자, 단순 번호 목차와 반응형·인쇄 스타일을 유지한다. 장식 이미지·복잡한 카드·외부 라이브러리는 추가하지 않는다.
- 틀의 치환 표시는 실제 내용으로 모두 바꾼다. 목차와 section은 필요한 수만큼 늘리거나 줄인다. 명령의 `<`, `>`, `&` 등을 HTML로 이스케이프하되 복사한 명령이 원래 문법을 유지하도록 한다.
- 문서 링크·목차·명령의 줄바꿈·인용부호·작업 경로를 점검한다. HTML은 가능한 도구로 PC·좁은 화면의 가독성과 가로 넘침을 확인한다. 확인하지 못한 항목을 완료로 보고하지 않는다.
- 명령의 실행 성공을 시험하려고 사용자 계정·저장소·장비에 변경을 가하지 않는다. 문서 작성 권한과 실제 명령 실행 권한은 별개다. Git commit·push도 별도 명시적 요청 없이 하지 않는다.
- 요청 범위에 해당하는 참조·버전·이력만 함께 갱신한다. 완료 보고는 결과 파일 링크와 핵심 변경·검증 범위를 짧게 적는다.

## 로컬 1회 구조 점검

- 가이드를 작성·수정한 뒤 AI가 해당 HTML만 지정해 `check_project_docs.ps1`를 로컬에서 1회 실행한다. 링크·같은 문서의 목차 연결·중복 ID 검사이며, 내용 정확성·화면 가독성 검토는 별도로 유지한다. 오류를 요청 범위 안에서 수정했다면 영향받는 파일만 다시 검사한다.
- 점검기는 동일 gptgit 작업 공간의 `project-management/tools/check_project_docs.ps1` 또는 사용자가 지정한 위치에서 확인한다. 다른 프로젝트의 가이드는 해당 프로젝트 루트와 결과 HTML을 지정한다. PC 전체 탐색이나 점검기 복사본 자동 생성은 하지 않는다.
- PowerShell 7 실행기, 점검 스크립트, 대상 프로젝트 루트, 결과 HTML의 실제 절대경로를 확인해 사용한다. 현재 실행 중인 PowerShell 7 경로, 사용 가능한 pwsh, 확인된 Codex 번들 위치를 활용할 수 있다. 특정 PC의 사용자 이름·설치 위치를 고정하거나 Windows PowerShell 5.1에서 직접 .ps1을 실행하지 않는다.
- 확인한 경로를 아래 변수에 넣고 실행한다. 이 명령은 결과 파일을 읽기만 하며 가이드에 실린 설치·장비·유료 API 명령을 실행하는 것이 아니다.

```powershell
& $powerShell7 -NoProfile -File $checkerPath -ProjectRoot $targetProjectRoot -Files $guidePath
```

- 종료 코드와 JSON의 `findings`·`skipped_checks`를 확인하고 실제 검사한 범위만 완료로 보고한다. 도구·PowerShell 7·접근 권한이 없거나 실행이 차단되면 미점검 사유를 알린다. 자동 설치·실행 정책 변경·우회는 하지 않는다.
- 작성·수정 직후의 점검만 수행한다. 예약 실행·전체 프로젝트 반복 검사·자동 링크 수정·Git 실행은 추가하지 않는다.

## 구조 점검 완료 보고

- 완료 보고에 **적용한 스킬·워크플로, 검사 대상 HTML, 실제 실행 횟수와 종료 코드, 발견 문제·검사 제외 항목, 별도 미검증 범위**를 짧게 표시한다. 형식보다 실제 실행 결과에 근거하는 것이 우선이다.
- 횟수와 결과는 현재 작업의 실제 도구 호출·출력으로 확인한다. 검사기를 실행하지 않고 절차 준수나 통과를 선언하지 않는다. 미실행이면 그 사실과 사유를 명시한다. 실행기 오류로 검사에 진입하지 못한 시도는 완료된 구조 검사와 구분한다.
- 오류 수정 후 재검사했다면 횟수와 이유를 표시한다. 내용 변경·오류·새 근거 없이 이미 통과한 검사를 반복하지 않는다. 다른 도구의 화면·문법 검사를 구조 검사 횟수에 섞지 않는다.
- `findings`와 `skipped_checks`, 도구 자체의 검사 범위를 함께 확인한다. 문제 0개와 검사 제외 0개여도 화면·내용 정확성까지 확인한 것은 아니다. 새 보고서나 상시 기록 파일은 자동 생성하지 않고 채팅에 보고한다.
- 다른 프로젝트의 스킬·규칙 연결이나 기존 파일 검사 성공을, 그 프로젝트의 실제 제작 과정에서 이 절차를 따랐다는 증거로 취급하지 않는다.

## 공유 원본과 적용 상태

- 이 스킬은 Git 관리용 공유 원본이다. 기존 원본의 위치와 식별자를 유지하며 같은 역할의 사본을 새로 만들지 않는다.
- 가이드 작업 시 프로젝트가 이 공유 원본을 기준으로 지정했다면 개인 설치본보다 이 원본의 작성·로컬 1회 구조 점검·완료 보고 절차를 우선 적용한다. 개인 설치본과 다르면 차이를 알리고 자동 덮어쓰기는 하지 않는다.
- 이 스킬 자체를 수정할 때는 메타데이터·참조·포함 자원과 변경 기능을 검증하고 실제 결과·검사 제외·미검증을 보고한다. HTML 가이드를 작성하지 않았다면 가이드 구조 검사를 실행한 것으로 보고하지 않는다. 공유 원본 저장·개인 설치·채팅 등록·실제 적용을 구분한다.
