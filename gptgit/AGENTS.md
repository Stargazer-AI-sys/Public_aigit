# AGENTS.md — GPT 공통 작업 규칙

> 문서 버전: 0.4 | 최초 작성: 2026-10-15 · 최종 수정: 2026-11-06 (한국 시간)

## 적용 범위와 작업 시작

- 이 문서는 gptgit과 그 하위 GPT 프로젝트의 공통 AI 행동 규칙이다. 상위 Aigit 전체나 형제 Claudecode 폴더의 규칙으로 확대하지 않는다.
- 공통 운영 방법은 [README.md](README.md), 개별 프로젝트의 목적과 상세 규칙은 해당 README·AGENTS에서 확인한다.
- 개별 프로젝트를 작업할 때 이 문서와 대상 프로젝트의 규칙을 함께 확인한다. 충돌 시 적용 범위와 사용자의 최신 지시를 확인하고, 권한을 임의로 넓히지 않는다.

## 공통 스킬 사용

- gptgit 하위 프로젝트에서 해당 요청을 받으면 아래 공유 원본을 읽어 적용한다. 스킬 보관 위치와 실제 작업 대상을 구분하며, 필요한 작업에 해당하는 스킬만 읽는다.

| 작업 | 스킬·공유 원본 |
| --- | --- |
| 사용자 가이드 작성·수정 | [simple-user-guide](skills/simple-user-guide/SKILL.md) |
| 아이디어·요구사항에서 초기 기획 또는 요구사항 구체화 | [project-planning](skills/project-planning/SKILL.md) |
| 작업기록 확인·인계 점검·작업 재개 | [project-handoff](skills/project-handoff/SKILL.md) |

- 개인 설치본이 없거나 공유 원본과 다르면 지정한 공유 원본을 읽어 적용하고 차이를 알린다. 파일 존재·개인 설치·채팅 목록 등록·실제 적용을 구분하며 자동 설치·덮어쓰기는 하지 않는다.
- 대상 프로젝트의 README·AGENTS·관련 상세 규칙과 원본을 확인한다. 프로젝트별 기술 기준·저장 위치·공식 기록·보류 조건을 유지하며, 관리 프로젝트의 폴더 구조·실행 역할·기록을 다른 프로젝트의 기준으로 대체하지 않는다. 최신 사용자 지시와 적용 범위를 확인해 충돌을 해결한다.
- 사용자 스킬 생성·수정에는 공유 원본 저장·관련 검증·실제 결과 보고를 매번 포함한다. 공통 재개·스킬 생성·검증·인계의 상세 절차는 [공통 작업 흐름](docs/common_workflow.md)을 따른다. 공통 스킬은 상위 `skills/`, 프로젝트 전용 스킬은 해당 프로젝트의 `skills/`에서 관리하며 사용자 지정 범위를 우선한다.
- 가이드 결과물에는 simple-user-guide의 구조 점검·결과 보고를 적용하고, 모든 스킬에 HTML 검사를 강제하지 않는다. 스킬 자체는 메타데이터·참조·자원·변경 기능에 맞게 검증한다. 검사 미실행·제외·동작 미검증은 실제 상태대로 보고한다.
- 이 연결은 스킬 사용·검증 절차의 공통화다. 개별 프로젝트의 개발·장비 설정·외부 반영·기록 갱신·Git 실행 권한이나 별도 에이전트 생성 권한을 추가하지 않는다. 보류된 프로젝트를 임의로 재개하지 않는다.

## 공통 서브에이전트 관리

- 승인된 위임에는 [공유 위임 스킬](skills/delegation-reporting/SKILL.md)을 적용한다. 역할·제공자·권한·기록 위치와 기록 허용 조건은 대상 프로젝트가 정한다. 관리 프로젝트의 날짜 보고 승인을 다른 프로젝트에 확대하지 않는다.
- Astra는 마스터의 판단·지시·검토·통합 전용이다. 하위 Codex 담당은 Luna 또는 Terra만 사용하며, 단순 작업은 Luna, 복잡한 작업·독립 검토는 Terra가 기본이다. Claude Code·Hermes 등 프로젝트별 별도 역할 계약은 유지한다.
- 테스트와 정식 업무에 같은 제한을 적용한다. 명시 모델 지정과 실제 모델·권한 확인 후 Task를 전달한다. 기본 모델 상속·미확인 전달·승인 없는 Astra 대체를 금지한다. 사용자 예외가 있어도 검사 코드를 조용히 우회하지 않고 적용 범위와 처리 방법을 확인한다.
- 마스터 대화 탭은 분할하지 않는다. 담당용 새 탭을 만들고 그 안에서만 pane을 분할한다. 같은 작업 묶음의 담당 탭은 상태 확인 후 공유할 수 있다. 기존 창·서버를 임의 종료하거나 사용자 포커스를 바꾸지 않는다.
- 공통 검사·시작 도구·보조 훅은 실행 조건을 검사한다. 훅 신뢰·실제 작동과 파일 등록을 구분하며 직접 실행의 모든 우회를 막는 보안 경계로 주장하지 않는다. 이 규칙은 승인되지 않은 위임·프로젝트 변경·외부 작업을 허용하지 않는다.

## 공통 조회·문서 책임

- README·적용 규칙·최신 인계에서 진입점을 찾고 해당 작업에 필요한 원본만 읽는다. 같은 작업에서 확인한 근거는 변경·누락·충돌이 있을 때만 재조회한다.
- README는 위치·목적, AGENTS는 행동·권한, 상세 문서는 고유 기준·현재 상태·이력을 맡는다. 같은 상세 상태나 절차를 여러 곳에서 동시에 관리하지 않는다.
- 과거 PC 경로·검증·원격 미확인은 시점과 사용자 최신 설명을 함께 확인한다. 추정·제안·사용자 보고·직접 확인을 구분한다. 비밀번호·API 키·인증정보를 문서에 기록하지 않는다.

## 파일 반영과 Git 실행 권한

- 파일 변경은 사용자가 명시적으로 요청한 대상과 범위에서 수행한다. 검토·설명·방향 동의만으로 파일 수정 권한을 얻었다고 판단하지 않는다.
- commit과 push는 각각 해당 동작에 대한 사용자의 명시적인 실행 요청이 있을 때만 수행한다. commit 요청만으로 push를 허용받았다고 판단하지 않는다.
- 파일 수정·반영·저장 요청, 작업 완료, 운영 절차에 대한 동의, 원격 최신 유지라는 일반 목표는 commit·push 실행 허가가 아니다. 작업 종료 시 자동 commit·push하지 않는다.
- clone·pull도 공통 운영 절차만을 근거로 자동 실행하지 않는다. 사용자가 요청한 Git 작업 범위에서 수행한다.
- Git 작업을 요청받으면 저장소 상태와 대상 파일을 확인하고, 요청 범위의 변경만 포함한다. 다른 프로젝트나 사용자의 미완료 변경을 임의로 포함·취소·덮어쓰지 않는다.
- 강제 push, 이력 재작성, 변경 폐기 등은 일반 commit·push 요청에 포함된 것으로 보지 않는다. 해당 동작에 대한 명시적인 요청 없이 수행하지 않는다.
- 실행한 작업과 검증 결과를 구분하여 보고한다. 실제 commit·push를 하지 않았다면 완료했다고 기록하지 않는다.
