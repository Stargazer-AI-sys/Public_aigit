# project-prototype 작업 규칙

버전 0.8 · 2026-11-18. [상위 공통 규칙](../AGENTS.md)의 권한·모델 제한을 따른다.

- 요청된 목표·파일 범위에서 실행한다. commit·push, 추가 결제, 외부 공개, 자료 손실이 생기는 범위 변경은 명시적 사용자 지시가 필요하다.
- 전달된 입력과 관련 소스만 읽는다. 이미 받은 규칙을 다시 읽거나 README→위키→스킬을 순회하지 않는다. 필요한 원본으로 바로 가며 탐색은 두 단계 이내로 한다. 누락·충돌 때만 추가 조회한다.
- 기획은 한 문서에 목표·범위·구조·Task·완료 조건·결과를 적는다. 별도 명세·리뷰 보고서·실행 원장·해시 증빙·비용 분석을 만들지 않는다.
- 테스트는 요청한 결과와 직접 영향받은 동작만 확인한다. 통과 후 새 변경·실패가 없으면 반복하지 않는다. 단순 문서 수정에 전체 개발·QA·모델 시험을 실행하지 않는다. 결과는 기존 기획서에 성공/실패·미확인만 짧게 남긴다.
- 실제 개발은 Codex 기획→Claude 기획 검토·개발→독립 Codex QA를 필요한 범위에만 적용한다. 검토자는 원본을 수정하거나 자기 결과를 최종 승인하지 않는다.
- 담당 실행은 herdr 별도 탭에서 한다. Astra는 마스터, Codex 담당은 Luna·Terra다. 모델·권한·세션을 실제 확인한 뒤 Task를 전달한다. 모호한 전달을 재전송하지 않는다. 같은 필수 결함이 두 번 수정 후 남거나 검토가 세 번 끝나면 재시도 전에 원인을 재평가한다.
- 한 파일에는 한 작성자를 둔다. 담당 입력은 목표·입력 경로·쓰기 범위·완료 조건으로 제한한다. 전체 대화·과거 기록을 전달하지 않는다.
- 재사용할 지식이 생기면 해당 작업 중 위키의 기존 분류 문서에 합친다. Codex Luna 기본·복잡한 합성 Terra이며 Hermes 대기를 요구하지 않는다. 위키는 필요할 때만 읽는 참고 자료다.
- 요청 범위의 파일과 연결만 확인하고 실행하지 않은 시험을 완료로 쓰지 않는다. 상대경로를 사용하고 실패 원인을 해결한다. 작업기록은 인계가 필요한 때만 기존 최신 항목을 간단히 갱신한다.

변경: 0.7→0.8 — 중복 지침·실행별 증빙·비용 분석 의무 제거, 검증과 위키 산출물 축소.
