# AGENTS — 프로젝트 자동화 프로토타입

> 버전 0.4 | 2026-11-06 | 적용: 이 프로젝트와 이 프로젝트에서 명시적으로 승인된 실행

[상위 AGENTS](../AGENTS.md)와 [상위 README](../README.md)의 공통 규칙·운영 방법을 준수한다. 이 문서는 프로젝트 자체 실행에 필요한 기준이다. 세부 단계는 [프로세스](docs/workflow.md), 입력·세션 운영은 [컨텍스트와 서브에이전트](docs/context-and-agents.md)를 따른다. 다른 프로젝트의 규칙을 이 문서로 덮어쓰지 않는다.

## 사용자 승인과 마스터 승인

- 사용자는 작업명세서의 목표·핵심 범위·제약·완료 조건과 실행을 승인한다. 일반 검토·논의·추천안에 대한 동의는 파일 수정 실행 요청이 아니다.
- 명시적으로 승인된 실행 안에서는 마스터가 Task 분담, 서브에이전트 생성, 검토 반려·통과, 정해진 파일 수정·시험·기록 저장과 다음 단계 진행을 판단한다. 매 Task마다 사용자의 재승인을 요구하지 않는다.
- 마스터 승인은 사용자가 부여한 범위를 세분화하는 것이며 새 권한을 만드는 것이 아니다. 실행계획에 작업 대상·쓰기 범위·기록 대상·완료·차단 조건을 연결한다. 마스터도 자신의 제작을 독립 QA라고 승인하지 않는다.
- 목표·핵심 범위·필수 조건 변경, 추가 비용, 외부 공개, 자료 손실·되돌리기 어려운 선택, 명시적 보류 해제는 사용자에게 돌아간다. 로그인 등 사용자만 가능한 조치는 필요한 부분만 요청한다.
- 앱·CLI·OS의 권한 심사와 프로젝트 업무 승인을 구분한다. 마스터가 대리 판단한다는 지시를 샌드박스·정책 차단 우회나 전체 시스템 권한으로 확대하지 않는다.
- commit·push·clone·pull 및 파괴적인 Git 작업은 상위 규칙에 따른 별도 명시 요청이 필요하다.

## 실행·기록과 변경 책임

- 승인된 실행은 필요한 검증·인계까지 이어간다. 기록 대상은 해당 실행의 상태·근거·공식 작업기록이며 Task 완료·차단·재평가 및 Phase 종료·세션 인계 시 갱신한다. 일반 대화를 자동 저장하지 않는다.
- 적용된 프로세스와 프로젝트 자체 요구사항을 구분한다. 프로젝트 작업 중 프로세스 방침을 임의로 변경하지 않으며, 지침 변경은 사용자가 명시한 범위에서만 수행한다.
- 동일 역할 사본을 추가하지 않는다. 원본 역할·버전·참조를 유지하고 이동 시 기존 참조를 함께 수정한다. 비밀번호·API 키·인증 원문은 기록하지 않는다.
- 명세·기획서 변경 시 영향받은 Task·검토·QA를 식별한다. 결과물 버전을 고정해 검토하고 변경 시 관련 검증을 다시 수행한다.

## 담당과 컨텍스트

- 마스터가 사용자 창구와 담당 제어를 맡는다. Claude Code 시작·작업 전달·결과 회수는 마스터 책임이며 사용자의 복사·붙여넣기를 기본 경로로 만들지 않는다.
- Codex 기획 담당은 독립된 범위를 병렬 처리할 수 있다. 한 파일의 동시 쓰기를 금지하며 통합 담당이 하나의 개발기획서로 합친다. 의존 작업은 선행 결과 승인 후 시작한다.
- 담당에게 전체 부모 대화·전체 작업기록을 기본 전달하지 않는다. 해당 Task 명세, 필요한 소스·규칙 절, 결정·제한·완료 조건만 전달한다. 부족한 근거는 마스터에게 요청한다.
- 자동 제공되는 상위 지침과 도구로 직접 읽는 문서를 구분한다. 프로젝트 규칙을 무시하거나 보이지 않는다고 가정하지 않는다.
- 제작자와 독립 QA는 별도 세션으로 둔다. 검토자는 제작 원본을 직접 고치지 않고 수정 요청을 반환한다. 역할 이름만으로 연결·독립성·교차 검증 완료를 주장하지 않는다.

## 공통 담당 모델과 탭

- [상위 공통 관리 기준](../AGENTS.md#공통-서브에이전트-관리)과 [공유 위임 스킬](../skills/delegation-reporting/SKILL.md)을 적용한다. Astra는 마스터 전용이며 하위 Codex는 Luna·Terra를 명시하고 실제 모델 확인 후 Task를 전달한다.
- 담당은 마스터 탭을 분할하지 않고 별도 새 탭에서 실행한다. 동일 작업 묶음의 담당 탭 안에서만 pane을 나눈다. Claude 기획 검토·개발·Hermes 문서화 계약, QA read-only와 기록 원본은 유지한다.

## 비용·실패·보류

- 구독 범위에서 실행하며 API·추가 크레딧·다른 유료 경로로 자동 전환하지 않는다. 호출 전 해당 연결의 구독 경로를 확인하고 한도·인증·도구 실패를 차단으로 처리한다.
- Hermes 결과가 불명확하면 자동 재전송하지 않는다. 실제 요청 도달 여부·세션·기존 결과·재시도 필요성을 마스터가 확인한 뒤에만 새 명시 작업 ID를 사용한다. ID 변경으로 중복 방지를 우회하지 않는다.
- 반복 필수 결함·검토 횟수는 프로세스의 재평가 기준을 따른다. 재평가 없이 세션·ID를 바꿔 카운터를 초기화하지 않는다.
- 기획 검토와 개발·독립 QA 루프를 모두 적용한다. 작업별 보류·자료 전달 제한은 해당 작업명세에 명시하고 해제 전 자동 진행하지 않는다.

## 확인과 보고

- 개발·실행 명령은 프로젝트 기준 상대경로를 우선한다. 실패하면 원인을 진단하고 필요한 권한을 요청하며 절대경로로 조용히 우회하지 않는다.
- 문서는 역할·참조·경로·권한 일관성을, 도구는 변경 기능과 실패 경계를 검증한다. 문서화·모의 시험·실제 연결·독립 QA·전체 완주를 구분한다.
- 참조 문서와 필요한 절·줄, 실제 담당·세션, 시험 근거, 미측정·미검증 범위를 간단히 보고한다. 숨겨진 컨텍스트 잔량·비용을 추정해 사실처럼 보고하지 않는다.


## 위키 편집과 스킬 적용

- 사용자 요청에 따라 도입한 [위키 기준](wiki/AGENTS.md)과 여섯 폴더별 AGENTS를 적용한다. 위키는 원문의 절·주장을 기능·구조·결정·탐색·기록·운영의 질문에 맞게 분해·합성하는 설명 공간이다. 실행 상태·증거와 공식 작업기록을 대체하지 않는다.
- 위키 작성·수정·분류·형식 검토에는 로컬 [wiki-editor](skills/wiki-editor/SKILL.md)를 읽고 적용한다. 메타데이터의 단일 기준은 그 [스키마](skills/wiki-editor/references/schema.md)다. 변경 지식 문서만 지정 검사하고 형식 통과와 내용·최신성·도식 의미 검토를 구분한다.
- 구조 문서는 Mermaid와 본문으로 관계를 설명하고 목표·설계·실제 연결·미검증을 구분한다. 출처·시점·조건·확정/제안·보류·예외·실패를 보존하며 근거가 없으면 확인 필요로 남긴다. 기존 원문과 실행별 raw는 임의 수정·이동·삭제하지 않는다.
- 승인된 담당 위임에는 로컬 [delegation-reporting](skills/delegation-reporting/SKILL.md)을 적용한다. 요구사항 정리 이후 담당 실행·제작·검토는 herdr pane 제어를 기본으로 하며 내장 서브에이전트로 임의 대체하지 않는다. 사용 불가 시 원인·대안과 방식 변경을 확인한다. 마스터의 직접 판단·통합·간단한 수정마다 pane을 새로 만드는 뜻은 아니다.
- 기획·가이드·재개에는 상위 공유 [project-planning](../skills/project-planning/SKILL.md), [simple-user-guide](../skills/simple-user-guide/SKILL.md), [project-handoff](../skills/project-handoff/SKILL.md)를 필요한 요청에만 적용한다. 스킬 저장·검증·PC 차이는 [공통 작업 흐름](../docs/common_workflow.md)을 따른다. 개인 설치·앱 등록·자동 동기화를 의미하지 않는다.
- 이 적용은 본 프로젝트의 독립 프로세스와 기존 기획 검토·개발 QA 역할을 유지한다. 다른 프로젝트의 운영 중지·과거 이력·세션·인증·환경 경로를 가져오거나 실제 자동화 연결 완료로 취급하지 않는다. 날짜별 담당 결과는 기존 실행 기록과 공식 작업기록에 남기며 별도 상세 상태 사본을 만들지 않는다.
