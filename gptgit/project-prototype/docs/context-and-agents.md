# 컨텍스트와 서브에이전트 운영

> 버전 0.2 | 2026-11-06

목표는 여러 담당을 적극 활용하면서 각 담당이 자신의 명세와 필요한 원본만으로 작업하게 하는 것이다. [프로세스](workflow.md)의 단계·승인 권한은 이 문서에서 중복 정의하지 않는다.

## 1. 역할과 입력

| 역할 | 기본 입력 | 읽지 않는 기본 자료 |
| --- | --- | --- |
| 마스터 | 최신 인계·사용자 요구·현재 명세·필요한 결정 근거 | 전체 로그 일괄 읽기 |
| Codex 기획 | 확정 작업명세의 해당 요구사항·제약·관련 기술 근거 | 과거 대화 전체·관련 없는 실행 기록 |
| Claude 기획 검토 | 작업명세＋통합 개발기획서의 고정 버전 | 관련 없는 작업기록 전체 |
| Claude 개발 | 승인 개발기획서의 담당 Task·인터페이스·관련 소스·필수 규칙 절 | 기획 과정의 전체 대화·과거 조사 전부 |
| 독립 QA | 승인 요구사항·시험 계획·고정 결과물·환경 | 제작 대화 전체·제작자 판단만 담긴 성공 요약 |
| Hermes 문서화 | 목적·확정 변경·검증 결과·근거 링크·남은 제한 | 전체 프로젝트 탐색·전체 로그·보류 자료 |

프로젝트 규칙이 자동 제공되는 경우 그 사실을 구분한다. 필요한 규칙을 숨기거나 제외하는 것이 목표가 아니다. 작업기록 탐색은 원칙적으로 마스터가 맡고 필요한 사실·원본 절을 전달한다. 담당이 증거 부족을 발견하면 누락 항목과 이유를 마스터에게 반환한다. 광범위한 추가 탐색은 마스터가 필요 범위를 정한다.

## 2. Task 입력 묶음

마스터는 다음 항목을 하나의 Task 입력으로 구성한다. 명세 원본을 복제한 새 진실 원본을 만들지 않고 버전·해시·절을 연결한다.

- 실행 ID·Task ID, 담당 역할, 실제 제공자·모델·세션은 확인 후 기록.
- 목표와 연결된 요구사항 ID, 승인 명세/개발기획서 버전·관련 절.
- 입력 원본·허용 읽기 범위, 필요한 결정·인터페이스·의존 Task 결과.
- 쓰기 대상 또는 읽기 전용 여부, 담당 파일 소유권, 금지·보류·비용 제한.
- 산출물 형식·반환 위치, 완료·시험·검토 조건과 기대 결과.
- 실패·자료 부족·작업량 확대 시 반환 조건, 재시도 금지와 다음 인계 조건.

개발기획서에는 목적·동작·입출력·오류 처리·인터페이스·파일 범위·Task 의존성·시험 조건을 포함한다. 구현에 필요한 관련 소스는 별도 읽기가 가능하다. “명세만 읽기”를 소스나 필수 규칙을 보지 말라는 지시로 해석하지 않는다.

## 3. 병렬 작업과 파일 소유권

기획에서 아키텍처·검증 계획 등 독립 항목을 나눌 수 있다. 마스터가 공통 전제와 인터페이스를 먼저 고정하고 통합 담당을 지정한다. 선행 결정에 의존하는 설계는 그 결정 후 진행한다.

한 파일에는 한 시점에 한 작성자만 둔다. 다른 담당은 읽기 전용 검토 또는 별도 반환 결과를 사용한다. 검토 담당은 제작 파일을 직접 수정하지 않는다. 독립 QA는 제작자와 분리된 세션을 사용한다. 기획·개발 담당의 같은 Task 수정은 기존 세션을 재사용할 수 있다.

동시 실행 수는 실제 슬롯·구독 한도·파일 독립성에 맞춰 마스터가 제한한다. 서브에이전트 수를 늘리는 것 자체를 목표로 삼지 않는다. 병렬 시작 전 소유권 충돌을 검사하고 완료·실패·대기 담당을 함께 추적한다.

## 4. herdr와 실제 세션

마스터는 시작기를 통해 담당을 제어한다. 시작 전 프로젝트 경로, 역할, 실제 프로세스·세션 상태를 확인하여 기존 정상 세션을 재사용하고 상태 불명확 시 중복 시작하지 않는다. pane ID는 관측값이며 과거 기록의 번호를 고정값으로 쓰지 않는다.

herdr 창·Task 별칭·실제 AI 세션 ID를 구분해 연결한다. 창이 열렸다는 사실, 요청 전달, 실행 시작, 결과 회수, 내용 검증을 각각 확인한다. 결과 회수 실패 시 실제 출력·세션을 먼저 확인하고 자동 재전송하지 않는다. 사용자가 창 사이에서 복사·전달하는 수동 경로는 정상 자동 운영 완료로 표시하지 않는다.

요구사항 정리 이후 승인된 담당 작업은 herdr pane 제어를 기본으로 한다. 내장 Codex 서브에이전트로 임의 대체하지 않으며 사용 불가 시 원인·대안과 방식 변경을 확인한다. 두 수단은 다른 실행 경로이므로 실제 제공자·모델·세션·전달·회수 결과를 기록한다. Codex 분담을 Claude 또는 Hermes 실행으로 보고하지 않는다. 마스터의 직접 판단·통합·간단한 수정마다 pane을 요구하지 않는다. 상세 절차는 [위임 스킬](../skills/delegation-reporting/SKILL.md)을 따른다.

## 5. 마스터 교대와 관측

Task/Phase 경계에서 마스터는 반복 조회·결정 누락·맥락 증가·인계 오류를 확인한다. 필요하면 승인 범위에서 인계를 남기고 새 마스터로 전환한다. Task마다 무조건 교대하거나 관측하지 않은 “창 50%”를 강제 기준으로 삼지 않는다.

인계에는 목표·현재 승인·완료·진행·차단 Task, 실제 세션·산출물 버전, 쓰기 소유권, 미검증·보류, 다음 첫 행동과 근거 위치만 담는다. 다음 담당의 수신·맥락 복원을 확인하기 전 교대 완료로 표시하지 않는다.

참조 문서·필요 절/줄·조회 이유·잘림 여부와 실제 측정 가능한 사용량을 기록한다. 누적 입력·캐시·현재 컨텍스트·구독 한도를 서로 환산하지 않는다. 원문·토큰·세션 ID가 확보되지 않으면 미측정·미확인으로 둔다.
