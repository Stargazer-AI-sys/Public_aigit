# 최소 작업 프로세스

버전 0.5 · 2026-11-18

1. 사용자 요청의 목표·허용 변경·완료 조건을 확인한다. 개발이면 한 기획서에 구조와 Task를 함께 적는다. 단순 수정은 별도 기획서를 만들지 않는다.
2. 실제 개발의 기획은 Codex가 작성하고 Claude가 필요한 절만 읽기 전용 검토한다. Claude가 구현하며 마스터가 통합한다. 문서 수정에는 이 전체 단계를 적용하지 않는다.
3. 요청한 결과만 확인한다. 개발의 독립 Codex QA도 해당 완료 조건과 직접 영향에 한정한다. 실패한 부분만 수정·재검증하며 통과한 시험을 이유 없이 반복하지 않는다.
4. 같은 필수 결함이 두 번 수정 후 남거나 검토 세 번 이후에도 미완료이면 반복을 멈추고 원인·입력·접근법을 재평가한다. 전달 여부가 불명확하면 기존 세션부터 확인한다.
5. 기존 기획서의 결과 칸에 변경 결과·확인한 항목·미확인을 짧게 적는다. 재사용할 지식만 위키의 해당 분류 문서에 합친다. 비용 측정·A/B 모델 실행·리뷰 사본·실행 원장·증빙 폴더를 자동 생성하지 않는다.

단순 작업은 채팅 결과로 끝낸다. 인계가 필요한 경우에만 기존 작업기록에 현재 상태와 다음 행동을 남긴다.
