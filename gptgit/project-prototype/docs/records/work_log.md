# 프로젝트 작업기록

## 읽기·쓰기 규칙

- 재개 시 현재 목표·진행 Task·차단·다음 행동만 먼저 읽고 필요한 근거를 추가 조회한다.
- 승인된 자체 작업의 완료·차단·재평가·인계 때 마스터가 갱신한다.
- 날짜, 명세/Task ID, 실제 결과·검증 근거, 미검증, 다음 행동을 짧게 남긴다.
- 현재 인계는 갱신하고 긴 과거 상세 이력은 분리해 링크한다. 같은 상태를 중복 관리하지 않는다.
- 문서 작성·모의 시험·실연결·전체 완료를 구분하고 미확인 세션·비용·완료를 만들지 않는다.

## 현재 자체 작업

### 2026-11-06 — POLICY-AGENT-01: 공통 담당 모델·새 탭·훅 적용

- 사용자 승인 범위: 공통 위임 관리 도입. 상위 정책·공유 스킬을 연결하고 프로젝트 고유 Claude 기획 검토/개발·Codex QA·Hermes 문서화 계약, QA read-only, 기존 실행 원장과 기록 권한을 유지했다. 로컬 위임 스킬은 고유 역할/기록 연결만 맡는다.
- 변경: start_role의 명시 Model 또는 packet.session.model 검사, 공유 모델 검사 호출, 실제 모델 확인 전 Task 대신 대기 지시. dispatch는 모델 선검사 후 담당용 새 탭을 만들고 기존 탭/새 pane/cwd와 중복 Task 영수증을 검증한다. 마스터 탭을 분할하지 않는다. template에 session.model을 추가했다.
- 검증: 전체 회귀 58건 통과 후 최종 기존 탭 ID 거부 보완에 대해 dispatcher 13건 한정 재검사 통과. 정상 로그인 stderr/인증 실패·누락/금지/불일치 모델·QA 권한 보존을 포함한다. 이 PC에서 실제 start_role로 Luna가 시작되고 Workspace(Approve for me)·대기 응답을 확인했다. dispatcher --apply의 실제 전체 전달은 이번에 실행하지 않았다.
- 훅: .codex/hooks.json으로 공통 PreToolUse 가드를 연결하고 사용자 승인 후 이 프로젝트의 로컬 훅을 신뢰 등록했다. 실제 Luna 세션에서 잘못된 pane ID를 안전장치로 둔 금지 Astra 담당 시작 명령이 Blocked by hook으로 실행 전에 거부되는 것을 확인했다. 금지 모델은 호출하지 않았다.
- 구현/독립 검토: Terra 제작 및 별도 read-only Terra 검토. 반환 탭의 기존 여부 검증 지적을 보완하고 관련 회귀를 통과했다. 마스터가 코드·실행 근거를 대조한다. 현재 작업은 정책/도구 적용이며 새 workflow run 등록이나 전체 프로세스 완주가 아니다.
- 환경/한계: Windows PowerShell 정상 stderr 처리 문제를 수정했다. hooks는 현재 PC 공통 경로를 참조하며 다른 PC에서는 경로·신뢰를 다시 확인한다. 훅은 모든 실행 우회를 차단하지 않으며 Claude/Hermes 실연결은 미검증이다. 마스터 테스트 packet .local/agent-policy-smoke.json은 검증용이며 정식 작업명세를 대신하지 않는다.
- 최종 검토: 독립 QA가 기존 탭 반환/탭 ID 누락 차단의 수정과 회귀 코드를 재검토해 지적 해결을 확인했다. 마스터는 이번 정책·도구·훅 적용 완료로 판정하며 전체 프로세스 완주와 구분한다.
- 다음 작업: 승인된 Task에 명시 모델을 넣고 dispatcher 입력 검사 → 새 탭 시작 → 실제 모델/권한 확인 → 최소 Task 전달을 수행한다. 일반 논의를 자동 기록하거나 별도 report_docs 폴더를 만들지 않는다. commit/push는 하지 않았다.

### 2026-11-06 — POLICY-WIKI-01: 위키 기준·스킬·위임 규칙 적용

- 사용자 승인 범위: 위키 분류·편집 규칙, 스킬, 에이전트 규칙과 여섯 폴더 구조의 적용. 이 프로젝트의 기존 목적·역할·실행 원장·권한·QA 읽기 전용을 유지했다.
- 결과: [README](../../README.md)·[AGENTS](../../AGENTS.md) 0.3, CLAUDE 계약과 담당 운영·프로세스·실행 환경·도구 목록을 연결했다. [위키 기준](../../wiki/AGENTS.md), 여섯 폴더 AGENTS와 [전체 색인](../../wiki/index/README.md), 로컬 wiki-editor 및 delegation-reporting을 적용했다. 편집 스키마·템플릿 4종·검사기·회귀 시험을 갖췄다. 상위 공통 규칙·세 공유 스킬은 원본 참조로 유지하며 개인 설치·앱 등록은 하지 않았다.
- 위임과 기록: 요구사항 이후 승인된 담당 위임은 herdr pane이 기본이며 내장 수단으로 임의 대체하지 않는다. 일반 CLI 권한과 QA read-only 예외를 구분한다. 담당별 날짜·결과는 기존 실행 기록과 이 공식 인계에 남긴다. 별도 상세 상태 사본이나 다른 프로젝트의 런타임·인증·세션 의존은 추가하지 않았다.
- 검증: 두 스킬 기본 검사 통과, 위키 검사기 회귀 17건(정상 3·예상 결함 14) 통과. 기존 필수 구조 15개 및 기록 갱신 전 상대 링크 97개 누락 0. 기존 tools·tests·templates·config 13개 파일은 작업 전후 SHA-256 일치. 독립 읽기 전용 검토에서 상위 공통 출처와 검사기의 루트 경계 충돌을 확인해, 지식 문서는 로컬 AGENTS 진입점과 실제 대조한 상위 원본 이름·버전·절을 함께 기재하도록 명시하고 재검토로 해결했다. 링크 문법 예시는 코드 블록으로 구분해 기존 구조 검사 오탐을 해소했다.
- 환경: 이 PC의 시스템 Python 3.14로 본 프로젝트 `.local/wiki-editor-venv`를 생성하고 PyYAML 6.0.3을 설치·사용했다. 다른 프로젝트의 Python을 런타임으로 참조하지 않는다. `.local`은 Git 제외이며 다른 PC에서는 환경 확인이 필요하다.
- 미검증: 지식 문서의 실제 작성·전체 재분류, Mermaid 화면 렌더링, 대상 프로세스의 실제 모델·구독·세션 연결과 전체 루프는 검증하지 않았다. 기존 역할 시작기와 실행 코드는 변경하지 않았다. 검사기는 형식·경로를 확인하며 내용 진위·최신성·독립 QA 수행 사실을 보증하지 않는다. commit·push는 하지 않았다.
- 다음 행동: 승인된 작업명세와 실행 범위가 생기면 해당 Task부터 기존 프로세스로 수행한다. 위키 작성 요청에는 이번 로컬 기준·스킬을 적용하고 내용별 폴더에 설명을 작성한 뒤 지정 검사와 원문 대조를 한다. 이번 규칙 적용으로 자동화 실행이 등록된 것은 아니며 실행 원장의 새 run은 아직 없다.
