# 실행 설계 기준

> 버전 0.2 | 2026-11-04

실제 작업의 개발기획서는 [개발기획서 양식](../templates/development-plan.md)을 사용한다. 이 문서는 설계 시 빠뜨리지 않을 운영 기준이다.

1. 승인 작업명세의 요구사항을 설계·Task·시험 기준에 연결한다.
2. 독립 Task는 병렬 담당에게 나누고 공통 인터페이스·파일 소유권·통합 담당을 먼저 정한다.
3. 기획 검토에는 작업명세서와 고정 개발기획서를 전달한다. 필수 결함은 작성 담당에게 반환하고 마스터가 통과를 판정한다.
4. 개발 담당에게는 승인된 해당 Task·관련 소스·필수 규칙만 전달한다. QA는 제작자와 다른 세션에서 실제 시험한다.
5. 문서화 담당은 검증된 결과·근거·제한만 받아 초안을 작성한다. 최종 반영은 마스터가 대조 후 수행한다.
6. Task 입력은 [packet 양식](../templates/task-packet.json), 상태 원장은 [원장 입력](../tools/workflow_packets.md)을 따른다. docs/workflows/<run_id>에 실행 근거를 둔다.
7. 시작·전달·실행·회수·검토·완료를 구분하고 timeout·불명확 응답은 재전송 전에 실제 상태를 확인한다.

새 pane은 실제 반환 ID와 cwd를 확인한다. 이미 존재하는 다른 세션은 임의로 종료·재사용하지 않는다. 전체 자동화는 모든 단계의 실행 근거를 확보했을 때만 완료다.
