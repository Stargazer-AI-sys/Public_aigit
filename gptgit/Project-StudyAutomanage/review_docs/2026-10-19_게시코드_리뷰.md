# 2026-10-19 게시 코드 리뷰와 이력 보관

## 범위와 기준

이번 대화에서 변경한 로컬 승인 → Notion 게시 경로를 중심으로 검토했다. 주요 대상은 `notion_mcp.py`, `notion_publisher.py`, `notion_sync.py`, `notion_front.py`, `notion_reader.py`, `openai_provider.py`, `render.py`, 연결된 전달·검증 코드와 테스트다. 전체 프로젝트의 모든 기능·외부 배포·실제 화면을 검증한 것으로 확대하지 않는다. 공식 현재 상태는 [작업기록 25절](../docs/04_records/학습내용정리_작업기록.md#25-2026-10-19-로컬-기준-게시-최적화라우팅원격접속-게시코드-리뷰와-인계)을 따른다.

Notion 구조 축소를 검토하라는 이전 대화와 이번 코드 리뷰·백업 요청을 구분했다. 기존 개념·실습·분류 DB나 게시 자료를 삭제하지 않았으며, 자료 페이지 중심의 새 게시 모드는 아직 구현하지 않았다.

## 보관한 코드와 유지한 코드

- [수정 전 소스 ZIP](../이전버전_source/2026-10-19_code_review/source_before_review.zip): 소스·테스트·실행기·Schema 76개. 원본 자료·승인 DB·Notion 영수증·캐시·실행 결과를 제외한 명시적 파일 목록으로 생성했다.
- [파일별 SHA-256·보관 범위](../이전버전_source/2026-10-19_code_review/manifest.json), [복원 안내](../이전버전_source/2026-10-19_code_review/README.md). ZIP 무결성과 모든 파일의 SHA-256 대조를 통과했다. 현재 소스와의 차이는 의도한 리뷰 변경이며, 스냅샷을 최신 실행본으로 사용하지 않는다.
- 실행 코드에서 제외한 것은 `NotionMCP.write`의 이전 별도 구현, `NotionPublisher.write` 중복 재정의, 미사용 `deliver_plan` import다. 전체 모듈을 무사용으로 추정해 이동하지 않았다.
- `NotionMCP.write_many`의 엄격 검증 경로는 테스트·복구 비교 기준이고, `NotionPublisher`는 기반 클래스의 파싱·변환·조회·복구 기능을 상속한다. `notion_front.refresh`의 엄격 분기, `verify.py`, 구형 Schema와 과거 실행기도 호환·검증 또는 참조가 남아 있어 이번에 제거하지 않았다.
- 소스 ZIP은 Git 이력이나 배포본을 대신하지 않는다. commit·push·pull은 실행하지 않았다. API 키나 인증정보를 새 보관 자료에 수집하지 않았다.

## 검증과 한계

- 신규 리뷰 회귀 검사 5건: 일부 게시 범위의 개념 인덱스, ID 생성 후 계획 실패, 안내 화면 실패의 성공 보고서 보존, 단건 중복 생성 방지, 엄격 단건 생성·조회 호환.
- [이번 관련 회귀 결과](../study/study-system/output/test_tmp/code_review_regression.json). 실행 환경은 프로젝트 `.test-deps`, 내부 `output/test_tmp`, `python -B -X utf8`다. 실행기·명령행과 모의 전달/복구를 포함하고 실제 Notion 호출·유료 분석은 하지 않았다.
- 전체 관련 검사 **134건**을 실행해 133건이 통과했고 저장 라우팅 재현 1건이 테스트 자료 범위 오류로 실패했다. 현재 승인 7건을 당시 게시 범위 6건으로 제한하도록 테스트 스냅샷을 보정한 뒤 해당 1건을 재실행해 통과했다. 전체 검사를 다시 반복하지 않았으며 원래 실행과 대상 재실행을 JSON에 구분했다. 이 조정은 실제 게시나 승인 DB를 바꾸지 않는다.
- 외부 배포 패키지의 전체 실행, 사용자 브라우저·모바일, 실제 Notion 화면, 새 게시 모드의 시간 절감은 이번 리뷰에서 검증하지 않았다. 이번 코드 통합 자체가 실제 전송 시간을 더 줄였다고 주장하지 않는다.

## 다음 작업

자료 페이지 중심의 최소 게시 범위를 먼저 정한다. 원본 자료의 본문·분류·인용을 유지하면서 개념/실습 독립 페이지와 안내 화면 동기화를 선택 기능으로 둘지 확인하고, 현재 페이지 ID·영수증·승인과의 호환 및 중단 복구 조건을 설계한다. 현 DB를 삭제하거나 기존 자료를 재게시해 기준을 다시 만들지 않는다. 범위가 확정되면 저장 사례·모의 테스트에서 쓰기 수와 결과 차이를 비교한 뒤 구현한다.
