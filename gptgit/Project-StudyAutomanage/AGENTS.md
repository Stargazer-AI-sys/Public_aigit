# AGENTS.md — 학습내용정리 프로젝트

> 최종 수정: 2026-10-19 — Notion 반복 실행·조회 축소·검증 기준 연결

> 적용 기준: 2026-10-12 현재 문서 배치. 문서 위치와 역할은 [README.md](README.md)에서 확인한다. 기존 문서는 역할별 docs 폴더에 배치한다. 내용 분리는 하지 않는다.

## 역할과 작업 범위

- AI는 기존 소스를 읽고 구현·수정·검증하는 개발자 역할을 맡는다.
- 사용자 요청 범위에서 필요한 작업을 진행하며, 일상적인 부분 수정마다 확인을 요청하지 않는다.
- 기존 정상 기능을 재사용하고 변경 범위를 필요한 파일·함수로 제한한다.

## 작업 시작과 기준 자료

1. `README.md`에서 실제 소스 위치, 기준 버전, 문서 위치를 확인한다.
2. `docs/00_rules/Study_rule.md`의 해당 작업 규칙을 확인한다.
3. `docs/00_rules/Study_rule.md`의 「프로젝트 재개 조회 범위」에 따라 공식 작업기록의 최신 인계에서 필요한 소절을 선택한다. 재개를 이유로 기록 전체나 과거 인계를 순서대로 읽지 않는다.
4. 선택한 다음 작업에 필요한 요구사항·설계·소스·Schema·실행 결과의 관련 구간만 추가로 확인한다.

- 공식 작업기록의 프로젝트 루트 기준 위치는 `docs/04_records/학습내용정리_작업기록.md`다. 다른 위치의 사본이나 초안과 혼동하지 않는다.
- 위 문서가 로컬에 없으면 접근 가능한 원본을 확인한다. 접근할 수 없고 작업에 필수이면 누락 자료를 사용자에게 알린다.
- 최신 인계·개발 원본 위치는 README와 공식 작업기록에서 확인한다. 현재 기록의 프로젝트 내부 수정본을 과거 ZIP·외부 실행 소스로 덮어쓰지 않는다.
- ZIP·백업·대화 기억을 버전 확인 없이 최신 소스로 간주하지 않는다. 기존 `study.zip`의 추출 테스트 구현은 재사용 가능 부분을 검토하되 최종 설계를 대신하지 않는다.
- 실제 소스 위치와 구조는 유지한다. 이 문서를 적용하기 위해 소스를 임의로 `src/`로 옮기지 않는다.

## 소스 재작성 방지

- 수정 전에 관련 구현을 검색하고 입력·출력, 호출 관계, 기존 정상 동작을 확인한다.
- 소스가 없거나 버전이 불명확하면 추측해 재생성하지 않는다.
- 전체 재작성·대규모 구조 변경이 필요하면 이유와 영향을 먼저 설명하고 사용자와 범위를 확정한다.
- 확정 설계와 구현이 다르면 관련 근거를 확인해 필요한 부분을 수정한다. 충돌이 해결되지 않으면 임의로 기준을 선택하지 않는다.
- Collector 추출 결과, Analyzer 입력, AI 분석 결과, 실행 상태 기록을 구분한다.
- 최종 결과는 실제 선택 Schema 및 확정 Analyzer 인터페이스와 대조한다. 기본 실행은 `output/study_material_analysis_schema_v0.2.json`이며, 과거 v0.1·v0.2 초안 결과는 해당 버전으로 검증한다. 경로·버전 변경 시 실제 자료를 우선 확인한다.
- API 키와 인증정보를 소스·로그·문서에 저장하거나 표시하지 않는다.

## 검증과 완료 보고

- 변경 전후 차이와 관련 기존 기능을 확인하고 변경 영향에 맞는 검증을 수행한다.
- 유료 API 호출이 필요한지 확인하고, 기존 결과나 로컬 검증으로 충분한 경우 이를 활용한다.
- Schema 통과와 분석 내용의 사실성·원문 근거 검토를 구분한다.
- 완료 보고에는 변경 파일, 변경 이유, 실제 검증 결과, 미검증 범위, 다음 작업을 간결하게 제시한다.
- 실행하지 않은 검증과 구현 예정 기능을 완료로 기록하지 않는다.
- Notion 게시·동기화·검증·관련 자동화를 수정하거나 실행할 때는 [상세 규칙](docs/00_rules/Study_rule.md)의 「Notion 게시·검증과 반복 실행 기준」을 먼저 확인한다. 저장된 전달·검증 코드를 재사용하고, 로컬 변경 정보와 원격 수정 시각을 이용하는 조회 축소가 유지되는지 변경 영향에 맞게 확인한다.

## 공통 절차와 사용자 가이드

- 스킬 선택·원본은 [상위 AGENTS](../AGENTS.md), 재개·스킬 생성 검증·인계는 [공통 작업 흐름](../docs/common_workflow.md)을 따른다. 공통 절차를 이곳에 복사하지 않는다.
- 사용자 가이드의 고유 기술 내용·저장·반영 조건은 이 프로젝트의 상세 규칙을 따른다. 실제 구현·장비 적용과 문서 작성·구조 검증을 구분한다.

## 문서와 조회 범위

- 사용자 가이드와 공식 작업기록은 사용자의 명시적 반영 요청이 있을 때만 요청한 문서를 갱신한다. 단계 완료만으로 자동 갱신하지 않는다.
- 기존 문서의 관련 절을 수정·통합하고 같은 역할의 사본을 추가하지 않는다.
- 가이드 기본 위치는 `guide_docs/`다. 공통 절차는 위 스킬을, 이 프로젝트의 내용·반영 조건은 `docs/00_rules/Study_rule.md`를 따른다.
- 전체 프로젝트를 매번 읽지 않는다. 같은 작업에서 확인한 자료는 변경·누락·충돌이 있을 때만 재조회한다.
- 세부 규칙은 `docs/00_rules/Study_rule.md`에서 관리하며 이 문서에 통째로 중복하지 않는다.
