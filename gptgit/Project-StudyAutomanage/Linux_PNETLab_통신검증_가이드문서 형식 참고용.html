Linux ↔ PNETLab 내부 네트워크
통신 검증 가이드

VMware의 외부 Linux 서버를 PNETLab의 Access 스위치에 연결하고, Core 스위치의 SVI를 통해 다른 VLAN까지 통신하는 실습 절차입니다.

[확정] 검증 완료
Linux → VLAN 10 게이트웨이, Linux → VLAN 20 PC 통신 성공. 두 VM 재부팅 후 브리지·IP·경로 유지, PC20 Ping 패킷 손실 0%.

$1 목적 및 적용 환경

검증 목표: 관리·인터넷 접속은 VMnet8에 유지하고, VMnet2에서 외부 Linux → ASW1 → CORE-TEST → VLAN 20 PC20 통신을 확인합니다.

  • VMware 위 PNETLab VM과 Ubuntu 테스트 서버 VM 각각 NIC 2개.
  • Linux OS: 사용자 제공 출력상 Ubuntu 26.04.1 LTS. ens34는 NetworkManager 프로필로 관리.
  • ASW1과 CORE-TEST: Cisco vIOS Switch / IOSvL2 계열. 사용한 ASW 버전은 Experimental Version 15.2(20200924:215240).
  • 현재 Image 이름은 viosl2-adventerprisek9-m.ssa.high_iron_2…까지만 확인. 전체 이름은 별도 확인 필요.

이 문서는 2026-10-11 실습에서 확인한 환경을 기준으로 합니다. NIC 이름, 포트명, 기존 브리지 구성이 다르면 실제 값에 맞춰 적용하세요. VLAN·IP는 현재 검증용 값이며 최종 회사망 설계는 아닙니다.

범위: ICMP 연결성, VLAN·Trunk·SVI·정적 경로, 영구 설정과 재부팅 유지. 웹서비스, 실습망의 인터넷 접근, Edge Router, AWS/VPN은 후속 작업입니다.

$3 VMware 관리망·실습망 구성

  1. 기존 스위치/VPCS 설정을 저장하고 VM을 정상 종료합니다.
  2. Edit → Virtual Network Editor에서 사용하지 않는 VMnet2를 설정합니다.
  3. 각 VM의 Settings → Add → Network Adapter로 두 번째 NIC를 추가합니다.
  4. 추가 NIC를 Custom: Specific virtual network → VMnet2로 지정하고 Connect at power on을 체크합니다.

VMnet2 ≠ pnet2: VMnet 번호는 VMware 네트워크 이름이고, pnet 번호는 PNETLab 브리지 이름입니다. 이 실습은 VMnet2에 연결된 eth1을 pnet1에 연결합니다.

%4 스위치 검증

양쪽 스위치:

show interfaces trunk
show spanning-tree vlan 10
show spanning-tree vlan 20

CORE-TEST:

show vlan brief
show ip interface brief
show ip route

정상 기준: VLAN10·20 active, Trunk의 허용·활성·forwarding 목록 모두 10,20, SVI up/up, 두 /24 C 경로. 현재 CORE Gi0/2는 두 VLAN에서 Root FWD입니다. 이는 루트 방향 포트라는 뜻이며 CORE 자체가 Root Bridge라는 뜻은 아닙니다.

Trunk 허용 목록만 설정해도 VLAN이 생성되는 것은 아닙니다. 양쪽 스위치에 VLAN 10·20이 있어야 합니다. Trunk 포트가 show vlan brief의 Ports에 없어도 VLAN 항목 자체는 표시돼야 합니다.

$5 PNETLab 외부 브리지 연결

%1 실제 연결 확인

PNETLab VM의 Linux 콘솔/SSH에서 실행합니다. Cisco 장비 콘솔이 아닙니다.

bridge link
ip -d link show dev eth1.1
grep -A 4 "^iface pnet1 " /etc/network/interfaces

이번 환경은 pnet1에 eth1.1이 연결되고, eth1.1은 802.1Q VLAN ID 1이었습니다. 태그 없는 Linux ens34와 연결하려고 pnet1을 eth1에 직접 연결했습니다.

아래 임시 변경은 pnet1이 실습용이며 기존 연결이 eth1.1인 이번 환경 기준입니다. 이미 eth1 → pnet1이라면 변경 명령을 반복하지 말고 상태만 확인합니다. eth0 / pnet0 관리망은 유지합니다.

%2 임시 변경 및 확인

ip link set dev eth1.1 nomaster
ip link set dev eth1 master pnet1
bridge link show dev eth1

핵심 확인: master pnet1, state forwarding. pnet1/eth1에는 별도의 IP를 설정하지 않습니다. eth1.1의 VLAN ID 1은 PNETLab 호스트 외부 태그 설정이며, ASW의 Access VLAN10과 다른 구분입니다.

%3 토폴로지 Network 객체 추가

  1. PNETLab에서 ASW1·CORE-TEST가 보이는 토폴로지 화면의 빈 공간을 우클릭합니다.
  2. Add an object → Network를 선택합니다. 메뉴 이름은 버전에 따라 다를 수 있습니다.
  3. Name: LINUX-LAB, Type: Cloud1 / pnet1 항목을 선택하고 저장합니다.
  4. ASW1 Gi0/3 ↔ LINUX-LAB을 연결합니다. 포트가 사용 중이면 다른 빈 포트를 선택하고 설정도 맞춥니다.

%4 영구 설정

임시 연결에서 Ping 성공을 확인한 뒤 진행합니다.

cp -a /etc/network/interfaces /root/interfaces.backup-20261011
nano /etc/network/interfaces

pnet1 블록의 bridge_ports만 eth1.1에서 eth1로 바꿉니다.

auto pnet1
iface pnet1 inet manual
    bridge_ports eth1
    bridge_stp off

저장: Ctrl+O → Enter → Ctrl+X. pnet0·pnet2 등 다른 블록은 유지합니다. 백업 파일이 이미 있으면 다른 이름으로 백업해 기존 원본을 보존하세요.

grep -A 4 "^iface pnet1 " /etc/network/interfaces

핵심 확인: bridge_ports eth1. 임시 연결이 이미 적용됐으므로 전체 네트워크 서비스 재시작 없이 다음 검증으로 진행합니다.

$6 Linux IP·경로 및 영구 설정

%1 임시 통신 검증

Linux 테스트 서버에서 실행합니다. 주소·경로가 이미 있으면 add를 반복하지 않습니다.

ip addr add 10.10.10.100/24 dev ens34
ip link set dev ens34 up
ping -I ens34 -c 4 10.10.10.1

핵심 확인: 게이트웨이 Ping 손실 0%. 성공 후 VLAN20 경로를 추가합니다.

ip route add 10.10.20.0/24 via 10.10.10.1 dev ens34
ping -c 4 10.10.20.10

핵심 확인: PC20 Ping 손실 0%. Linux가 기존 ens32 기본 경로로 보내지 않도록 목적지 VLAN20의 경로만 추가합니다.

%2 관리 방식 확인·백업

cat /etc/os-release | head -n 5
ls /etc/netplan
nmcli -t -f NAME,DEVICE connection show --active
cp -a /etc/netplan "/root/netplan-backup-$(date +%Y%m%d-%H%M%S)"

이번 환경에는 netplan-ens32:ens32 및 ens34:ens34가 표시됐습니다. 다른 연결 이름이면 실제 프로필명으로 변경합니다.

%3 NetworkManager 프로필 영구화

nmcli connection modify ens34 \
  ipv4.method manual \
  ipv4.addresses "10.10.10.100/24" \
  ipv4.gateway "" \
  ipv4.routes "10.10.20.0/24 10.10.10.1" \
  ipv4.never-default yes \
  connection.autoconnect yes

nmcli connection up ens34

ens32는 수정하지 않습니다. never-default yes는 실습 NIC에 기본 경로가 생성되는 것을 막습니다. 이 명령은 ens34의 IPv4 주소·정적 경로 목록을 지정한 값으로 설정하므로 다른 실습 경로가 있다면 먼저 확인하세요.

ip -br addr show ens34
ip route
ping -c 4 10.10.20.10

핵심 확인: ens34 주소, default via 192.168.111.2 dev ens32, VLAN20 경로, 손실 0%. 이번 NetworkManager/Netplan 연동 환경에서는 nmcli로 관리하고 중복 YAML을 별도 작성하지 않았습니다.

%2 임시 변경 원복

PNETLab 브리지의 이번 변경을 되돌릴 때:

ip link set dev eth1 nomaster
ip link set dev eth1.1 master pnet1

영구 설정도 되돌리려면 interfaces의 pnet1 bridge_ports를 기존 eth1.1로 복구합니다. 이 경우 Linux의 태그 없는 연결은 더 이상 동일하게 동작하지 않습니다.

Linux에서 임시 주소·경로만 제거할 때:

ip route del 10.10.20.0/24 via 10.10.10.1 dev ens34
ip addr del 10.10.10.100/24 dev ens34

위 명령은 실행 중 상태만 변경하며 NetworkManager 영구 프로필을 복구하지는 않습니다. 영구 설정 원복은 백업의 기존 ens34 값으로 프로필을 복구하고 재활성화한 뒤 ip route로 확인합니다. ens32 관리 연결은 유지하세요.
