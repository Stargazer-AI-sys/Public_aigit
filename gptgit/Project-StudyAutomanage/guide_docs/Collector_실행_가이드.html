Collector 실행 가이드

원본 자료를 준비하고, 실행 환경을 설치한 뒤, AI 분석에 사용할 수집표를 만드는 순서입니다.

$1 목적과 문서 순서

Collector는 TXT·DOCX 원본의 글과 파일 정보를 읽어 material_inventory.csv라는 결과표를 만듭니다. 이 단계는 AI를 호출하지 않습니다. Analyzer는 그 결과표를 받아 AI 분석을 수행합니다.

처음 시작한다면 이 문서에서 설치와 수집을 완료한 뒤 API Key·분석 실행 가이드를 읽으세요. 결과 읽는 방법은 JSON·품질 검토 가이드에 모았습니다.

$2 압축 해제와 VS Code 준비

  1. study_analyzer_v0.5.zip을 새 폴더에 압축 해제합니다. 이전 버전의 결과 폴더는 보관합니다.
  2. VS Code에서 파일 → 폴더 열기로 압축 안의 study/study-system을 엽니다.
  3. 탐색기에 collector, analyzer, fixtures, output, requirements.txt가 보이는지 확인합니다.
  4. 터미널 → 새 터미널을 열고 프로필을 Command Prompt(CMD)로 선택합니다.
폴더역할
study/sourcefile원본 복사본을 넣는 폴더. study-system의 바깥에 있습니다.
study/study-system명령을 실행하는 작업 폴더
study-system/output수집표와 분석·재검증 결과

$3 자료 준비

ZIP에는 아래 대표 원본 4개가 포함돼 있습니다. 다른 자료를 처리하려면 sourcefile에 복사하세요. 원본 11개 전체가 포함된 패키지는 아닙니다.

파일형식
12일차.docxDOCX
15일차 Dynamic routing_IGP.txtTXT
18일차.txtTXT
20일차 경로재분배,루프백가상장비설정.txtTXT

하위 폴더까지 TXT·DOCX를 찾습니다. TXT는 UTF-8 계열·CP949·EUC-KR을 시도합니다. DOCX는 일반 문단만 읽으며 표·이미지는 현재 추출 범위에 포함되지 않습니다. 빈 본문은 실패입니다.

$4 Python 환경 설치

Windows에서 Python 3.10 이상을 준비합니다. 아래는 VS Code의 CMD 터미널이 study-system에 있다는 전제입니다. 한 줄씩 실행하세요.

python --version
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

python을 찾지 못하고 py -3은 작동한다면 앞의 두 명령에서 python을 py -3으로 바꾸세요. 마지막 명령은 그대로 사용합니다. 같은 폴더의 .venv 설치가 끝났다면 다시 설치하지 않습니다. 새 버전 폴더에서는 환경을 새로 준비합니다.

$5 원본 수집 실행

.venv\Scripts\python.exe -m collector.main

대표 4개만 있는 경우 전체=4, 성공=4, 실패=0과 output/material_inventory.csv 경로가 표시됩니다. 자료를 추가했다면 전체 개수는 달라집니다.

원본은 수정하지 않습니다. 기존 수집표가 있으면 같은 폴더의 backup CSV로 보관한 뒤 갱신합니다. 원본이 바뀌거나 자료를 추가했을 때 다시 수집하세요. 동일한 원본의 정상 CSV가 이미 있다면 매번 수집할 필요는 없습니다.

%다른 원본 폴더를 사용하는 경우

아래 경로는 예시입니다. 출력 CSV는 원본 폴더 밖에 두세요.

.venv\Scripts\python.exe -m collector.main --source-dir "D:\학습자료" --output-file "output\material_inventory.csv"

$6 수집 결과 확인

CSV 열확인할 내용
filename / extension분석하려는 파일명과 .txt/.docx 형식
statussuccess이면 다음 단계에 사용할 수 있음
text추출된 본문. 글이 실제로 들어 있는지 확인
sha256원본 파일 바이트로 계산한 64자리 식별값
error실패 이유

분석 명령의 파일명은 CSV에 정확히 한 행이어야 합니다. fixtures/legacy_material_inventory.csv는 과거 11개 자료의 수집표이며 현재 원본을 다시 수집한 결과로 취급하지 않습니다.

완료 기준: 대상 행이 success이고 본문이 비어 있지 않습니다. 입력 변환은 Analyzer 실행 중 수행되므로 별도 convert 명령은 필수 단계가 아닙니다.

$7 수집 문제가 생겼을 때

증상조치
requirements.txt 또는 collector를 찾지 못함VS Code에서 연 폴더와 터미널 위치가 study-system인지 확인
Python을 찾지 못함설치와 버전을 확인하고 python 또는 py -3 사용
실패 행 또는 빈 본문CSV의 error와 원본을 확인. DOCX가 표·이미지만 있는지 확인
파일명 중복수집 범위를 조정해 해당 이름이 한 행만 되도록 준비
자료를 찾지 못함sourcefile 위치와 TXT/DOCX 확장자 확인. 기존 CSV는 유지됨

터미널 종료 코드 0은 성공, 1은 일부 자료 처리 실패, 2는 실행 설정 오류입니다. 원본을 고쳤다면 수집표를 다시 만들고 다음 단계로 진행합니다.
