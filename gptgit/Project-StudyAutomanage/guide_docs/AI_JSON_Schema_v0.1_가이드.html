$1 결과 파일의 역할

JSON은 분석 내용을 항목별로 담은 파일이고, Schema는 필수 항목과 값의 형식을 검사하는 기준표입니다. Analyzer는 Schema 검사와 추가 품질 검사를 수행합니다.

실행 명령은 API Key·Analyzer 실행 가이드에서 관리합니다. 이 문서는 결과를 읽고 검토하는 단계에 집중하며 설치·호출 명령을 중복하지 않습니다.

$4 원문 근거가 들어오는 방식

인용이 원문과 일치해도 설명을 충분히 뒷받침하는지는 별도 검토합니다. 넓은 구간 안에 무관한 내용이 섞일 수 있습니다. 명령 예시, 확인 지시, 원문에 적힌 관찰 결과, 성공 여부 미확인을 구분해야 합니다.

$7 사용자가 확인할 순서

  1. 원본 연결: source.filename이 분석한 파일인지 확인합니다.
  2. 유형·요약: 자료의 주 목적과 혼합 성격이 잘 드러나는지 읽습니다.
  3. 이론: 원문 설명을 재현했는지, 의심스러운 단정을 검증된 사실로 바꾸지 않았는지 확인합니다.
  4. 실습: 설정 명령만 있는지, 확인 지시인지, 실제 관찰 기록이 있는지 구분합니다. 핑 명령만으로 성공을 확정하면 안 됩니다.
  5. 근거: 설명의 설정·삭제·관찰 등 각 주장을 인용이 뒷받침하는지 확인합니다.
  6. 누락·미완성: 중요한 내용이 빠지거나 질문·메모가 완성된 설명으로 바뀌지 않았는지 확인합니다.
  7. 관계: 연결 대상이 원문 의미와 맞는지 확인합니다.

이상한 부분은 문장과 항목 위치를 알려주면 됩니다. 별도 요청이 없다면 파일 전체를 다시 올리거나 프로그램을 재실행할 필요는 없습니다. 결과 JSON을 수동 수정해도 다음 AI 분석 지침이 자동으로 바뀌지는 않습니다.
