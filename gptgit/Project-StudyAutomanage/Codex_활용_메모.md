# 학습내용정리 — Codex 활용 메모

작성일: 2026-10-12 · 연결 정리: 2026-10-16. 다음 작업 시작용 안내이며 프로젝트 규칙·진행 상태의 기준 문서를 대신하지 않는다.

## 역할과 시작 자료

- Codex 역할: 기존 소스 개발·부분 수정·오류 분석·검증. 사용자는 목표·우선순위와 결과 수용 여부를 결정한다.
- 시작: [README.md](README.md) → [AGENTS.md](AGENTS.md) 및 `docs/00_rules/Study_rule.md`의 관련 규칙 → `docs/04_records/학습내용정리_작업기록.md`의 최신 인계 절.
- 최신 작업기록과 README에서 현재 수정 소스를 확인한다. 과거 ZIP·외부 실행 폴더를 현재 개발 원본으로 자동 선택하지 않는다.
- Codex가 직접 수정하려면 실제 소스에 접근할 수 있어야 한다. 문서만 제공한 상태를 소스 확보로 간주하지 않는다.

## 맡기기 좋은 작업

1. 저장된 분석 결과와 원문으로 의미 품질·누락·인용 근거를 검토한다.
2. 개선 범위를 정해 기존 코드의 필요한 부분만 수정한다.
3. 무료·로컬 검증과 기존 기능 확인을 먼저 수행한다. 새 유료 API 호출은 프로젝트의 승인 범위·예산 기준을 따른다.
4. 결과가 안정화되면 사용자 승인 흐름·전체 자료 확대·Notion 연동을 단계별로 구현한다. 다음 실제 우선순위는 최신 작업기록을 따른다.

## 사용자 작업 순서

- 이번 목표 하나와 대상 소스 버전·위치를 알려준다.
- 오류 해결이라면 실행 명령, 오류 메시지, 필요한 로그를 제공한다. API 키는 제공하지 않는다.
- 변경 파일·변경 이유·검증 결과·미검증 범위를 확인한다. 검증된 변경은 Git에 기록하는 방식을 권장한다.
- 작업기록·가이드 갱신은 필요한 시점에 별도로 요청한다.

## 다음 작업 요청 예시

> 최신 README.md와 AGENTS.md, 공식 작업기록의 최신 인계를 확인해줘. 이번 목표는 [목표]이고 기준 소스는 [버전·위치]야. 관련 구현을 먼저 읽고 필요한 부분만 수정해줘. 소스가 없거나 버전이 불명확하면 재작성하지 말고 알려줘. 승인 범위 내 무료 검증부터 진행하고 변경 파일·검증 결과·남은 작업을 간략히 보고해줘. 작업기록과 가이드는 내가 반영을 요청할 때 갱신해줘.

## 공통 사용 기준

재개·스킬 생성 검증·인계의 상세 절차는 [상위 공통 작업 흐름](../docs/common_workflow.md)을 따른다. 이 메모의 요청 예시는 안내용이며 별도 실행 권한이나 현재 상태의 기준이 아니다.

Codex의 AGENTS 지침 적용은 실제 작업 환경에 놓인 파일을 기준으로 한다. Library에 보관한 파일만으로 PC 소스 폴더에 자동 동기화되는 것은 아니다. 로컬에서 작업할 때도 AGENTS와 참조 문서의 경로를 맞춘다.
