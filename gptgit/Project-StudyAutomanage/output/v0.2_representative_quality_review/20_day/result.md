# 20일차 — 새 흐름 적용 검토 결과

SVI를 통한 VLAN 라우팅, 루프백을 이용한 핑 테스트, RIP 정적 경로 재분배의 설정과 확인을 다룹니다.

> 저장 결과를 원문 대조 후 재구성한 검토용 결과입니다. 새 API 분석은 수행하지 않았습니다.

## SVI와 트렁크 구성

스위치 포트를 VLAN에 할당하고 트렁크를 설정한 뒤, trunk 상태와 VLAN 인터페이스의 IP 및 활성화 여부를 확인하도록 안내합니다. 결과 출력은 기재되지 않았습니다.

## 루프백 주소를 소스로 지정한 핑

자료에서는 루프백 인터페이스를 가상 장비로 추가한 경우 확장 핑에 소스 IP를 기입해야 한다고 설명합니다. 예시 명령만 제시되어 있어 핑 성공 여부는 확인되지 않습니다.

루프백 주소를 소스 IP로 지정해 핑을 실행하는 명령 예가 있습니다. 핑 결과는 원문에 제시되지 않아 성공 여부를 확인할 수 없습니다.

❗ **정정** 특정 루프백에서 출발하는 통신을 시험할 때 소스 주소를 지정하는 것이며, 루프백이 있다는 이유만으로 모든 핑에 소스 지정이 필수인 것은 아니다. [Cisco — Understand the Extended Ping and Extended Traceroute Commands](https://www.cisco.com/c/en/us/support/docs/ip/routing-information-protocol-rip/13730-ext-ping-trace.html)

## 정적 경로의 RIP 재분배

서로 다른 라우팅 프로토콜을 사용하는 네트워크 간에 경로 정보를 번역하고 공유하여 한쪽 프로토콜이 학습한 네트워크 정보를 다른 쪽 프로토콜로 전달하는 기능이라고 설명합니다.

자료에서는 RIP에 정적 경로를 재분배할 때 메트릭을 10으로 지정하는 설정 예를 제시합니다.

자료에서는 경로 재분배를 동적 라우팅 프로토콜로 연결된 구간에서 사용하며, 정적으로 연결된 라우터 간에는 사용하지 않는다고 설명합니다.

R1에서 정적 경로를 RIP로 재분배하는 명령을 제시합니다. 이어서 학습되지 않은 ESW3의 라우팅 테이블에 192.168.40.0/24 경로가 표시된 관찰 기록이 있으며, 이 기록의 설정과 장비 간 연결 원인은 별도로 확정하지 않습니다.

❗ **정정** 정적 경로도 redistribute static으로 동적 라우팅 프로토콜에 주입할 수 있으므로 정적 경로는 재분배하지 않는다고 일반화하면 안 된다. [Cisco — Configure Routing Protocol Redistribution](https://www.cisco.com/c/en/us/support/docs/ip/enhanced-interior-gateway-routing-protocol-eigrp/8606-redist.html)

## 남은 확인 사항

- 설정에는 fa1/14, 확인 메모에는 fa0/14가 있어 실제 장비의 포트 이름 확인이 필요하다.
- RIP 버전·자동 요약·단말 게이트웨이·배선이 확인되지 않아 네트워크 실습 성공은 판정하지 않았다.
