장점
1. 개발자 및 엔지니어가 프로토콜에 대한 이해를 쉽게 할 수 있다.
 =>개발자는 자신이 개발하는 프로그램의 계층을 미리 지정함으로써 사용될 프로토콜 종류를 개발과정에서 추가할 수 있다.
 =>엔지니어는 자신이 관리하는 장비의 계층을 확인하면 사용되는 프로토콜의 종류를 짐작할 수 있다.
2. 사용자의 편의성 확장
 =>제조사가 다른 장비의 호환성을 통해 장비를 더 쉽게 사용할 수 있게 됨.
3. 캡슐화 과정에 대한 이해를 쉽게 함으로써 네트워크 장애시 빠른 대처가 가능하다.

■7계층에 대한 이해
1. 통신 프로그램 실행(*.exe)
 =>프로그램을 실행하는 자체가 7계층의 구현
 =>이 때 이미 사용될 TCP/UDP의 종류와 포트 번호는 결정됨.
2. 실행된 프로그램의 화면을 표현하기 위한 프로토콜들이 동작
 =>압축 및 암호화 기능도 함께 동작
3. 통신의 연결, 유지, 종료 및 통신 방향 결정, 프로세스 관리
4. 7계층에서 실행된 프로그램의 형태(신뢰(TCP)/비신뢰(UDP))를 이용해 포트 번호 지정
5. 트래픽의 출발지/목적지 주소 지정. 네트워크 경로 지정, IP관련 테이블 매핑.
6. 목적지의 내/외부 구분
7. 모든 트래픽의 신호 변환

■ 게임 실행
1. 사용자가 실행 아이콘을 더블클릭=> application
2. 게임 실행화면에 표현되는 여러가지 포맷(파일형식)들확인=> presentation
3. 서버와의 세션 수립, 유지, 종료 및 통신 방향 결정=> session
4. 게임 진행에 필요한 각종 서비스 관련 포트 지정.=> transport
5. 게임서버와 사용자 시스템간 상호 식별 및 사용자 정보가 네트워크로 넘어갈 때 경로 지정.=> network
6. 게임서버가 LAN에 있는지 아니면 WAN에 존재하는지 구분
7. 모든 트래픽의 출력과 신호 종류 구분(연결된 NIC의 종류에 기반)

■PDU와 헤더
-Message : 5~7계층
-Segment : 4계층 TCP
-Record/Datagram : 4계층 UDP
-Packet : 3계층
-Frame : 2계층

Frame의 크기가 1400byte라고 하면 그 속에 실제 데이터인 message의 크기는 얼마인가?(현재 사용중인 프로그램은 Web)

라우터가 스위치로 받은 패킷의 크기는 1380byte이다. 라우터의 ACL에서 차단목록에 포함시킨 TCP의 패킷이라고 했을 때 이 패킷속에 있는 메세지의 크기는 얼마인가?

■Frame구조
-Preamble : 데이터의 시작을 알리는 기능 담당. 7byte로 구성되어 있으며 모두 1010....반복구조.
-SFD : 1byte크기로 프리앰블의 정상적인 마무리를 표시
-DST MAC(6byte): 목적지 MAC주소. 송신 시스템이 목적지 IP에 대한 MAC을 ARP에서 찾지 못하는 경우 전체를 이진수 1처리(FFFF.FFFF.FFFF). 송신 시스템은 정상적으로 목적지 MAC주소를 입력했으나, 스위치가 학습하지 못한 경우에는 Unknown MAC으로 처리하여 수신 포트를 제외한 나머지 모든 포트로 Flooding처리.
-SRC MAC(6byte) : 출발지 MAC주소로 스위치는 이 주소를 MAC-address-table에 등록. 이런 이유로 브로드캐스트 MAC주소는 MAC Table에 학습될 수 없음.
-Type or Length(2byte): 3계층 헤더의 종류를 표시하는 영역으로 IP, ARP, ICMP, IPv6등을 미리 알리는 기능.
-FCS or CRC(4byte) : 프레임의 정상적인 끝맺음을 표시하는 영역으로 4byte모두 이진수 0으로 처리. 정상적이지 않은 경우 해당 프레임은 폐기처리.

■Packet 구조
-Header 길이 : 4bit 처리하며 IPv4, IPv6 등을 구분
-Total length(16bit) : 패킷의 전체 길이 표시. 최대 길이는 이론적으로 65536byte의 길이가 최대 길이이나 MTU로 처리하기 때문에 일반적인 이더넷 통신은 1500byte를 사용.
 =>MTU(Maximum Transfer Unit-최대 전송 단위): 시스템이 한번에 보낼 수 있는 최대 크기를 의미하며 커넥터의 형식에 따라 다름. 이더넷의 경우 1500byte를 기준으로 하고, FDDI, Token Ring, Token bus 등은 모두 조금씩 차이가 있음.
-Identification(16) : 데이터를 여러개의 조각으로 나눌 때 동일한 식별자를 부여하여 수신 시스템이 패킷 재조립 과정에서 그룹핑 작업이 가능하도록 하며, 다른 시스템에서 보내는 패킷 덩어리와 구분할 수 있도록 하는 역활 수행
-Fragment Offset(13bit) : 조각난 패킷의 누적 크기를 표시하는 영역으로 최초 패킷은 0처리되며 이후 패킷은 앞부분의 전체 전달량을 표시하여 수신 시스템이 패킷을 재정렬할 때 참고한다.
-Flags(3bit) : 여러개의 패킷을 보내는 경우 뒤에 추가 패킷이 있는 경우 More(1)로 처리하고 더 이상 추가 패킷이 없는 경우 Don't More(0)처리하여 추가 패킷의 여부를 확인하는 용도로 사용

■Segment 구조
-SRC 포트 : 출발지 포트 번호로 랜덤으로 선택
-DST 포트 : 목적지 포트 번호. telnet=23, ssh=22 등
-Sequence Number : 순서번호로 Windows Size와 연동하며, 동시 전송 데이터가 많으면 순서 번호도 같이 증가됨.
-Ack Num : 순서 번호에 1을 더한 값으로 응답 확인을 위해 사용
-Flags : Syn, Ack, Urg, Fin 등으로 구성되며 TCP의 신호 종류에 따라 필요시 각각 1의 값을 사용
-Window Size : 수신 장비의 버퍼 공간을 기준으로 송신시스템에 전송 데이터의 양을 지정하는 목적으로 사용.
-Urgent pointer: 재전송 데이터 발생시 오류가 발생한 순서번호 값을 이용해 송신 시스템에 3회 요청을 하며 송신시스템은 해당 순서번호부터 재전송을 시작

■MEMORY분류
1. 주 기억장치 : CPU와 직접 통신 가능
 - RAM(RANDOM ACCESS MEMORY) : 아무때나 읽기/쓰기 가능, 휘발성
   - SRAM(Static RAM): 공급되는 전압이 고정적(일정)
     =>Cache: 반복적으로 사용되는 자료 보관, CPU에 있는 L1, L2, L3 캐시
     =>Buffer: 속도 보상을 목적으로 사용.
   - DRAM(Dynamic RAM): 유동적인 전압 사용
     - SDRAM(Syncronous DRAM)
     - RDRAM(Rambus DRAM)
     - DDR SDRAM(Double Data Rate SDRAM)
 - ROM(READ ONLY MEMORY) : 읽기만 가능, 비휘발성
  ROM=> PROM=> EPROM=> EEPROM=> Flash
2. 보조 기억장치 : CPU와 직접 통신 불가능. 주 기억장치와 통신
 - 자기드라이브 : HDD, ZIP, Floppy
 - 광학드라이브 : CD, DVD
 - 전자기 드라이브 : SSD
