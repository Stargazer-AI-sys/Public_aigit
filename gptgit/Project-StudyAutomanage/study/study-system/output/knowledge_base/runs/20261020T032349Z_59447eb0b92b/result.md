## DHCP 개요와 호스트 설정 정보

### DHCP

연결된 호스트에 IP 관련 설정 정보를 자동으로 할당하는 기능을 담당하는 프로토콜이다\. 자료에서는 운영체제에서 별도로 할당하는 방법과 라우터에서 할당하는 방법을 언급한다\.

### 호스트 IP 관련 설정 정보

자료에서 네트워크 통신을 위해 호스트에 필요한 정보로 할당할 유니캐스트 주소, 서브넷 마스크, 게이트웨이, DNS 서버 주소 등을 제시한다\.

### DHCP

연결된 호스트에 IP 관련 설정 정보를 자동으로 할당하는 기능을 담당하는 프로토콜이다\. 자료는 호스트에 할당할 정보의 예로 유니캐스트 주소, 서브넷 마스크, 게이트웨이, DNS 서버 주소 등을 든다\.

```text
-윈도우나 리눅스에서 별도로 만들어 할당하는 방법과 라우터에서 할당하는 방식이 있다.

```

## 라우터 인터페이스 및 DHCP 풀 구성 예시

### DHCP 풀

라우터에서 DHCP를 구성할 때 사용하는 설정 단위로, 예시에서는 각 풀에 네트워크 주소와 마스크, 기본 라우터 주소, DNS 서버 주소를 지정한다\.

### 라우터 인터페이스 주소

예시 구성에서 라우터의 FastEthernet 인터페이스에 지정하는 IP 주소와 서브넷 마스크다\. 첫 구성은 Fa0/0에 192\.168\.1\.254/24, Fa1/0에 192\.168\.2\.254/24를 지정하며, /27 예시에서는 각각 200\.100\.100\.94/27과 200\.100\.100\.158/27을 지정한다\.

### 라우터에서 DHCP 풀 구성 예시

R1에서 Fa0/0을 192\.168\.1\.254/24, Fa1/0을 192\.168\.2\.254/24로 설정하고 각 인터페이스를 활성화하는 명령을 제시한다\. 이어 ict1 풀에는 192\.168\.1\.0/24, 기본 라우터 192\.168\.1\.254, DNS 서버 192\.168\.1\.253을 지정하고, ict2 풀에는 192\.168\.2\.0/24, 기본 라우터 192\.168\.2\.254, DNS 서버 192\.168\.2\.253을 지정하는 구성 예시다\. 명령 실행이나 구성 확인 결과는 기록되어 있지 않다\.

원문 인용 · 표시본의 인증값은 숨김

```text
R1
en
conf t
int fa0/0
ip addr 192.168.1.254 255.255.255.0
no sh
int fa1/0
ip addr 192.168.2.254 255.255.255.0
no sh
do sh ip route
exit
ip dhcp pool ict1
network 192.168.1.0 255.255.255.0
default-router 192.168.1.254
dns-server 192.168.1.253
exit
ip dhcp pool ict2
network 192.168.2.0 255.255.255.0
default-router 192.168.2.254
dns-server 192.168.2.253
```

## /27 서브넷 계산과 DHCP 구성 예시

### DHCP 풀

라우터에서 DHCP를 구성할 때 사용하는 설정 단위로, 예시에서는 각 풀에 네트워크 주소와 마스크, 기본 라우터 주소, DNS 서버 주소를 지정한다\.

### 라우터 인터페이스 주소

예시 구성에서 라우터의 FastEthernet 인터페이스에 지정하는 IP 주소와 서브넷 마스크다\. 첫 구성은 Fa0/0에 192\.168\.1\.254/24, Fa1/0에 192\.168\.2\.254/24를 지정하며, /27 예시에서는 각각 200\.100\.100\.94/27과 200\.100\.100\.158/27을 지정한다\.

### /27 서브넷 주소 범위

자료의 계산 예시에서는 200\.100\.100\.0/24를 /27로 나누고, 세 번째와 다섯 번째 서브넷 범위를 각각 200\.100\.100\.64–95와 200\.100\.100\.128–159로 제시한다\.

### 자료의 /27 서브넷 계산 예시

자료는 200\.100\.100\.0/24를 /27로 서브넷팅하는 문제에서 서브넷 비트가 3비트 추가된다고 적고, 세 번째 서브넷을 200\.100\.100\.64–95, 다섯 번째 서브넷을 200\.100\.100\.128–159로 제시한다\. 각 라우터 인터페이스에는 해당 범위의 마지막 사용 가능 주소라고 제시된 \.94와 \.158을 지정하고, DHCP 풀에는 각각 \.64/27과 \.128/27 네트워크를 설정한다\.

## ping 초기 타임아웃 설명

### ARP 테이블

ping 초기 타임아웃에 관한 자료의 설명에서 최초 통신 시 아직 구축되지 않은 것으로 언급되는 테이블이다\. 자료는 이후 목적지 호스트에 대한 스위치의 브로드캐스트와 학습 지연을 설명한다\.

### ping 응답 시간 제한

자료는 ping에서 기본 2초 안에 응답이 있어야 한다고 설명하며, 최초 통신에서 학습 시간이 이를 초과하면 초기 테스트가 실패할 수 있다고 서술한다\.

### 초기 ping 타임아웃

자료에서는 최초 통신 시 ARP 테이블이 구축되지 않아 발생하는 브로드캐스트와 학습 시간 때문에 처음 1\~2개 패킷에서 Request time out이 나올 수 있고, 이후에는 정상 테스트가 진행된다고 설명한다\.

### 자료의 ping 초기 타임아웃 설명

자료에서는 최초 통신 때 ARP 테이블이 아직 구축되지 않아 목적지 호스트에 대해 스위치가 브로드캐스트하고, 이로 인한 학습 시간이 기본 2초 응답 시간 안에 들지 않으면 처음 1\~2개 패킷에서 Request time out이 발생할 수 있으며 이후에는 정상 테스트가 진행된다고 설명한다\. 이는 자료에 적힌 설명이며, 별도의 검증 결과는 제시되어 있지 않다\.

```text
-최초 통신을 하면 ARP테이블이 구축되지 않은 상태이므로 목적지 호스트에 대해 스위치가 브로드캐스트를 하게 된다.
ping은 기본 2초의 시간 안에 응답이 있어야 하는데, 브로드캐스트 신호로 인해 학습까지 걸리는 시간이 초과되는 경우가 발생되어 test 실패가되며 이후에는 모두 정상적으로 test가 진행된다.
```
