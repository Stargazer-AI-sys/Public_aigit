■DHCP(Dynamic Host Configuration Protocol)
-연결된 호스트에 대해 IP관련 설정 정보를 자동으로 할당하는 기능을 담당하는 프로토콜이다.
-윈도우나 리눅스에서 별도로 만들어 할당하는 방법과 라우터에서 할당하는 방식이 있다.
-네트워크 통신을 위해 호스트에서 필요한 IP관련 정보는 할당할 유니캐스트, 서브넷 마스크, 게이트웨이, DNS서버 주소 등이 있다.

R1
en
conf t
int fa0/0
ip addr 192.168.1.254 255.255.255.0
no sh
int fa1/0
ip addr 192.168.2.254 255.255.255.0
no sh
do sh ip route
exit
ip dhcp pool ict1
network 192.168.1.0 255.255.255.0
default-router 192.168.1.254
dns-server 192.168.1.253
exit
ip dhcp pool ict2
network 192.168.2.0 255.255.255.0
default-router 192.168.2.254
dns-server 192.168.2.253

문제. 200.100.100.0/24 주소를 /27로 서브넷팅.
3번째 서브넷과 5번째 서브넷을 각각 할당
라우터에는 사용 가능한 마지막 IP 할당 및 DHCP구성.
1. 주소 범위 계산
 서브넷 비트가 3비트 추가됨. 추가된 3비트로 십진수 2, 4가 해당됨.
010 0 0000=>64
010 1 1111=>95

100 0 0000=>128
100 1 1111=>159
2. 라우터에 할당 주소
 Fa0/0 : 200.100.100.94/27
 Fa1/0 : 200.100.100.158/27

3.라우터 구성
R1
en
conf t
int fa0/0
ip addr 200.100.100.94 255.255.255.224
no sh
int fa1/0
ip addr 200.100.100.158 255.255.255.224
no sh
exit
ip dhcp pool ict1
net 200.100.100.64 255.255.255.224
default-router 200.100.100.94
dns-server 200.100.100.93
ip dhcp pool ict2
net 200.100.100.128 255.255.255.224
default-router 200.100.100.158
dns-server 200.100.100.157



Tip. ping test에서 처음 1~2개의 패킷이 손실되면서 Request time out이 나오는 이유?
-최초 통신을 하면 ARP테이블이 구축되지 않은 상태이므로 목적지 호스트에 대해 스위치가 브로드캐스트를 하게 된다.
ping은 기본 2초의 시간 안에 응답이 있어야 하는데, 브로드캐스트 신호로 인해 학습까지 걸리는 시간이 초과되는 경우가 발생되어 test 실패가되며 이후에는 모두 정상적으로 test가 진행된다.
