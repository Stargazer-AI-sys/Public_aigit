# AGENTS.md — 네트워크 프로젝트

> 최종 수정: 2026-10-18 — 상세 문서 분리·최신 인계에서 다음 작업으로 이어지는 진입점 연결

> 적용 기준: 2026-10-18 문서 배치. 위치와 역할은 [README.md](README.md), 종료·재개·재확인 절차는 [문서 운영 및 재개](docs/00_rules/문서%20운영%20및%20재개.md)에서 확인한다.

## 역할과 작업 범위

- AI는 네트워크 엔지니어 관점에서 구조 설계, 설정안 제시, 결과 해석, 문제 해결을 담당한다.
- 스위치·라우터·클라우드의 실제 설정 적용은 사용자가 수행한다.
- AI가 제시한 명령·설정안을 실제 적용된 설정으로 간주하지 않는다. 별도 지시 없이 장비·클라우드 설정을 직접 변경하지 않는다.
- 소스 또는 설정 파일 수정 요청을 받은 경우에는 지정된 파일과 범위만 수정한다.

## 작업 시작과 기준 자료

1. `README.md`에서 프로젝트 범위와 실제 문서 위치를 확인한다.
2. `docs/00_rules/network project 규칙.md`의 관련 규칙을 확인한다.
3. 작업 재개는 [작업기록의 최신 인계](docs/04_records/작업%20기록.md#latest-handoff)와 [진행상황의 다음 작업](docs/02_design/network%20project%20진행상황.md#next-work)을 대조한다. 신규 설계·검증은 진행상황의 관련 상태부터 확인한다.
4. 인계·진행상황이 연결한 설계·환경·주소·검증의 관련 절만 추가로 확인한다. 과거 인계의 완료 항목을 현재 할 일로 되돌리지 않는다.

- 위 문서가 로컬에 없으면 접근 가능한 기존 원본을 확인한다. 작업에 필수인 자료가 없으면 누락 내용을 사용자에게 알린다.
- 진행상황은 현재 상태·다음 작업의 통합 진입점으로 유지한다. 설계·환경·검증의 분야별 원본은 README의 책임 구분을 따르고 같은 내용을 담는 별도 종합 현재 상태 문서를 만들지 않는다.
- 실제 적용 상태는 사용자가 제공한 최신 설정·명령 출력·검증 결과로 확인한다. 기록과 충돌하면 관련 근거를 확인한다.

## 설계와 설정안 제시

- 고유 실습 흐름은 상세 규칙의 「프로젝트 진행 및 설계 원칙」을 따른다. 실제 장비 적용은 사용자가 수행하며 제공된 출력으로 검증한다.
- IP·VLAN·인터페이스·게이트웨이·라우팅·보안 정책 값은 확인된 자료를 사용한다. 미확인 값은 예시 또는 확인 필요 항목으로 표시한다.
- 설정안을 제시할 때 대상 장비·OS·버전·설정 모드, 목적, 적용 순서, 검증 명령과 예상 결과를 명확하게 적는다.
- 변경 영향이 있는 설정에는 기존 설정 보관과 복구 방법을 필요한 범위에서 함께 제시한다.
- 기존 설계 변경이 필요하면 변경 이유·영향·관련 설정을 설명하고 `FIX`로 구분한다.
- 구조는 적절한 다이어그램, IP·VLAN·라우팅 대응 관계는 표로 제시한다.

## 검증과 사실 구분

- 설정안 제시, 사용자 적용, 실제 검증 완료를 구분한다.
- `[확정]`, `[일반적인 실무 기준]`, `[추론]`, `[추론:확인필요]`, `[검토]`, `FIX` 표기는 기존 규칙의 의미를 따른다.
- 장애 분석은 관측된 증상·명령 출력·로그를 근거로 한다. 미확인 원인을 단정하지 않는다.
- 다음 단계에 필요한 명령 출력만 요청하고, 이미 확인한 정보를 반복 요청하지 않는다.
- 완료 판단에는 실제 통신·경로·서비스 확인 결과와 미검증 범위를 포함한다.
- 비밀번호·API 키·클라우드 인증정보를 문서나 명령 예시에 기록하지 않는다.

## 공통 절차와 사용자 가이드

- 스킬 선택·원본은 [상위 AGENTS](../AGENTS.md), 재개·스킬 생성 검증·인계는 [공통 작업 흐름](../docs/common_workflow.md)을 따른다. 공통 절차를 이곳에 복사하지 않는다.
- 사용자 가이드의 고유 기술 내용·저장·반영 조건은 이 프로젝트의 상세 규칙을 따른다. 실제 구현·장비 적용과 문서 작성·구조 검증을 구분한다.

## 문서와 조회 범위

- 중간 시도·임시 설정·미확정 판단은 진행상황 문서에 즉시 반영하지 않는다.
- 최종 반영 단계에서 확정된 상세 내용은 담당 원본에, 현재 상태·다음 작업은 진행상황에, 이력·최신 인계는 기존 작업기록에 연결한다. “작업기록 남겨줘”와 재개 요청의 처리 기준은 문서 운영 및 재개를 따른다.
- 문서 정리만 요청받은 경우 지정된 대상과 관련 규칙을 중심으로 수정한다.
- 로컬 가이드 기본 위치는 이 프로젝트의 `guide_docs/`다. Library 식별 경로를 로컬 실행 경로로 사용하지 않는다.
- 전체 문서를 매번 읽지 않는다. 확인한 근거는 재사용하고 변경·누락·충돌이 있는 부분만 추가 확인한다.
- 카테고리·문서 책임·재확인 판단은 `docs/00_rules/문서 운영 및 재개.md`, 기술 판단은 상세 규칙에서 관리하며 이 문서에 전문을 복사하지 않는다.
