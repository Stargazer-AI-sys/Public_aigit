## $3 관리망 DHCP의 현재 판단

- [확정:사용자 확인] VMnet8 DHCP 범위 `192.168.111.128~192.168.111.254`.
- [확정] ens32 프로필 `ipv4.method auto`, 수동 `ipv4.addresses 192.168.111.100/24`; Netplan은 `dhcp4: true`, `dhcp6: true`, 수동 addresses는 .100만 포함한다.
- [확정] 제공 DHCP 출력의 임대 IP는 .128, DHCP 서버 .254, 임대시간 1800초. 조회 당시 `dynamic` 및 남은 유효기간 1710초도 확인했다. MAC은 `00:0c:29:0f:ac:f2`.
- FIX: 과거 사용자는 .100·.128을 모두 직접 입력했다고 보고했으나 현재 설정·임대 증거상 .128은 DHCP 주소다. 변경 경위는 미확인이다. 과거 보고를 지우거나 현재 .128을 수동 주소로 단정하지 않는다.
- 확인된 수동 .100·EDGE .110은 임대 범위 밖이다. 이번에 설정을 바꾸지 않았으며 .128 삭제·DHCP 범위 변경을 요구할 근거는 없다. 다른 VM 전체의 고정 주소·임대·예약을 조사하지 않았으므로 관리망 전체 무충돌을 확정한 결과는 아니다.
- 실습 VLAN의 DHCP 서버·범위·예약 정책은 아직 설계하지 않았다. VMnet8의 기존 DHCP와 별개다.

| 장비 | 경로 / 설정 | 마지막 근거 |

| EDGE | 내부 두 /24 via 10.255.0.1; default via 192.168.111.2 | 10월 18일 경로 출력 |
| Linux | ens32 관리 기본 경로, ens34의 VLAN20·전송망 개별 경로 | 기존 기록 + 10월 18일 제공 설정 |

LAB-NAT는 NAT 대상 선택용이며 인터페이스 방화벽 정책이 아니다. Linux의 `1.1.1.1/32` 임시 경로는 영구 프로필에 넣지 않았고, 10월 18일 조회 결과 없음(사용자 확인). 정책 라우팅 전체를 검사한 결과는 아니다.

AWS 현재 리소스·주소를 확인한 자료는 없다. 계획만으로 구현 상태를 만들지 않는다.
