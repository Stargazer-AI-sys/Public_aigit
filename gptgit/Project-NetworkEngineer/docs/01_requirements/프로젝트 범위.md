## $1 목적

네트워크 엔지니어 취업을 위한 사내망·클라우드 인프라의 구조와 통신 흐름을 이해하고 직접 실습한다. 특정 웹서비스 운영이나 애플리케이션 개발 자체를 중심으로 두지 않는다.

## $2 포함 범위

- On-Premise Network, Linux Server, Web Service·Database 통신 확인
- AWS Cloud Network, On-Premise–AWS Hybrid 연결
- HA·Redundancy, Security, Monitoring, Python Automation

## $3 기본 배경과 제약

- [확정] 중견 규모 개발회사가 기존 On-Premise 일부와 AWS를 함께 사용하는 Hybrid Cloud 환경을 가정한다.
- [확정] 개발·관리·모니터링 환경에서 AWS Private Subnet 시스템에 접근하는 흐름을 학습한다. 서비스 트래픽과 관리·배포 트래픽을 논리적으로 구분한다.
- [확정] 기본 내부망은 Edge Router 1대, Core L3 1대, L2 Switch 3대이며 개발/테스트 1대·운영 2대 역할로 나눈다. 초기 기능 검증은 단순화할 수 있다.
- [확정] 실습은 VMware 기반 가상 장비로 수행하고 네트워크 장비 계열은 Cisco로 통일한다. 실습실 물리 모델의 실제 이미지를 사용하는 것으로 간주하지 않는다.
- [현재 사용] PNETLab을 검증 환경으로 사용한다. 최종 플랫폼의 별도 채택 결정과 현재 사용 사실을 구분한다.
- [확정] AWS는 필요한 기본 리소스만 사용해 비용을 최소화하고 실습 후 제거하는 방향이다. 아직 생성·설정 완료를 의미하지 않는다.
- [확정] Python 자동화는 상태 조회·정보 수집부터 시작하며 초기 자동 복구는 적용하지 않는다.

## $4 이번에 확정하지 않는 항목

전체 호스트 수·IP, 최종 보안·HA 범위, AWS 세부 구성, 배포 방식은 이 범위 문서에서 임의로 정하지 않는다. 현재 미확정 목록과 다음 결정 순서는 [진행상황 `$7`·`$8`](../02_design/network%20project%20진행상황.md#open-items)을 따른다.
