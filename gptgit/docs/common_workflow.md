## 2. 작업 재개와 PC 이동

1. 현재 작업 폴더·사용자 요청에서 대상을 정하고 README·적용 AGENTS·관련 상세 규칙을 확인한다. 이미 확인한 자료는 변경·누락·충돌이 있을 때만 다시 읽는다.
2. 공식 작업기록의 최신 인계와 프로젝트가 지정한 현재 상태 문서를 확인한다. 다음 작업에 필요한 원본·소스·증빙만 추가 확인하고 전체 저장소를 일괄 조회하지 않는다.
3. 이전 PC의 절대경로·설치·검증 결과는 당시 환경의 정보로 해석한다. 현재 프로젝트의 실제 경로와 이번 작업에 필요한 실행기·자료·접근 조건만 확인한다. ZIP·외부 실행 폴더·백업으로 현재 수정본을 덮어쓰지 않는다.
4. 필요한 스킬의 공유 원본·개인 설치본·현재 채팅 목록을 구분한다. 설치본이 없거나 다르면 차이를 알리고 지정 공유 원본을 읽어 적용한다. 필수 자원이 없으면 해당 작업만 미확인으로 남긴다. 설치·복사·덮어쓰기·설정 변경은 별도 요청 없이 하지 않는다.
5. 사용자의 최신 설명과 최신 인계를 함께 반영한다. pull 완료 보고는 사용자 보고로 받아들이고 과거 원격 반영 미확인 문구만으로 같은 질문·pull을 반복하지 않는다. 과거 할 일과 보류를 현재 할 일로 자동 승계하지 않는다.
6. 기준 위치·복원한 상태·영향 있는 환경 차이·다음 행동을 짧게 알린다. 대상·범위와 필요한 실행 요청이 확인되면 작업을 계속한다. 필수 입력·주요 결정·추가 권한이 필요한 부분만 질문하고 독립적인 조회·분석은 계속한다. 기록의 제안 자체를 실행 허가로 확대하지 않는다.
7. 이번 변경·환경 차이에 필요한 검증을 수행한다. 파일 최신화·설치·채팅 등록·동작 검증을 구분하고 과거 검사를 일괄 반복하지 않는다. 보류된 작업은 해당 작업의 재개 요청이 명확한 경우에만 시작한다.

### 2.1 필요한 맥락만 복원하기

- 작업기록은 제목·최신 인계에서 중단 지점을 찾는 진입점이다. 다음 행동을 정하기 전에 그 행동의 역할·설계·결정 원본 중 필요한 절을 대조한다. **결정 완료 / 구현 필요 / 검증 필요 / 실제 미정**을 구분하고 미구현을 미정으로 취급하지 않는다.
- 현재 대화에서 확인됐지만 아직 저장되지 않은 사용자 지시·완료·보류를 함께 반영한다. 기존 결정 안에서 처리할 사항을 사용자에게 다시 결정하도록 요구하지 않는다.
- 제목 검색 → 필요한 절·줄 범위 → 직접 연결된 근거 순서로 조회한다. 전체 작업기록·과거 대화·큰 도구 출력을 일괄 읽지 않으며 이미 읽은 자료는 변경·충돌·누락이 있을 때만 다시 읽는다. 출력 잘림은 확인 완료가 아니다.
- 승인된 다중 에이전트 작업은 기획 시 Task별 담당 세션·입력·산출물·완료/검토/인계 조건을 정한다. 부모 대화 전체 대신 목표·명세 Task ID·확정 결정·원본 범위·권한·보류·검증 근거를 전달한다. 별도 에이전트 생성은 기존 사용자 요청·적용 지침의 허용 범위를 따른다.
- 예상 밖 작업량 확대 시 짧게 알리고, 승인된 실행 기록 범위에서 완료·미해결·다음 행동·원본 버전을 남겨 인계한다. 같은 범위의 세션 분할만으로 재승인을 요구하지 않으며 비용·핵심 범위 변경은 기존 기준을 유지한다. 일반 조회·논의에는 기록 자동 저장 권한을 부여하지 않는다.

네트워크는 현재 설계·상태 문서에서 환경과 다음 실습을, 학습 프로젝트는 최신 공식 인계와 실제 소스에서 구현·검증 기준을 찾는다. 관리 프로젝트의 상태 요약으로 개별 원본을 대신하지 않는다.

## 3. 스킬 생성·수정·검증

1. 사용자 스킬 생성·수정 요청에는 공유 원본 저장 → 관련 검증 → 실제 결과 보고를 매번 포함한다. skill-creator를 사용하고 기존 원본·참조·자원을 함께 갱신한다. 같은 역할의 사본을 만들지 않는다.
2. 여러 프로젝트에서 쓰는 스킬은 gptgit의 `skills/<스킬명>/`, 특정 프로젝트 전용 스킬은 해당 프로젝트의 `skills/<스킬명>/`을 기본 위치로 한다. 기존 식별자·이력을 유지하고 위치 변경 시 참조를 함께 수정한다. 사용자 지정 위치·범위가 있으면 우선한다.
3. 스킬 기본 검사기로 메타데이터·명명·미완성 표시를 확인하고 수정한 Markdown의 상대 파일 링크·포함 자원도 확인한다. Windows에서 UTF-8 문서를 읽는 기본 검사기는 `python -X utf8`로 실행할 수 있다. PyYAML 등 의존성은 현재 검사기 실행 Python에서 확인하며 다른 PC 설치 이력을 현재 환경의 완료로 보지 않는다.
4. 새로 만들거나 동작을 바꾼 스크립트는 안전한 입력으로 관련 기능을 검증한다. 실제 HTML 가이드를 작성·수정했을 때만 simple-user-guide의 로컬 구조 점검을 추가한다. 시험용 가이드·전체 프로젝트 재검사를 자동으로 만들지 않는다.
5. 필수 문제를 요청 범위에서 수정하고 영향받는 검사만 다시 수행한다. 도구·라이브러리·권한이 없으면 가능한 대체 확인은 계속하고 미실행 사유·미검증을 보고한다. 설치·정책 변경은 별도 허용 범위를 따른다.
6. 공유 원본 위치·버전, 실제 검사 대상·횟수·종료 코드·발견 문제·검사 제외·미검증을 보고한다. 실행기 오류로 검사에 진입하지 못한 시도와 완료된 검사를 구분한다. 개인 설치·파일 일치·채팅 등록·실제 작업 적용은 각각 확인한 상태만 보고한다.

이 절차는 AI가 생성·수정 작업 중 수행하는 기준이다. 자동 배포 스크립트·예약 감시·개인 설치본 자동 갱신을 뜻하지 않는다. [문서 점검 도구](../project-management/tools/check_project_docs.ps1)의 지원 범위·실행 방법은 [점검 도구 운영 문서](../project-management/docs/02_design/management_workflow.md)의 5절을 따른다.

## 4. 결과 보고와 인계

완료 보고는 실제 변경·검증 근거·미확인·다음 행동을 구분한다. 사용자 가이드의 검사 보고는 simple-user-guide에서 관리하며 이 문서에 복사하지 않는다.

기록 갱신을 요청받았을 때만 대상 프로젝트의 기존 공식 기록에 다음을 남긴다.

- 기준 문서·원본 위치, 완료 근거와 미검증 범위. 저장소 위치는 상대경로로 연결하고 PC별 절대경로·설치·검증 정보에는 확인 날짜·PC를 표시한다.
- 다음 작업의 대상·목적·첫 행동·완료 기준·담당·필요한 사용자 입력. 미정인 입력은 시작 조건으로 남긴다.
- 보류 사항·재개 조건과 과거 인계를 대체하는 변경 사항. 끝난 일·현재 할 일·제안을 구분한다.

상세 설계·현재 상태·작업 이력·사용자 가이드의 역할을 유지한다. 최상위에는 각 원본의 위치만 연결하며 상세 상태 사본이나 재개 때마다 새 인계 파일을 만들지 않는다.
